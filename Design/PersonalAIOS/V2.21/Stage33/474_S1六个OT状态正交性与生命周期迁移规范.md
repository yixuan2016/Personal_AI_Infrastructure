# 474｜S1六个OT状态正交性与生命周期迁移规范

**状态：** State/Lifecycle Contract Candidate；No State Machine Implementation

## 1. 正交状态维度

不得用单一Status表达生命周期、可用性、权利、完整性、处理、质量、Projection Freshness和删除状态。每个维度独立维护，变化必须带Actor、时间、原因、Expected Version和适用Policy引用。

`transition_id`、`object_ref`、`from_state`、`to_state`、`state_dimension`、`actor_ref`、`purpose_ref`、`command_id`、`expected_object_version`、`policy_decision_ref`、`approval_ref`、`reason_ref`、`evidence_refs`、`occurred_at`、`recorded_at`、`correlation_id`。

## 4. 迁移守卫

- Source Registered→Active：身份命名空间、来源权威和必要证据可核验。
- Snapshot Captured→Integrity Intact：Digest范围明确且匹配；不推导来源真实性。
- RawAsset Available：M02返回有效Opaque Handle和保管状态。
- KnowledgeAsset Processing→Ready：必需处理步骤和输出校验完成；不推导Assertion Verified。
- ExtractionRun Running→Succeeded：所有必需输出完成并通过结构/完整性校验。
- Chunk Building→Published：父版本、Run、集合Manifest、分类和当前Policy均满足。
- Evidence Unverified→Intact：目标版本和Locator可解析，Digest匹配。
- 任意对象→Restricted/DeletionPending：Rights/Consent/Policy/Deletion触发，优先阻断新读取和发布。

## 5. 不可逆历史与部分失败

SourceSnapshot捕获事实、ExtractionRun执行历史、Consent撤销、DeletionCompleted和外部Receipt均不可因旧Event重放而回退。恢复访问必须有新的授权/PolicyDecision；重新采集必须创建新Snapshot；重新处理必须创建新Run和派生版本。

Partial不是Succeeded的同义词。所有Partial状态必须列出成功/失败的输入和输出范围、是否可被下游消费、是否需人工复核、是否允许重试及补偿路径。

## 6. 负向验收

Source Active推导Rights Permitted；Snapshot Intact推导来源可信；KnowledgeAsset Ready推导Verified；Chunk Published绕过Policy；DeletionCompleted因旧Event恢复为Active。
