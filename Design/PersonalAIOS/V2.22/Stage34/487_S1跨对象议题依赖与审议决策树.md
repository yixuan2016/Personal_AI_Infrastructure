# 487｜S1跨对象议题依赖与审议决策树

**状态：** Cross-object Review Dependency Candidate

## 1. 目的

六个Profile不能彼此孤立审议。一个字段的结论可能影响上游来源身份、下游派生物、权限传播、删除闭包和Evidence定位。本文件把关键依赖变成有顺序的审议议题，避免各Owner只看局部字段而遗漏端到端后果。

## 2. 端到端身份与血缘链

`Source → SourceSnapshot → RawAsset → KnowledgeAssetVersion → ExtractionRun → Chunk/ChunkSet → Evidence → M06 Assertion Relation`

该链是逻辑血缘，不表示所有步骤都必须发生，也不表示Evidence一定来自Chunk。每一条边必须保留精确引用、版本和权威Owner；Receipt/Observation作为Evidence目标时仍由其原Owner管理。

## 4. 推荐审议顺序

1. **先定身份与对象边界**：Source、Snapshot、RawAsset和子记录关系。
2. **再定权利与采集封套**：Rights Snapshot、Purpose、Processing Basis、Consent、PolicyDecision。
3. **再定物理保管**：Opaque Handle、Custody、Digest、Retention和删除回执。
4. **再定内容与处理版本**：KnowledgeAssetVersion、ExtractionRun、Processor Version。
5. **再定派生与检索**：ChunkSet、Embedding、Projection State和Context访问。
6. **最后定Evidence交接**：TargetRef、Locator、Digest和M06核验。
7. **做跨链审计**：删除闭包、权限传播、版本兼容和事件重放。

## 5. 决策树

- 若问题改变某OT的类型定义、字段语义或关系约束：进入M06 TDA/SA审议。
- 若问题改变实例写入、状态、版本或血缘维护：进入M08 IA审议。
- 若问题涉及物理字节、密钥、宿主访问、备份或销毁：必须由M02决定。
- 若问题涉及Purpose、Consent、Policy、Approval、Retention或分类：必须由M18决定并接受专业审查。
- 若问题涉及Provider、Region、训练使用或模型处理：M15/M18会审并进入Security/Privacy/Legal审查。
- 若问题涉及已批准OD边界：暂停字段定稿，转496号OD/ACR路由。
- 若现有对象注册表不存在引用目标：标记`ReferenceTargetPending`，不得隐式新增OT。

## 6. 冲突与阻断

上游身份或权利问题未解决时，不应先批准下游派生数据的长期保留或发布。物理删除能力未明确时，不得批准“可完全删除”的强保证。Evidence目标版本未明确时，不得批准Integrity状态为Intact。Policy未知时，敏感处理必须Fail Closed。

## 7. 本阶段结论

本依赖图是审议顺序建议，不构成Owner批准，也不意味着任何依赖已经被运行时验证。
