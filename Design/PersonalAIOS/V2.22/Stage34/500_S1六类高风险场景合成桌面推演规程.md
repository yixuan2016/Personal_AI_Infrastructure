# 500｜S1六类高风险场景合成桌面推演规程

**状态：** Tabletop Exercise Design；Not Conducted

## 1. 目的与边界

桌面推演用于检查Owner是否理解权威边界、状态转换和证据要求，不验证软件运行行为，也不产生Owner批准。全部角色、资源、主体、Receipt和内容均使用合成标识；不连接真实Provider、文件系统、邮件、Connector或生产服务。

## 2. 场景A：同一URL内容变化且来源权利发生变化

**输入：** 合成Source `SRC-DEMO-01`；第一次和第二次Snapshot内容不同；第二次采集前Source Rights状态变化。

**推演步骤：**
1. M08确认Source身份是否保持稳定；
2. 新采集创建新Snapshot，不覆盖旧Snapshot；
3. M18判断当前采集Purpose/Policy及Rights变化；
4. M02确认新RawAsset物理保管；
5. M08/M06核对历史Evidence是否仍指向旧Snapshot精确版本。

**预期断言：** URL不作为Source唯一身份；旧Snapshot不可变；历史Rights Snapshot不等于当前授权；Rights Unknown/Policy Deny时停止新处理。

## 3. 场景B：Opaque Handle过期且收到删除请求

**输入：** RawAsset存在逻辑记录，M02句柄过期；随后收到合成删除请求。

**推演步骤：**
1. M08不得自行重建物理路径或绕过Host Permission；
2. M02确认句柄状态、备份副本和物理删除能力；
3. M18确认请求范围和例外；
4. M07/M08枚举Chunk、Embedding、Context和Cache派生闭包；
5. 记录M02回执并进行逻辑/物理状态对账。

**预期断言：** 逻辑删除不等于物理删除完成；句柄过期不代表数据已删除；缺少回执不得声称物理销毁完成。

## 4. 场景C：Provider结果未知且出现重试请求

**输入：** ExtractionRun发起外部处理后网络中断，Provider结果未知；调用方再次提交相同幂等键。

**推演步骤：**
1. M08将结果保留为UnknownOutcome，不伪装Failed；
2. M15查询Provider/Receipt状态；
3. M18复核当前Purpose/Policy/Provider条款；
4. 对相同Key相同Payload返回原Run状态；相同Key不同Payload拒绝；
5. 只有对账后才决定是否创建新Run。

**预期断言：** 不盲目重复外发；UnknownOutcome不自动等于Failed；重试不覆盖原Run。

## 5. 场景D：ChunkSet部分成功且源权限撤销

**输入：** 一个ChunkSet有部分Chunk完成；源资产随后被Restricted/Withdrawn。

**推演步骤：**
1. M08检查集合Manifest和Expected/Published Count；
2. M07检查Embedding/Index/Context失效；
3. M18确认撤销后的允许操作；
4. M08保留Partial状态，不将集合标记Published；
5. 重建前重新读取当前Tombstone和Policy。

**预期断言：** 部分成功不等于完整发布；Projection不能绕过源Policy；旧Event不能恢复Active。

## 6. 场景E：Evidence目标版本变化且Locator无法解析

**输入：** Evidence指向旧KnowledgeAssetVersion；新版本已产生；原Locator无法解析。

**推演步骤：**
1. M08保持Evidence Target Version指向原精确版本；
2. Integrity State更新需有校验证据，不得继续标Intact；
3. M06判断相关Assertion关系是否需要复核；
4. 如目标为ConnectorReceipt，M17保留原件权威；
5. 新Locator或目标版本变化时创建新Evidence或Correction记录，不覆盖历史。

**预期断言：** Locator不可解析不等于目标不存在；Digest一致不等于Assertion已核验；Evidence不复制Receipt权威。

## 7. 场景F：第三方内容混入个人KnowledgeAsset并请求导出

**输入：** 合成邮件/附件包含本人和第三方信息；用户提出导出个人知识资产。

**推演步骤：**
1. M08识别Source/Snapshot和多主体引用；
2. M18与Privacy/Legal判断导出Purpose和主体边界；
3. 对第三方内容做最小化/遮蔽或阻断；
4. M07检查摘要、Chunk、Embedding和Context是否泄露第三方内容；
5. 导出清单记录排除项和原因。

**预期断言：** 本人请求不自动构成第三方授权；派生数据也受主体和Purpose限制。

## 8. 推演记录

记录`exercise_id`、`scenario_id`、参与角色、基线版本、合成输入、关键选择、发现问题、异议、缺口、责任人和后续动作。桌面推演状态只允许Designed、Scheduled、Conducted、FindingsRecorded、Closed；不得映射为测试Passed或OwnerApproved。
