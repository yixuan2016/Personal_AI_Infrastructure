# 494｜S1跨模块权威冲突裁决与升级机制

**状态：** Authority Conflict Resolution Candidate

## 1. 冲突分类

| 冲突类别 | 典型表现 | 首要处理 |
|---|---|---|
| Identity Conflict | 同一外部资源出现多个Source ID | M06/M08核对命名空间与身份规则 |
| Semantic/Instance Conflict | M08写入类型语义或M06维护实例状态 | 按IA/TDA/SA边界拆分 |
| Physical/Logical Conflict | M08要求访问/删除物理字节，M02拒绝或状态不同 | M02确认物理能力；M08对齐逻辑状态 |
| Policy/Business Conflict | 业务Owner要求处理但M18 Policy Deny/Unknown | M18说明策略依据，业务方不得绕过 |
| Provider/Region Conflict | 处理记录未能证明实际Provider/Region | M15/M18/Security核实；未知则限制处理 |
| Projection/Source Conflict | Chunk/Embedding仍可访问但源资产已撤销 | M07/M08执行失效闭包，M18确认策略 |
| Evidence/Semantic Conflict | Evidence完整性被解释为Assertion Verified | M06维护语义关系/核验，M08维护定位完整性 |
| Receipt Ownership Conflict | Evidence复制ConnectorReceipt成为第二份权威 | M17保留Receipt原件，M08仅引用 |

## 2. 裁决顺序

1. 固定争议对象、字段、版本和真实事件；
2. 查明现行OD、ADR、Object Type Registry及历史Supersedes关系；
3. 识别争议涉及的权威角色，而不是先按模块层级排序；
4. 由每个权威角色分别给出权限范围内的意见；
5. 对齐事实和语义后形成可选方案及反方风险；
6. 若触及既有批准决策，进入OD治理；若改变架构基线，进入ACR；
7. 保存异议、未决假设、条件和风险接受；
8. 独立复核决策传播范围。

## 3. 不可越权的边界

- M08不能批准M02的物理删除证明、密钥策略或Host Permission。
- M08不能写入M06的Assertion关系、可信度或Verification。
- M08不能创建M18 PolicyDecision，也不能把历史Purpose当作当前授权。
- M06不能修改M17 Receipt原件，也不能替M02签发物理Handle。
- M15不能自行决定个人是否允许将敏感内容外发。
- M07不能通过缓存/Embedding绕过源资产Policy或Tombstone。
- Security/Privacy/Legal提供专业审查，不自动代替Owner对业务语义的决定。
- Personal Owner对本人价值、意图和个人数据主权的确认不可由模块投票替代。

## 4. 升级级别

| 级别 | 触发条件 | 升级对象 | 结果 |
|---|---|---|---|
| L1 | 同一Owner范围内定义不清 | 对象/契约Owner | 澄清或字段修订 |
| L2 | 两个模块权威边界冲突 | 双方Owner及架构负责人 | 联合决议或明确分界 |
| L3 | 涉及已批准OD或顶层模块职责 | Personal Owner / OD决策流程 | OD决定或拒绝变更 |
| L4 | 涉及法律、安全、隐私高风险且意见不一致 | Legal/Privacy/Security及Personal Owner | 暂停、缩小范围或风险处置 |
| L5 | 无法证明安全/删除/权限边界 | 相关Owner与Personal Owner | Fail Closed，维持Blocked |

## 5. 冲突记录最低字段

`conflict_id`、`baseline_id`、`object_type_id`、`field_or_relation_id`、`authority_roles`、`module_positions`、`evidence_refs`、`risk_class`、`options`、`decision_owner`、`escalation_level`、`decision_status`、`approval_evidence_ref`、`supersedes_ref`。

## 6. 暂停原则

在权威冲突未解决期间，不得将争议字段/契约标记Approved，不得进行真实数据迁移，不得以工程实现先行“倒逼”语义决策。对敏感处理、Provider外发和删除状态不明的情形，默认限制操作。
