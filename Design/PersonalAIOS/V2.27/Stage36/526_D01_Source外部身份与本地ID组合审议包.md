# 526｜D-01 Source外部身份与本地ID组合：Owner审议包

**状态：** Decision Dossier Candidate；Owner Feedback Pending；No Approval Recorded

## 1. 议题定义

同一来源可能同时具有本地稳定标识、来源系统标识、发布者身份、账户身份或跨平台别名。若把外部标识直接当成本地对象主键，会把外部系统的重命名、复用、迁移和权限变化传播为内部身份变化；若只使用本地ID，又可能无法证明来源归属和去重依据。

## 2. 关联字段与权威边界

- SRC-001 source_id
- SRC-003 source_authority_ref
- SRC-004 origin_identity_ref
- 主审议候选：M06负责类型与身份语义，M08负责实例身份维护；必须会审真实Source Authority。涉及个人来源或第三方主体时按需引入Privacy/Legal。

## 3. 必须回答的问题

1. source_id是否仅承担本地稳定身份，且不从外部Locator或可变名称推导？
2. source_authority_ref指向发布者、数据源系统、记录签发者还是其他权威？是否允许多个权威？
3. origin_identity_ref表达来源中的原始身份还是采集账户身份？两者是否需要分开？
4. 同一外部对象在多个来源系统出现时，如何记录等价、别名、合并候选和身份冲突？
5. 外部ID被复用、撤销、迁移或更正时，内部ID是否保持不变？

## 4. 候选方案（不构成推荐或批准）

- A：本地稳定ID为唯一内部身份，外部身份作为有来源链的引用。内部身份稳定，但需要治理外部引用和匹配关系。
- B：本地ID与明确命名空间的外部ID组成复合身份。来源语义显式，但命名空间治理和外部ID变更更复杂。
- C：以外部权威ID作为内部主身份。仅在外部权威长期稳定、唯一性和生命周期有充分证据时才可考虑。

## 5. 必须提供的证据

- 外部来源系统对ID唯一性、稳定性、复用和撤销的正式说明；
- 真实来源样例及跨系统重复、别名、迁移和身份冲突样例；
- SRC-001/003/004字段定义及引用关系；
- 去重、合并、拆分、撤销和身份纠错场景；
- 身份变更对历史Evidence、Snapshot、KnowledgeAsset和审计引用的影响分析。

## 6. 下游影响与测试

影响Source、SourceSnapshot、RawAsset、KnowledgeAsset、Evidence及所有引用Source的Query/Event。身份映射改变不得导致历史证据断链；消费者不得仅凭名称或Locator推断身份相等。

测试至少覆盖外部ID复用、命名空间冲突、别名变化、本地ID稳定、跨来源重复、来源撤销、历史引用解析和越权改写。测试ID应回查461/481及519，不在本包中虚构执行结果。

## 7. 阻断条件

外部命名空间不明；无法确认来源权威；存在ID复用但没有冲突处理；身份纠错会覆盖历史；批准人授权范围不覆盖身份语义。
