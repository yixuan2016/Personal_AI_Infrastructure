# 537｜字段—决策—契约—消费者—测试追踪矩阵

**状态：** Traceability Matrix Candidate；No Profile Delta Approved

## 1. 目的

任何字段决策都必须能够追踪到下游契约和实际消费者。只修改字段定义而不识别读取者、写入者、Policy和删除传播路径，会产生“文档上正确、运行时仍然错误”的架构偏差。

## 2. 追踪链

每项变更必须建立完整链路：

**Feedback → Atomic Issue → Decision Record → Field/Relation Profile → Command/Query/Event → Producer/Consumer → Policy/Consent → Lifecycle/Retention/Deletion → Negative Test → Evidence → Manifest**

链路中任何节点未知，都必须保留Unknown并标注阻断影响；不得通过默认值把未知变成已确认。

## 3. 首批决策消费者映射

| 决策 | 主要契约/消费者 | 必查影响 |
|---|---|---|
| D-01 | Source创建/查询、Snapshot、KnowledgeAsset、Evidence | 身份稳定、命名空间、历史引用和去重 |

| D-07 | Custody、Encryption、Backup、Delete、Restore | 副本清单、密钥、回执、Retention和Legal Hold |

## 4. 消费者影响分类

Producer产生或发布字段；Consumer读取或解释字段；Policy Consumer把字段用于授权裁决；Lifecycle Consumer处理状态、撤销、保留和删除；External Consumer包括Connector、Provider或外部服务；Audit Consumer负责审计和证据核验。每个消费者应记录读写方向、契约版本、依赖字段、兼容类别、迁移动作、Owner确认和测试引用。

## 5. 兼容性规则

Backward/Forward/Conditional/Breaking/Unknown必须按实际消费者行为判定。字段存在但语义改变仍可能是Breaking；可选变必填、封闭枚举新增值、Unknown默认False、权威写入者变化和删除传播缺失均不得视为表面兼容。消费者清单不完整时，默认Unknown并按高风险处理。

## 6. 变更传播

Profile Delta获批后，逐项更新受影响契约、Event版本、消费者说明、Policy规则、状态机、删除闭包、测试预期和文档索引。每个受影响消费者需要Owner确认或记录明确的未确认风险。
