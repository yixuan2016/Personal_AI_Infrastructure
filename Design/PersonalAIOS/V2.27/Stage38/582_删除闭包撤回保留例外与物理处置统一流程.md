# 582｜删除闭包、撤回、保留例外与物理处置统一流程

**状态：** Cross-Object Deletion Workflow Candidate；No Deletion Executed

## 1. 统一生命周期

RequestReceived → Identity/AuthorityVerified → ScopeResolved → PolicyAndBasisEvaluated → DependencyEnumerated → Hold/ExceptionCheck → LogicalAccessRestricted → ProjectionRemovalDispatched → ProviderRemovalRequested → PhysicalDeletionDispatched → ReceiptVerification → ResidualRiskReview → ClosureVerified。

这是流程候选，不代表现有系统已具备所有状态或自动化能力。

## 3. 删除不等于撤回

- Withdrawal：某来源、权利、证据或主张不再可用/支持；
- Access Revocation：某主体不再有权访问；
- Logical Deletion：业务目录不再将对象视为活动对象；
- Physical Deletion：受控存储中的字节被处置；
- Crypto-Erasure：密钥销毁使特定数据不可恢复；
- Retention Expiry：保留期限届满；
- Legal Hold：在合法依据下暂停部分删除。

不同动作可组合但不可互相冒充。

## 4. 依赖闭包和反向引用

删除目标前同时计算正向派生依赖和反向业务引用。正向依赖用于识别应撤除/删除的派生副本；反向引用用于识别Evidence、Assertion、Decision和其他资产的影响。不能因为一个对象被引用就永久保留其内容，也不能因为删除源对象就静默删除所有仍需保留的审计记录。

## 5. 部分完成与例外

每个子系统回执独立记录Pending、Confirmed、Blocked、Not Applicable或Unknown。Legal Hold、法定保留、争议保全、备份轮换和Provider例外必须记录依据、批准主体、对象范围、期限、隔离方式和复核时间。任何未知副本或未核实Provider均阻止“闭包完成”结论。

## 6. 关闭判据

只有依赖清单完整、各权威回执可核验、Projection不可再访问、Provider处置已确认或例外有批准依据、物理处置证据齐备、残余风险有记录并经复核后，才可标记ClosureVerified。不得由流程编排者代替M02/M07/M15/M18签发各自权威证据。
