# 580｜六对象生命周期与状态机跨对象一致性矩阵

**状态：** Lifecycle State Consistency Candidate

## 1. 设计原则

对象生命周期、处理运行状态、完整性状态、权限状态、Projection状态和物理保管状态必须分开建模。状态相同的英文单词不代表相同状态机；任何状态变化都必须有权威、前置条件、事件记录和下游传播规则。

## 2. 对象状态域

| 对象/子记录 | 状态域 | 典型独立状态事实 | 不得混淆 |
|---|---|---|---|
| Source | Availability / Lifecycle | 可访问、停用、撤回、归档 | 可访问≠允许处理 |
| SourceSnapshot | Capture State / Immutability | 捕获中、完整、部分、失败、校验失败 | 采集失败≠来源不存在 |
| RawAsset | Integrity / Custody / Deletion | 完整性、保管、物理处置 | Integrity≠来源可信 |
| KnowledgeAsset | Lifecycle / Version Pointer | 当前版本、被替代、保留、删除请求 | Lifecycle≠Content Version |
| ExtractionRun | Dispatch / Execution / Persistence / Publication | Submitted、UnknownOutcome、Succeeded等 | 外部完成≠输出可发布 |
| Chunk | Projection / Deletion | 投影生成、过期、撤销、移除 | Projection State≠访问授权 |
| Evidence | Integrity / Lifecycle / Withdrawal | 可验证、失效、撤回、受限 | Integrity≠Assertion Verified |

## 3. 状态迁移守卫

每个迁移必须定义：发起主体、权限检查、前置状态、所需证据、原子性、并发冲突、失败回滚、审计记录和下游事件。状态迁移失败不得静默回退到旧状态或默认成功。

## 4. 跨对象发布门禁

- SourceSnapshot只有在捕获清单和完整性规则通过后才能作为完整输入。
- RawAsset完整性未知时，不得被标记为已验证原始内容。
- KnowledgeAsset Content Version必须由完整输入和可核验处理/更正记录产生。
- ExtractionRun UnknownOutcome或Partial Side Effect期间，输出隔离。
- ChunkSet必须满足成员Manifest、版本一致和权限校验后才可发布。
- Evidence Target不可解析或Digest不匹配时，不得作为有效定位证据。
- Assertion核验状态由独立核验流程负责，不由Evidence状态自动驱动。

## 5. 状态机变更治理

新增、合并、废弃状态值或改变迁移语义均可能构成Breaking Change。必须有Owner批准、Schema/Contract版本更新、消费者确认、迁移策略和负向测试。

## 6. 当前结论

本矩阵建立跨对象状态域和迁移门禁候选，不批准任何新的状态枚举或Profile变化。
