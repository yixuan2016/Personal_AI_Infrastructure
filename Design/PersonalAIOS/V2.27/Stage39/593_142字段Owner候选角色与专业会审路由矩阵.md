# 593｜142字段Owner候选角色与专业会审路由矩阵

**状态：** Owner Routing Matrix Candidate；Individual Representatives and Authority Evidence Pending

## 1. 角色分工原则

角色分配沿用V2.22/486及OF-006候选分工。此处的M06、M08、M02、M18等是模块/权威角色，不是已核验的具体人员姓名，也不代表当前组织授权已生效。每个Atomic Issue必须重新核验实际代表和其授权范围。

| 角色/模块 | 候选责任 | 不可越权 |
|---|---|---|
| M06 TDA/SA | OT/子记录类型、字段语义、关系、基数、枚举、状态和Evidence语义 | 不写入M08实例；不持有M02物理字节；不代替M18 Policy |
| M08 IA | 六个OT实例身份、创建/更新、状态、版本、血缘和生命周期记录 | 不定义M06语义；不签发M02 Handle；不代签M18 Policy |
| M02 Physical Custodian | 物理字节、Opaque Handle、宿主访问、密钥、加密、备份、物理删除与Custody Receipt | 不决定Purpose、Assertion语义或个人授权 |
| M18 Policy Authority | Purpose、Policy、Consent、Processing Basis、Approval、Classification、Retention与PEP规则 | 不伪造M15 Provider事实，不代替M02执行物理删除 |
| M15 Processor/Provider Authority | Processor/Provider能力、版本、实际调用、Region、幂等、对账和外部副作用事实 | 不授权个人数据外发，不替代M18 |
| M07 Projection Owner | Embedding、Index、Context、Cache等派生Projection的构建、版本、可见性、撤销、失效和删除 | 不形成源知识事实权威，不降低源权限 |
| M17 Receipt/Connector Authority | Connector Receipt原件、来源回执、连接器采集事实及原始证据链 | 不替代M06 Assertion核验，不把Evidence副本变成原件 |
| Source Authority | 外部来源内容、发布事实和外部身份的权威确认 | 不等同本地采集者或存储者 |
| Personal Owner | 本人数据主权、个人目标、价值、个人Consent/本人确认事项 | 不替第三方主体授权 |
| Security/Privacy/Legal | 独立专业审查和风险意见 | 专业意见不自动代替业务Owner批准 |

## 2. 字段路由通则

- 所有字段默认接受M06语义审查与M08实例维护审查；这是候选职责分工，不意味着两个模块对每个字段都拥有同等决定权。
- 物理字节、Handle、Custody、密钥、备份和物理删除事项增加M02审议。
- Rights、Purpose、Consent、Processing Basis、Classification、Retention和Policy事项增加M18审议。
- Processor、Provider、Region、重试、幂等和外部副作用事项增加M15审议。
- ChunkSet、Embedding、Index、Context、Cache、Projection失效事项增加M07审议。
- Connector Receipt原件、Connector回执和连接器采集来源事项增加M17审议。
- 外部Source身份/发布事实由实际Source Authority确认。
- 涉及本人数据主权或个人意图的事项须由Personal Owner本人确认。
- Security/Privacy/Legal按539号触发矩阵独立审查。

## 3. 具体路由不得静态推断

一个字段可能被多个模块读取，但读取者不自动成为决定权威。某字段的最终决定权威应根据Atomic Issue的实际问题确定：语义、实例、物理、Policy、Provider、Projection或Receipt问题分别路由。若一个Issue跨越不同权威，先拆分；不可拆分时明确联合决策规则和各方批准范围。

## 4. 人员核验要求

进入正式审议前必须补齐：实际姓名/账号、组织角色、模块归属、授权文件/目录、可批准范围、替补人、批准渠道、授权有效期和利益冲突声明。当前没有可核验的个人代表清单，故不填写姓名、不推断已授权。
