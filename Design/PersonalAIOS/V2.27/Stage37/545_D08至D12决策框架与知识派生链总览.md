## 3. 派生链

Source → SourceSnapshot → RawAsset → KnowledgeAsset Version → ExtractionRun → ChunkSet/Chunk → Projection → Evidence → Assertion Verification。

该链是逻辑血缘关系，不代表所有内容必须经过同一条线性流水线。Evidence可指向原始Source、Snapshot、RawAsset、KnowledgeAsset Version、Chunk或其他被允许的目标；Assertion核验是独立认知流程，不得被误画成ExtractionRun的自动输出。

## 4. 四种必须区分的版本

- Object Version：对象元数据/状态的修订版本；
- Content Version：KnowledgeAsset具体内容版本；
- Processor/Configuration Version：产生派生内容的处理器及配置版本；
- Contract/Schema Version：接口和语义定义版本。

四者不可共用一个version字段，也不能仅凭时间戳推断版本等价。

## 5. 三条横切控制

- **权利与目的：** Rights、Purpose、Consent、Processing Basis和Policy Decision沿派生链传递，但不得被压成单一授权标志。
- **完整性与可信度：** Digest/Integrity说明明确字节范围的一致性；来源可信度和Assertion Verification必须另行判断。
- **生命周期：** Retention、Withdrawal、Legal Hold、Logical Tombstone、Projection Removal和Physical Deletion分别表达，不能用一个Deleted状态覆盖。

## 6. 决策依赖

D-08先确定知识版本及依赖边界；D-09确定外部处理事实与地区；D-10确定执行结果对账；D-11在版本和运行结果明确后定义集合发布；D-12在目标版本和证据来源可定位后确定核验交接。此顺序不构成自动批准链。
