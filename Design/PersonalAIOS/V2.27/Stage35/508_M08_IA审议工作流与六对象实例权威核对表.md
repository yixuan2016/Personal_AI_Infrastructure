# 508｜M08 IA审议工作流与六对象实例权威核对表

**状态：** IA Review Workstream Candidate；M08 Owner Feedback Pending

## 1. 审议目标

核验M08作为六个S1 OT候选Instance Authority时，是否真正承担实例身份、创建、更新、状态、版本和生命周期写入责任；同时确认M08不因持有IA而取得类型语义、物理字节、Policy或Assertion核验权威。

## 2. 六对象职责核对

| 对象 | M08候选职责 | 必须由其他Owner决定的内容 |
|---|---|---|
| Source | Source实例身份、Locator引用、状态、版本、来源关系 | M06定义语义；外部Source Authority由实际来源确认；M18治理Rights/Purpose |
| SourceSnapshot | 创建采集快照、登记不可变封套和关联引用 | M02物理字节/Handle；M18处理依据；M06定义子记录语义 |
| RawAsset | 逻辑资产身份、血缘和逻辑生命周期 | M02物理字节、密钥、Custody、备份、物理删除 |
| KnowledgeAsset | 逻辑知识资产身份、内容版本引用和生命周期 | M06类型语义；M18分类/Retention/Policy；M07派生Projection |
| ExtractionRun | 运行记录、输入/输出引用、状态和追踪信息 | M15 Processor/Provider实际能力；M18 Purpose/Policy；Security隔离审查 |
| Chunk | Chunk身份、ChunkSet关系、父版本和Projection引用 | M06语义；M07 Embedding/Index/Context Projection；M18权限传播 |

## 3. IA逐项审议问题

1. M08是否对每个OT有唯一、可审计的实例写入入口？
2. 是否存在其他模块直接修改M08管理对象核心字段的情况？
3. 是否明确系统Actor、用户Actor、Connector Actor和Processor Actor的写入权限？
4. 对象版本是否在并发更新时单调推进，旧Event能否覆盖新状态？
5. 状态迁移失败、UnknownOutcome、重试和补偿是否有确定语义？
6. SourceSnapshot是否不可变，Correction是否通过新记录表达？
7. 删除请求如何触发M02/M07/M18等模块的协同，而非M08单方面宣告完成？
8. M08如何证明每个Reference都解析到已批准OT/OF/子记录，而不是隐式新增类型？

## 4. M08不可越权清单

- 不持有或签发M02物理Handle；
- 不管理M02密钥材料、宿主权限和备份删除；
- 不写入M06 Assertion关系、Confidence或Verification；
- 不创建M18 PolicyDecision或替代Consent；
- 不将Source Locator的可访问性解释为合法处理授权；
- 不把ExtractionRun Succeeded解释为内容真实或知识已验证；
- 不因IA身份自行修改OD、OT Registry或TDA定义。

## 5. 所需证据

- M08对象写入责任说明和角色授权矩阵；
- 六对象Command/Event的责任Owner和状态守卫；
- 对象版本、并发和幂等规则；
- SourceSnapshot不可变与Correction流程；
- 删除协同与M02回执对账流程；
- 引用解析和注册表核对样例；
- 对越权写入的拒绝测试设计。

## 6. 反馈落账

M08的每条意见先登记Feedback Record，再拆成Atomic Issue。M08可以确认实例维护事实，但涉及TDA/SA、Physical Custody、Policy Authority或OD的议题必须转交对应权威。没有正式Owner确认时，M08工作流状态保持`PendingOwnerReview`。

本文件仅提供M08审议工作流。当前没有新增可核验M08 Owner反馈或批准证据；不得将候选IA分配升级为已批准的运行责任。
