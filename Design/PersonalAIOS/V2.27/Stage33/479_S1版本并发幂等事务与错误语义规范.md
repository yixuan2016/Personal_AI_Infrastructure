# 479｜S1版本并发、幂等、事务与错误语义规范

**状态：** Reliability Contract Candidate；No Runtime Verification

## 1. 版本维度

必须分离：`object_version`、`source_snapshot_sequence`、`asset_version`、`extraction_run_version`、`chunk_set_version`、`processor_version`、`locator_schema_version`、`policy_version`、`contract_version`和`event_payload_version`。不得用一个版本字段替代所有维度。

## 2. 乐观并发

权威写入Command携带`expected_object_version`。目标Owner只有在当前版本匹配时才提交；否则返回`VersionConflict`并返回当前版本Ref。调用方重新读取、重新评估Policy后再提交。不得自动Last-Write-Wins。

## 3. 幂等键作用域

建议：`actor_ref + command_type + target_ref + purpose_ref + stable_payload_digest + idempotency_window`。同一Key不同Payload必须拒绝；同一Key相同Payload返回原Command/Run/Receipt状态；不同输入版本、Processor版本、配置或Purpose必须创建新Run。幂等键以受控方式存储/哈希，避免泄露秘密。

## 4. 事务边界

单一Owner内可采用本地原子提交/Outbox候选模式；跨Owner流程采用Saga/补偿。M08登记逻辑资产与M02物理字节写入不是一个全局数据库事务；M08与M06证据语义交接也不是单Owner事务。每个阶段需有状态、超时、重试、补偿和对账规则。

## 5. 错误码目录

| 错误码 | 含义 | 默认处理 |
|---|---|---|
| `IdentityConflict` | 稳定身份冲突 | 人工/规则复核 |
| `ReferenceTypeMismatch` | 引用类型不匹配 | 拒绝 |
| `SourceUnavailable` | 来源当前不可达 | 保留快照，不伪造失败来源 |
| `RightsUnknown` | 来源权利未知 | 敏感处理Fail Closed |
| `PurposeMissing` | 未声明Purpose | 拒绝 |
| `PolicyDenied` | Policy不允许 | 拒绝 |
| `ConsentRequired` | 当前场景需要Consent但缺失 | 拒绝/补充授权 |
| `ApprovalRequired` | 缺少必要Approval | 拒绝 |
| `HostPermissionDenied` | M02拒绝物理访问 | 拒绝 |
| `OpaqueHandleExpired` | 受控句柄过期 | 重新申请并重新授权 |
| `DigestMismatch` | 摘要不匹配 | Quarantine |
| `UnsupportedMediaType` | 媒体类型不支持 | Quarantine/人工处理 |
| `ProcessorTimeout` | 处理器超时 | Run Failed/Partial |
| `ProviderOutcomeUnknown` | Provider结果未知 | 对账，不盲目重发 |
| `PartialExtraction` | 部分输出 | 保持Partial |
| `TargetVersionMissing` | Evidence目标版本缺失 | 不得Intact |
| `LocatorUnresolvable` | 定位无法解析 | 复核/重新定位 |
| `VersionConflict` | Expected Version冲突 | 重新读取 |
| `DuplicateCommand` | 幂等重复 | 返回原结果 |
| `TombstoneApplied` | 目标已撤销/删除 | 阻断 |
| `DeletionInProgress` | 删除传播中 | 限制访问/发布 |
| `ProjectionStale` | 派生投影过期 | 重建前重新授权 |

## 6. 失败分类与事件顺序

`RejectedBeforeExecution`、`FailedNoSideEffect`、`PartialSideEffect`、`Succeeded`、`UnknownOutcome`必须分开。UnknownOutcome不得自动视为Failed；Provider外发等副作用先通过Receipt/状态查询对账，再决定是否重试。

消费者按Event ID去重、按Aggregate Version检查顺序。Tombstone/撤销序列优先于旧Projection事件；旧Event不得将Deleted/Withdrawn/Restricted恢复为Active。Projection重建需重新读取当前权威状态和Policy。
