# 516｜ACR/OD路由判定与变更升级门槛

**状态：** Change Routing Decision Tree Candidate

## 1. 目的

Owner反馈可能只是澄清文字，也可能触及类型边界、模块权责、全局对象权威或个人主权。必须在修改Profile前完成路由，避免把架构变更伪装成字段调整。

## 2. 路由决策树

**问题一：是否改变字段的业务语义、类型、基数、缺失语义、可变性或校验？**
- 是：字段Owner + M06/M08审议；形成字段级Decision Record。
- 否：进入问题二。

**问题二：是否改变Command/Query/Event载荷、错误、幂等、并发或消费者行为？**
- 是：契约Owner、生产者和消费者联合审议；建立Contract Change/兼容性分析。
- 否：进入问题三。

**问题三：是否改变OT数量、对象粒度、父子关系、唯一权威注册表或跨模块职责？**
- 是：提交ACR；如触及顶层决策或模块边界，进一步进入OD流程。
- 否：进入问题四。

**问题四：是否改变IA/TDA/SA/Physical Custodian/Policy Authority分配？**
- 是：相关Owner联合审议；影响OF-006或已批准OD时必须走ACR/OD。
- 否：进入问题五。

**问题五：是否改变个人数据主权、目标、价值、授权或本人确认权？**
- 是：必须由Personal Owner明确决定；不得由模块Owner或AI代替。
- 否：按普通Profile/文档变更管理。

## 4. ACR最小材料

`acr_id`、触发反馈、父基线、现行OD、问题定义、变更分类、选项、推荐方案、反方审查、影响闭包、风险、兼容/迁移/回滚、Owner意见、专业审查、批准证据和生效条件。

## 5. 不允许的绕行

- 不允许先改Profile再补ACR；
- 不允许以“字段重命名”改变语义；
- 不允许通过新增内部对象绕开OT准入；
- 不允许把模块内部组件提升为新模块；
- 不允许把AI建议当作Personal Owner批准；
- 不允许用ACR批准推定Owner批准所有字段；
- 不允许用字段批准推定工程授权。

## 6. 当前结论

Stage35未记录新的ACR或OD批准。所有潜在架构级反馈必须先路由，再进入候选差异。
