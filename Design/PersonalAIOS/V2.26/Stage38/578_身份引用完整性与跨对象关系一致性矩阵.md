# 578｜身份、引用完整性与跨对象关系一致性矩阵

**状态：** Reference Integrity Candidate；No Relation Change Approved

## 1. 目标

确保142字段中的每个引用都指向正确的身份层级、版本和权威对象，避免逻辑身份、外部身份、物理Handle、内容版本和派生对象互相混淆。

## 2. 关键身份边界

| 概念 | 身份回答 | 不可混用对象 |
|---|---|---|
| Source ID | 来源主体/系统是谁 | Origin Identity、Locator |
| Origin Identity | 外部系统中的身份标识 | Source ID |
| Locator | 如何定位来源 | 身份、凭据、授权 |
| Snapshot ID | 某次不可变采集记录 | Source ID、RawAsset ID |
| RawAsset ID | 原始数字资产逻辑身份 | Physical Handle |
| Physical Handle | M02管理的物理字节定位/句柄 | RawAsset ID、公开URL |
| KnowledgeAsset ID | 逻辑知识资产身份 | Content Version |
| Content Version ID | 某个不可变内容版本 | Object Version |
| ExtractionRun ID | 单次处理尝试 | 逻辑任务ID、Provider Operation ID |
| Chunk ID | 分块派生对象身份 | ChunkSet ID/Version |
| Evidence ID | 证据记录身份 | Assertion ID、Target ID |

## 3. 关系完整性矩阵

| 起点 | 关系/字段 | 目标 | 完整性要求 |
|---|---|---|---|
| Source | SNP-002 | SourceSnapshot | Snapshot必须归属于明确Source |

| Chunk | CHK-002/003/004 | KnowledgeAsset/Version/Run | 三者必须形成可验证来源链 |

| Evidence | EVD-009 | Excerpt | 摘录来源、权限、Digest和Retention可追踪 |

## 4. 引用规则

- 不允许自由文本字段冒充类型化对象引用。
- 不允许引用不存在、已被错误复用或版本不可解析的对象。
- 对历史审计、Evidence和处理输入，默认固定版本；动态Current引用必须显式声明并保存解析快照。
- 循环关系、替代关系、父子关系和派生关系分别定义，不可用一个generic related_refs替代。
- 跨模块读取必须通过有权模块的受控契约，不得通过内部存储路径绕过授权。
- 引用失效、目标删除或权限撤回必须产生可观察状态，不得静默改写目标。

## 5. 关系基数待审

每一关系需逐项明确1:1、1:N、N:M、顺序性、重复处理、反向索引和删除行为。现有142字段中集合引用的具体基数仍需Owner/Schema权威确认；本阶段不凭推断填入最终基数。
