# V1.7 参考部署与演进边界

1. Environment Runtime 保持真实状态权威。
2. Evidence Store 存储可追溯事件、结果和诊断证据。
3. Evolution Registry 管理问题、提案、候选、父版本和工件血缘。
4. Sandbox 使用隔离身份、网络、存储和资源配额。
5. Twin Runtime 复用 V1.6 模型和情景执行能力。
6. Independent Evaluator 使用独立身份、隐藏数据和冻结评分规则。
7. Governance Engine 负责风险分类、审批、Mandate和撤权。
8. Release Manager 负责 Shadow、Canary、监控和回滚。
9. ADS Knowledge Registry 保存已验证的 ImprovementPattern；领域Owner保留采用权。

## 推荐首期试点
先从 R1/R2 低风险变更开始：记忆/技能候选、工具路由或工作流配置。固定基线和隐藏留出集，进行历史回放、Twin、Shadow与有限人工评审。通过后再研究R3拓扑优化。R4改进器优化必须增加元评估和独立红队。C5根权限级变更不进入RSI自主修改范围。
