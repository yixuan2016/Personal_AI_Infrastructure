# V1.6 参考部署与模型治理边界

## 1. 参考部署
- Environment Runtime 继续作为真实状态唯一权威源。
- Snapshot Builder 从事件流和授权数据投影生成带 cutoff 与水位线的版本化快照。
- Domain Twin 保留领域私有状态与模型；ADS 仅消费最小必要的跨域投影。
- Simulation Runtime 与生产 Runtime 使用独立身份、网络、存储命名空间和凭证。
- Model Registry 管理模型规格、版本、数据血缘、签名、适用范围和限制。
- Evaluation Registry 保存历史回放、留出集、压力测试、校准与Shadow结果。
- ADS Decision Support 生成Decision Brief，不签发生产授权。
- 生产命令仍由既有PDP/PEP、领域Runtime和人类审批流程执行。

## 2. 模型选择策略
- 硬约束与状态机：确定性规则。
- 生态关系和依赖：Ontology/图模型。
- 资源负载与队列：排队论、统计模型、优化模型。
- Agent行为：规则、行为模型、受限LLM代理的混合方式。
- 长期群体演化：Agent-Based Model与系统动力学。
- 因果问题：显式因果图、结构方程或经过设计的实验；不得仅凭相关性建因果结论。

## 3. 数据治理
- Twin 默认只读。
- 跨域只交换授权投影、统计摘要和必要关系。
- 个人私有上下文不得默认进入公共模型训练。
- 所有快照、训练集、校准集和仿真运行记录版本化。
- 回放必须遵循历史时间截止，避免未来数据泄漏。

## 4. 模型治理
- 规格定义、验证、校准、留出集、VVUQ、Shadow、独立评审、有限发布、监控、回滚。
- 风险越高，验证强度越高。
- 模型分数不等于授权；模型输出不等于生产命令。
- RSI只能提出模型和策略改进候选，根策略发布必须经过人类外环。

## 5. 推荐首期试点
选择一个领域，先构建事件快照和历史回放。然后只验证两个场景：资源短缺下的多方案分配；Agent失联后的联盟接续与恢复。在回放误差、校准、不确定性和Shadow结果达标后，再考虑跨域孪生。
