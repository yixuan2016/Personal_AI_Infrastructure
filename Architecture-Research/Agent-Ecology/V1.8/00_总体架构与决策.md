# 00｜总体架构与决策

## 1. 执行摘要
V1.8 将 Agent Ecology 从单生态内部自治扩展为多生态联邦。目标是“多中心、弱耦合、证据驱动、环境协同”。每个生态保留自己的身份、Ontology、数据权属、业务规则、风险策略和生产执行权；联邦层让生态发现彼此、协商任务、交换经授权的能力声明与证据，并选择性采用其他生态的改进模式。

## 2. 关键 ADR
### ADR-1801：联邦不设全局执行主权
FCP 不持有成员生态生产凭证、业务数据所有权或本地策略修改权。任一联邦组件失陷，不得直接在成员生态执行副作用操作。

### ADR-1802：本地策略优先，跨域兼容只取安全交集
跨域动作必须同时满足发起方、执行方、数据/资源 Owner 的约束。任一硬约束 DENY，整体 DENY；关键 ABSTAIN、证据缺失或过期，整体 HOLD。禁止将安全限制平均、投票或按信誉权重放宽。

### ADR-1803：提案传播与本地采用分离
改进提案和证据包可以跨域传播；是否采用由接收生态独立决定。来源域批准不能替代接收域 Shadow、审批和 Canary。

### ADR-1804：能力信誉不压缩为单一分数
使用多维、上下文相关、带时效的 Trust Vector。身份、授权、证据质量、能力适配和撤销状态分别设门槛；关键维度缺失不能被其他维度高分补偿。

### ADR-1805：默认数据最小化
默认交换能力元数据、签名证据摘要、协议版本和非敏感统计。原始轨迹、私有记忆、策略全文、训练样本和模型梯度均不默认跨域。

## 3. 逻辑分层
1. **Ecology Domain：** Local ADS、Environment Runtime、Ontology、World Model、Local PDP/PEP、Domain Owner。
2. **Federation Edge：** 身份验证、导出过滤、签名、数据最小化、速率限制、反重放。
3. **Federation Coordination Plane：** 成员发现、能力索引、任务契约协商、证据目录、事件路由、策略兼容请求。
4. **Evidence & Trust：** 身份证明、能力证明、执行回执、独立评估报告、撤销状态和来源链。
5. **Human Governance：** 各生态自己的策略权威、数据授权人、专业 Owner 和独立评审者。

## 4. 环境优先协作与 A2A 的关系
Agent 不以逐个互发消息为唯一协作模式，而是围绕共同环境中的任务状态、工件和事件痕迹协调。A2A 等协议承担 Agent 寻址、协商和传输；环境状态、任务契约和本地 PEP 才决定事实与授权。目录收录不代表能力已验证，消息到达不代表动作已授权。

## 5. 运行不变量
- 未知成员默认拒绝；凭证和能力声明需签名验证并检查撤销状态。
- 每次跨域执行绑定 task_id、purpose、scope、expiry、policy_version、evidence_digest 和本地授权收据。
- FCP 不可用时，本地安全任务可按本地策略继续；新跨域副作用默认 HOLD。
- 联邦视图是汇总投影，不覆盖各 Owner Runtime 的权威状态。
- 所有状态变更通过可审计事件，不以对话文本作为授权记录。

## 6. 非目标
本版本不强制采用区块链、某一 DID 方法、某一 A2A 实现、消息中间件或联邦学习算法；不宣称签名可以证明语义能力正确；不自动共享私有记忆、训练样本或策略全文。
