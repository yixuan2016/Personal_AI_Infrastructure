# 02｜身份信任与能力信誉

## 1. 信任对象拆分

必须区分四个对象：

1. **生态身份：** 哪个组织/个人/治理域承担责任。
2. **运行实例身份：** 哪个具体 Agent、服务或执行实例正在行动。
3. **操作授权：** 当前主体在何种目的、范围、期限、资源和策略版本下可做什么。
4. **能力证据：** 该主体是否在相似上下文中表现出所声明能力。

DID、VC、签名证书、工作负载身份或组织 PKI 可作为实现选项；选择何种技术不改变上述语义边界。身份可信不等于授权充分，授权充分不等于能力可靠，能力可靠也不等于本次任务必然安全。

## 2. 能力声明

能力声明至少包含：

- capability_id、version、owner_domain、operator_identity；
- 输入/输出 Schema、Ontology 对齐版本；
- 允许的动作类别、工具范围和副作用级别；
- 依赖、SLO、资源约束、数据驻留约束；
- 验证环境、测试版本、有效期；
- 证据引用、签名、撤销端点。

能力注册只意味着“可被发现”，不能标记为“已认证”或“可直接执行”。

## 3. 多维信任向量

建议向量：

`TrustVector = (identity_assurance, authorization_validity, capability_evidence, provenance_integrity, safety_record, freshness, independent_review, revocation_status)`

判定按维度门槛和上下文规则进行，不计算可抵消硬风险的总分。

- 身份不确定：拒绝建立高风险协作。
- 授权无效/过期：拒绝执行。
- 证据不足：限制为低风险、可逆、隔离的探索任务。
- 安全负面事件：缩小权限、暂停能力或撤销凭证。
- 证据过期：重新验证，不沿用历史高信誉。

## 4. 防操纵

- Sybil：运营者/法律实体/设备根身份绑定，注册配额，独立审查；不能仅以注册成本作为安全证明。
- 串谋背书：识别互相背书闭环、同源控制、异常集中度。
- 声誉洗白：保留不可覆盖的负面事件和撤销历史；更换 DID 不得自动清空责任链。
- 任务刷分：按任务难度、风险、独立验证和对照组分层。
- 证据伪造：签名、时间戳、环境证明、可复现工件和抽样复核组合使用。
- 信誉漂移：证据随时间衰减，但安全事故和撤销记录不得简单衰减消失。

## 5. 信誉输出

对外只发布最小必要声明，例如：
- `capability_status=verified_for_context`
- `evidence_level=E2`
- `last_verified_at`
- `valid_until`
- `known_limitations`
- `revocation_status`

不公开私有任务内容、内部评分细节或敏感操作轨迹。
