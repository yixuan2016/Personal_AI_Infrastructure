# 04｜安全威胁与实施验收

## 1. 主要威胁
- Sybil/身份冒充：身份绑定、运营者证明、配额、撤销。
- 能力广告投毒：签名声明、挑战验证、目录非信任根。
- 声誉串谋：背书图分析、独立来源、抽样审计。
- 跨域提示注入：输入隔离、来源标签、工具最小权限。
- 改进供应链攻击：内容摘要、签名、依赖清单、沙箱。
- 证据投毒：数据谱系、独立评估、基线和复现。
- 策略降级：版本下限、签名、执行前动态校验。
- 事件重放/乱序：Nonce、序列号、水位、幂等键。
- 联邦协调者失陷：无生产凭证、多源发现、本地再校验。
- 数据外泄：Export Policy、DataUseGrant、DLP。
- 模型更新投毒：默认禁用参数聚合、隔离验证、回滚。
- 撤销不可达：短时凭证、缓存上限、失联 HOLD。

## 2. 失陷处置
1. 冻结受影响域联邦导出与新授权。
2. 撤销或暂停身份、能力声明和证据凭证。
3. 各接收生态查询本地采用记录并定位受影响版本。
4. 按风险暂停 Shadow/Canary/生产版本。
5. 保留审计证据，不删除或改写事故记录。
6. 独立评估回滚、密钥轮换和身份重签发。
7. 各生态治理 Owner 分别决定恢复，FCP 无权单方面解除隔离。

## 3. 分阶段实施
- F0 治理与成员边界冻结：成员身份、Owner、根策略、加入/退出和密钥轮换。
- F1 能力发现与身份联邦：签名声明、目录同步、撤销查询。
- F2 任务契约与环境事件互操作：双域本地记录、事件水位、幂等和对账。
- F3 策略兼容与双域执行门禁：三值判定、执行前本地动态校验。
- F4 改进提案与证据交换：提案、证据、独立评估、采用回执和撤销。
- F5 双生态 Shadow/Canary：两个生态分别审批和回滚。
- F6 多生态扩展：第三生态、不同实现、联邦故障隔离与退出演练。

## 4. 验收边界
设计完成不等于测试执行；Schema 静态校验不等于语义互操作；仿真通过不等于真实跨域验证；一个生态成功不代表另一个生态可采用。所有安全关键门禁必须有独立证据、责任人和回滚方案。
