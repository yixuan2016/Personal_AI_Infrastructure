# 05｜隐私保护知识交换与共同进化

## 1. 默认交换层级

从低敏感到高敏感：

1. 公开能力元数据和协议版本；
2. 签名证据摘要、评估结论和已知限制；
3. 去标识化/聚合的性能统计；
4. 经许可的模式、规则模板、Ontology 映射；
5. 经专门授权的样本、轨迹或模型更新；
6. 原始数据、私有记忆和完整策略文本（默认禁止跨域交换）。

每提升一个层级，必须增加用途绑定、数据 Owner 授权、最小化、留存期限和撤销处理。

## 2. 共同进化对象

允许优先共享：
- 经独立验证的通用任务模板；
- 不含敏感内容的失败模式分类；
- 工具能力契约和接口适配器；
- Ontology 映射候选与兼容测试；
- 安全策略模式和反例测试；
- 评估方法、基准集生成规则和复现脚本（确认许可后）。

禁止默认共享：
- 用户私有记忆；
- 原始对话、邮件、健康或财务资料；
- API Key、Token、证书私钥；
- 生产环境轨迹和可识别的业务数据；
- 其他生态未授权的模型权重或训练样本。

## 3. 联邦学习/模型更新的边界

联邦学习不是天然隐私安全。梯度、适配器、参数差分可能泄露信息，也可能遭到投毒。默认不把梯度或模型更新当作低敏感数据。

如未来启用，必须单独完成：
- 数据 Owner 明确授权；
- 安全聚合和参与者认证；
- 差分隐私预算与效用评估（如适用）；
- 投毒、后门、Sybil 和模型反演测试；
- 独立验证器、版本回滚与影响评估；
- 训练数据来源、许可和删除/撤回约束。

## 4. 共享环境与痕迹协作

共同环境只暴露每个参与者被授权读取的状态投影。每条状态事件应有：
- event_id、producer_domain、subject、task_id；
- state_transition、schema_version、visibility；
- causation_id、correlation_id；
- event_time、recorded_at、sequence_no；
- signature、evidence_ref、retention_class。

订阅者必须验证来源、权限、事件顺序和撤销状态。事件流不是可信事实的唯一来源；Owner Runtime 的签名回执才是该域状态权威。

## 5. 共同语义治理

Ontology 采用“共同核心 + 领域扩展 + 明确映射”：
- Common Core 只定义跨域最小公共语义；
- Domain Extension 由领域 Owner 维护；
- Mapping Contract 声明源/目标版本、转换规则、丢失字段、适用范围；
- 任何有损转换必须显式标记，不得自动将未知概念映射为近似概念。
