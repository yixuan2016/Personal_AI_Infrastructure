# 04｜跨域策略兼容与冲突仲裁

## 1. 设计原则

跨域策略不是求平均值的问题，而是判断双方是否存在合法、安全且可执行的兼容空间。每个生态的本地策略权威独立存在。

## 2. 三值判定

每个策略域返回：
- `ALLOW`：在声明范围内明确允许。
- `DENY`：明确禁止。
- `ABSTAIN`：信息不足、证据过期、冲突未解或权限不明。

组合规则：
1. 任一硬约束 DENY → 整体 DENY。
2. 任一关键授权 ABSTAIN → 整体 HOLD。
3. 仅当所有必要授权均 ALLOW 且证据仍有效时，才可进入本地执行前检查。
4. 联邦协调平面不得把 ABSTAIN 自动解释为 ALLOW。

## 3. 冲突分类

- 法律/监管冲突：转交合规与法律 Owner，不由模型推断消解。
- 数据用途冲突：按数据 Owner 授权；目的不匹配即 DENY。
- 身份/信任冲突：隔离相关主体并独立核验。
- Ontology 冲突：显式映射、版本协商和语义验证；不可映射字段不得静默丢弃。
- 资源冲突：通过租约、配额、优先级和补偿流程处理；不得重复分配同一排他资源。
- 任务目标冲突：拆分任务或终止协作，不允许以多数票覆盖少数域的硬约束。
- 进化提案冲突：各域独立采用；无法兼容的分支允许长期并存。

## 4. 仲裁流程

1. 各域本地 PDP 对任务契约进行本地评估。
2. FCP 收集最小化兼容声明和证据引用。
3. 冲突检测器对目标、主体、动作、数据、期限、资源和策略版本进行交叉检查。
4. 若仅软偏好冲突，按事先签署的协商规则提出多个方案。
5. 若硬约束冲突或关键证据缺失，返回 DENY/HOLD。
6. 必要时由各自授权的人类治理角色协商；联邦协调者不能替代本地审批。
7. 双方签署兼容结果摘要；执行前仍须本地 PEP 再校验。

## 5. 版本与降级

- 兼容协议需声明最小/最大支持版本。
- 未知字段可忽略仅限明确标记为 non-critical 的字段。
- 未知关键字段、Schema downgrade、签名算法降级或策略版本回退均进入 HOLD。
- 协议兼容不代表语义兼容；语义映射需独立验证。
