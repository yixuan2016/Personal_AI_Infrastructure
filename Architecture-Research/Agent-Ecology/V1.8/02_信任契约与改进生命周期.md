# 02｜信任契约与改进生命周期

## 1. 信任对象拆分
必须分别证明：生态身份、运行实例身份、当前操作授权、能力证据。身份可信不等于授权充分；授权充分不等于能力可靠；能力可靠也不等于本次任务必然安全。

DID、VC、工作负载身份、签名证书或组织 PKI 均为实现选项。目录注册只意味着“可发现”，不能自动标记为“已验证”或“可执行”。

## 2. 能力声明
至少包含 capability_id/version、owner_domain、operator_identity、输入/输出 Schema、Ontology 版本、允许动作、工具范围、副作用级别、依赖、SLO、数据驻留约束、验证环境、证据引用、有效期、撤销端点和签名。

## 3. 多维信任向量
TrustVector = (identity_assurance, authorization_validity, capability_evidence, provenance_integrity, safety_record, freshness, independent_review, revocation_status)。

按维度门槛判定，不计算可抵消硬风险的总分。身份不确定或授权无效则拒绝；证据不足只允许隔离的低风险探索；撤销状态不可达时，高风险操作 HOLD。

## 4. 防操纵
- Sybil：绑定运营者/法律实体/设备根身份，配额与独立审查。
- 串谋背书：识别互相背书闭环、同源控制和异常集中度。
- 声誉洗白：保留负面事件和撤销历史，换 DID 不清除责任链。
- 刷分：按任务难度、风险、独立验证和对照组分层。
- 证据伪造：签名、时间戳、环境证明、可复现工件和抽样复核组合。
- 信誉漂移：普通证据可过期；重大安全事故和撤销记录不能简单衰减消失。

## 5. Federated Improvement Proposal
提案至少包含 proposal_id、origin_domain、origin_rsi_version、target_scope、problem_statement、hypothesis、change_manifest、dependencies、compatibility_range、ontology_version、risk_class、reversibility、blast_radius、evaluation_plan、baseline、metrics、stop_conditions、evidence_bundle_ref、signature、created_at、expires_at、license 和 data_rights。

禁止包含密钥、生产凭证、未授权数据、私有记忆或无法合法再分发的材料。

## 6. 证据等级
- E0：自述、未经核实。
- E1：来源可验证，工件和版本可定位。
- E2：可重复离线评估与基线对照。
- E3：独立评估者复核，包含负面结果和局限。
- E4：接收生态本地 Shadow/Canary 验证并有本地审批收据。

证据等级不是安全等级；E4 只对特定接收生态、版本和场景有效。

## 7. 本地采用状态机
RECEIVED → QUARANTINED → STATIC_REVIEW → SANDBOXED → INDEPENDENTLY_EVALUATED → SHADOW → CANARY → ADOPTED。  
分支状态：REJECTED / HOLD / EXPIRED / REVOKED / ROLLED_BACK。

候选内容摘要变化即视为新候选，必须重新评估。来源域批准不能代替接收域审批；接收域采用必须签发 LocalAdoptionReceipt。
