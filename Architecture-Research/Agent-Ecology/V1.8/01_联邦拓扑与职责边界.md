# 01｜联邦拓扑与职责边界

## 1. 拓扑
采用“自治生态 + 联邦协调平面 + 多路径互联”。FCP 可以多节点、区域索引、点对点目录或混合部署；不得成为唯一信任根。两个生态可直接协商，也可通过多个中继交换签名工件。

## 2. 角色权责
| 角色 | 职责 | 不拥有的权力 |
|---|---|---|
| Local ADS | 本地规划、协作、候选评估、执行监控 | 修改本地根策略或代 Owner 授权 |
| Environment Runtime | 本地真实状态、任务/事件状态、执行回执 | 代替策略权威审批 |
| Local PDP/PEP | 本地授权判定与强制执行 | 放宽根策略 |
| Domain Owner | 数据、资源、业务规则与能力采用权 | 控制其他生态内部治理 |
| Federation Directory | 成员/能力发现和索引 | 证明能力可用或签发授权 |
| Federation Coordinator | 契约协商、路由、状态对账 | 直接调用成员生产工具 |
| Independent Evaluator | 独立复核候选和证据 | 自行发布生产变更 |
| Human Governance | 根策略、审批、否决、接管和问责 | 被自动评分替代 |

## 3. 联邦任务状态
正常：DISCOVERED → NEGOTIATING → AUTHORIZED → EXECUTING → RECONCILING → COMPLETED。  
异常：DENIED / HOLD / EXPIRED / REVOKED / COMPENSATING / FAILED。

发起生态拥有自己的任务记录；执行生态拥有本地执行状态；联邦状态是投影，不是新的全局真相。

## 4. 环境痕迹协作流程
1. 生态 A 发布最小化任务意图和 Task Contract。
2. 目录返回候选能力和签名 Attestation。
3. A 与 B 协商输入/输出、成本、风险、责任和数据用途。
4. A、B 分别在本地 Runtime 创建记录，引用同一 federation_task_id。
5. 状态事件通过授权通道传播；Agent 读取状态变化再决定后续行动。
6. 完成后交换签名回执与必要证据，双方分别对账。

## 5. 故障隔离
- FCP 不可用：已有本地任务按本地策略处理；新跨域副作用 HOLD。
- 单域失陷：撤销该域凭证和能力声明，隔离事件源，其他域保持本地运行。
- 目录污染：目录仅用于发现，使用者必须验证签名与来源链。
- 网络分区：不猜测成功；恢复后幂等对账。
- 事件乱序/缺口：按 producer、event_id、sequence、水位处理，缺口进入 RECONCILIATION_REQUIRED。
