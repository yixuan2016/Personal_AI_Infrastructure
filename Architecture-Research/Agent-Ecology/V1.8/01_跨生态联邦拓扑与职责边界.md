# 01｜跨生态联邦拓扑与职责边界

## 1. 拓扑模型

采用“自治生态 + 联邦协调平面 + 可选的多路径互联”：

- 每个 Ecology Domain 是独立信任与治理边界。
- Federation Coordination Plane（FCP）可以由多个节点组成，也可以采用点对点目录、区域索引或混合拓扑。
- FCP 不执行成员生态内的业务动作，不替成员生态签发本地授权。
- 两个生态可以直接协商，也可以通过多个中继交换签名工件；任何中继都不应成为唯一信任根。

## 2. 角色与权责

| 角色 | 核心职责 | 不拥有的权力 |
|---|---|---|
| Local ADS | 本地任务规划、Agent 协调、候选评估、执行监控 | 修改本地根策略、替 Owner 批准跨域数据使用 |
| Local Environment Runtime | 真实状态记录、任务/事件状态权威、执行回执 | 代替策略权威审批 |
| Local PDP/PEP | 本地授权判定与强制执行 | 放宽根策略 |
| Domain Owner | 数据、资源、业务规则和能力采用权 | 控制其他生态内部治理 |
| Federation Directory | 成员与能力发现、索引 | 证明能力真实可用或签发授权 |
| Federation Coordinator | 协议协商、任务路由、状态对账 | 直接调用成员生态生产工具 |
| Independent Evaluator | 独立复核候选改进和证据 | 自行发布生产变更 |
| Human Governance | 根策略、风险审批、否决、接管、问责 | 由自动评分系统替代 |

## 3. 协作状态空间

联邦任务至少有以下状态：

`DISCOVERED → NEGOTIATING → AUTHORIZED → EXECUTING → RECONCILING → COMPLETED`

异常状态：

`DENIED / HOLD / EXPIRED / REVOKED / COMPENSATING / FAILED`

状态权威必须明确：任务发起生态只拥有本地任务记录；执行生态只拥有本地执行状态；联邦视图是汇总投影，不可覆盖任一 Owner 的权威状态。

## 4. 环境优先的协作

协作以共享任务工件和环境状态为中心：

1. 生态 A 发布最小化任务意图和任务契约。
2. 目录返回候选能力清单和签名能力证明。
3. A 与候选生态 B 协商输入、输出、成本、风险和责任边界。
4. 双方在各自环境中创建本地任务记录，并引用同一 federation_task_id。
5. 状态事件通过授权通道传播；Agent 根据状态变化决定后续行动。
6. 完成后交换签名回执和必要证据，双方分别完成本地对账。

这保留了 Stigmergy（痕迹协作）的核心：Agent 通过读取共同环境中的可信状态来协调，而不是依赖无限扩张的消息互发。A2A 等协议承担 Agent 寻址、协商和交互传输；环境状态、任务契约和本地 PEP 才决定事实与授权。

## 5. 故障隔离

- FCP 不可用：已建立的本地任务按本地策略处理；新跨域副作用默认 HOLD。
- 单一生态失陷：撤销该域凭证和能力声明；其他生态隔离其事件源，保留本地运行。
- 目录污染：目录记录仅作候选发现，必须验证签名与来源链。
- 分区网络：禁止通过“猜测成功”更新任务完成状态；恢复后执行幂等对账。
- 事件乱序：按事件 ID、序列号、签名、时间窗口和 Owner 水位处理；缺口进入 RECONCILIATION_REQUIRED。
