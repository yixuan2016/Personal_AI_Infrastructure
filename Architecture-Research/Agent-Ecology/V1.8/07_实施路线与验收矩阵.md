# 07｜实施路线与验收矩阵

## 1. 分阶段路线

### Phase F0｜治理与成员边界冻结
- 确认生态身份、Owner、根策略和责任边界。
- 形成成员加入/退出、密钥轮换、撤销流程。
- 验收：每个生态均能独立运行；FCP 无本地生产凭证。

### Phase F1｜能力发现与身份联邦
- 建立能力声明、签名、目录同步和撤销查询。
- 验收：伪造身份、过期凭证、恶意广告均不能进入已验证能力池。

### Phase F2｜任务契约与环境事件互操作
- 建立 federation_task_id、本地任务映射、状态投影、事件水位和幂等。
- 验收：重复、乱序、缺失、重放事件不会造成错误完成或重复副作用。

### Phase F3｜策略兼容与双域执行门禁
- 建立三值策略判定、兼容摘要、执行前本地动态校验。
- 验收：任一域 DENY 即整体 DENY；ABSTAIN 或证据过期即 HOLD。

### Phase F4｜改进提案与证据交换
- 建立提案、证据包、评估报告、采用回执和撤销事件。
- 验收：来源批准不能自动使接收域采用；候选内容摘要变化即重新评估。

### Phase F5｜双生态 Shadow/Canary 试点
- 在非生产、可回滚环境进行双生态互操作。
- 验收：两个生态分别产生独立评估与审批证据；失败时可局部回滚。

### Phase F6｜多生态扩展
- 增加第三个独立生态、不同协议实现和目录中继。
- 验收：无单一中心故障导致全体失去本地自治；撤销、隔离和审计可端到端完成。

## 2. 验收原则

- 设计完成不等于测试执行。
- 静态 Schema 校验不等于语义互操作。
- 仿真通过不等于真实跨域验证。
- 一个生态的成功不代表另一个生态可采用。
- 所有安全关键门禁必须有独立证据、责任人和回滚方案。

## 3. 当前状态

本版本只形成候选架构和验证设计。所有矩阵项目初始状态均为 `NotRun`。没有真实双生态部署、外部身份系统接入、生产授权或现场测试结果。
