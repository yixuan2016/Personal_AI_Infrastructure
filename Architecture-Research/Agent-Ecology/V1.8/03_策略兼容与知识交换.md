# 03｜策略兼容与知识交换

## 1. 三值策略判定
每个策略域返回 ALLOW、DENY 或 ABSTAIN。
- 任一硬约束 DENY → 整体 DENY。
- 任一关键授权 ABSTAIN、证据过期或策略冲突未解 → 整体 HOLD。
- 仅当所有必要授权均 ALLOW 且证据仍有效，才进入本地执行前检查。
- 联邦协调平面不得把 ABSTAIN 自动解释为 ALLOW。

跨域策略不是求平均值。法律/监管冲突交由合规 Owner；数据用途冲突按数据 Owner 授权；Ontology 冲突通过显式映射和版本协商处理；资源冲突通过租约、配额和补偿机制处理。硬约束不得被多数票覆盖。

## 2. 版本兼容
协议声明最小/最大支持版本。未知字段仅在明确标记为 non-critical 时可忽略；未知关键字段、Schema 降级、签名算法降级或策略版本回退均 HOLD。协议兼容不等于语义兼容。

## 3. 默认交换层级
1. 公开能力元数据和协议版本。
2. 签名证据摘要、评估结论和已知限制。
3. 去标识化/聚合性能统计。
4. 经许可的模式、规则模板和 Ontology 映射。
5. 经专门授权的样本、轨迹或模型更新。
6. 原始数据、私有记忆和完整策略文本（默认禁止跨域交换）。

每提升一个敏感等级，增加用途绑定、Owner 授权、最小化、留存期限和撤销处理。

## 4. 共同进化对象
优先共享独立验证的任务模板、非敏感失败模式分类、工具能力契约、Ontology 映射候选、安全策略模式、反例测试和评估方法。默认禁止共享私有记忆、原始对话、邮件、健康/财务资料、API Key、生产轨迹和未授权模型权重。

## 5. 联邦学习边界
联邦学习不天然隐私安全。梯度、适配器和参数差分可能泄露信息或被投毒。默认禁用跨生态参数聚合。若未来启用，必须单独完成数据 Owner 授权、安全聚合、差分隐私预算评估（如适用）、投毒/后门/Sybil/反演测试、独立验证、回滚与数据许可核验。

## 6. 共同语义治理
Ontology 采用“共同核心 + 领域扩展 + 显式映射”。Common Core 只定义最小公共语义；Domain Extension 由领域 Owner 维护；Mapping Contract 声明源/目标版本、转换规则、丢失字段和适用范围。任何有损转换必须显式标记。
