# 00｜V1.8 总体架构与设计目标

## 1. 执行摘要

V1.8 将 Agent Ecology 从单生态内部自治扩展为多生态联邦。核心不是把多个 ADS 合并成一个超级 ADS，而是建立一套**联邦协作协议 + 本地主权执行**的架构：每个生态保留自己的身份体系、Ontology、数据权属、业务规则、风险策略和生产执行权；联邦层仅让生态能够发现彼此、协商任务、交换经过授权的能力声明与证据，并选择性采用其他生态已经验证的改进模式。

目标形态是“多中心、弱耦合、证据驱动、环境协同”。各生态在共同任务环境中留下状态变化、任务工件、事件和可验证收据，其他参与者订阅自己获准访问的状态，不要求所有 Agent 之间进行高频逐一汇报。点对点通信仍然存在，但不成为协作的唯一组织原则。

## 2. 关键架构决策

### ADR-1801：联邦不设全局执行主权

- 决策：联邦协调平面不持有成员生态的生产凭证、业务数据所有权或本地策略修改权。
- 理由：避免单点权力集中和跨域失陷的级联影响。
- 代价：协作需要显式协商，局部可用性下降时可能出现 HOLD。
- 验收：任一联邦组件失陷，不得直接在成员生态执行副作用操作。

### ADR-1802：本地策略优先，跨域兼容只做交集

- 决策：跨域动作必须同时满足发起方、本地执行方及资源/数据所有者的约束。
- 规则：任一硬约束 DENY，则整体 DENY；任何关键判定 ABSTAIN、过期或证据缺失，则 HOLD。
- 禁止：把多个策略的安全限制做平均、投票或按信誉权重放宽。

### ADR-1803：共享改进与本地采用分离

- 决策：改进提案、证据包和兼容声明可以跨生态传播；是否采用由每个生态独立决定。
- 要求：本地 Shadow 与 Canary 不能由来源生态替代。
- 验收：同一改进提案在生态 A 被采用，不代表生态 B 自动获得采用状态。

### ADR-1804：能力信誉不压缩为单一分数

- 决策：采用多维、上下文相关、带时效的信任向量。
- 理由：高任务成功率不能抵消越权、身份不确定或证据伪造。
- 验收：任何关键维度缺失不得由其他维度高分补偿。

## 3. 逻辑架构

1. **生态自治域（Ecology Domain）：** Local ADS、Environment Runtime、Ontology、World Model、Local PDP/PEP、数据/资源 Owner。
2. **联邦接入边界（Federation Edge）：** 身份验证、能力导出过滤、数据最小化、签名、速率限制、反重放。
3. **联邦协调平面（Federation Coordination Plane）：** 成员发现、能力索引、任务契约协商、证据目录、事件路由、策略兼容请求。
4. **证据与信任层（Evidence & Trust）：** 可验证身份、能力证明、执行回执、独立评估报告、撤销状态、来源链。
5. **人类治理层（Human Governance）：** 各生态自己的策略权威、跨域数据授权人、专业 Owner、独立评审者。联邦治理委员会可以定义共同最低互操作约定，但不能代替本地 Owner。

## 4. 运行原则

- 默认拒绝未知参与者；通过显式 onboarding、身份绑定和能力范围声明后才允许低风险交互。
- 联邦目录是发现设施，不是信任根；目录收录不代表能力已验证。
- 联邦证据是决策输入，不是自动授权。
- 任何跨域执行都必须绑定 task_id、purpose、scope、expiry、policy_version、evidence_digest 和本地授权收据。
- 断网、目录陈旧、信任状态不可达时，非必要跨域副作用进入 HOLD；本地安全任务可以按本地策略继续。
- 所有状态变更采用可审计事件；禁止只在 Agent 对话文本中传递关键授权状态。

## 5. 非目标

本版本不规定必须采用区块链、某一 DID 方法、某一 A2A 实现、某一消息中间件或某一联邦学习算法；不宣称仅凭密码学签名就能证明 Agent 的语义能力或行为安全；不自动共享私有记忆、训练样本和内部策略全文。
