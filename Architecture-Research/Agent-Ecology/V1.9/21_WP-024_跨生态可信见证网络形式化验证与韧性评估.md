## 0. 决策摘要

WP-024 将 WP-020—WP-023 的跨生态信任、目录撤销、Witness Quorum、成员治理与灾难恢复设计转化为可复现的验证体系。

本工作包首先纠正一个容易产生误解的边界：

**Agent Ecology 的 Witness Quorum 是跨生态透明证据的多方观察/签署门槛，不等同于一个完整的 Byzantine State Machine Replication（拜占庭状态机复制）共识协议。**

Witness 为特定 Log Origin 保存最新已验证 Checkpoint，并检查新 Checkpoint 与历史 Checkpoint 的 Merkle Consistency Proof。Quorum 证明的是按既定策略获得了足够的独立见证，不代表 Witness 网络替业务生态决定事实、授权或执行顺序。

因此，本工作包分别验证：
1. 单个 Witness 的 Checkpoint 单调性与防双签；
2. 多 Witness 证据集合的阈值、交集和独立性；
3. 故障、恢复和网络分区下的安全性；
4. 在明确网络与故障假设下的可用性；
5. 形式模型、确定性模拟和实现测试之间的证据一致性。

## 1. WP-024 的核心新发现：恢复状态本身属于 Quorum 安全边界

2026-10-06 发布的 arXiv 预印本《When Can Stateless Recovery Defeat Byzantine Quorum Safety? A Tight Normal Form for Single-Step BFT》（arXiv:2610.07759）分析了签名身份保留、协议状态丢失后的 Quorum 安全问题。

其单阶段证书模型给出：
- 两个大小至少为 q 的签名集合，其交集至少为 2q-n。
- 交集中的身份必须是 Byzantine 身份，或发生过 state-erasing recovery（状态擦除式恢复）的正确身份。
- 若实际 Byzantine 身份数为 b、发生状态擦除式恢复的正确身份数为 c，则冲突证书要求 b+c≥2q-n。
- 在其模型中，若配置上界满足 b̄+c̄<2q-n，则可排除冲突证书。
- 对 n=3f+1、q=2f+1、最多 f 个 Byzantine 身份的标准参数，仅一次正确身份的状态擦除恢复，在特定执行下就足以构造冲突证书。
- 正确身份必须在释放签名之前持久化安全相关记录，并保证恢复不能回滚该记录，才能维持该模型下的防冲突性质。

**适用边界：** 该论文研究固定身份、可归属签名、单阶段阈值证书及特定恢复语义；论文明确指出多阶段协议还需要分析 View、Phase、Locking 和 Justification 规则。不得将其结论直接等同于 C2SP Witness Protocol 或 Agent Ecology 全部协议已经被证明存在漏洞。

### 1.1 对 Agent Ecology 的具体决策

- 将“状态擦除式恢复”纳入独立故障变量，而不是简单归入普通 Crash。
- 对保留原身份和签名密钥、但无法证明防双签状态连续性的恢复实例，禁止恢复 ACTIVE。
- Witness 必须先持久化最新 Checkpoint 与安全相关状态，再释放 Cosignature。
- 如果底层存储可能被快照回滚，必须有独立的防回滚证据；若无法证明，隔离旧身份，必要时使用新 Membership Epoch 和新 Key Epoch。
- 对同一身份的并发克隆、双实例启动和分叉存储进行独立测试。
- 任何 Quorum Policy 都不得把状态不连续的 Witness 计入有效独立见证数。

## 2. Quorum 参数模型与适用边界

WP-022 采用的基础候选参数为：

[
n=3f+1,quad q=2f+1
]

两组 q 大小的签名集合在固定成员集合中的最小交集为：

[
I_{min}=2q-n=f+1
]

当最多 f 个签名身份为 Byzantine，且正确 Witness 不会对不一致的同一 Log Origin 历史重复签名时，交集至少包含一个非 Byzantine、非状态擦除身份。

对于论文研究的单阶段证书模型，若将可丢失防双签状态且保留原身份/密钥的正确身份计入 c，则一个保守的充分条件是：

[
ar b+ar c<2q-n
]

这里的 c 不是所有普通重启次数，而是可能丢失安全相关单调状态、又继续使用原身份和密钥签名的正确身份数。完成安全状态恢复且能够证明防回滚的正常重启，不应被错误地当成状态擦除恢复。

| Witness 数 n | f | q | 最小交集 2q-n | 最多 f 个节点不可用时可达性 |
|---:|---:|---:|---:|---|
| 4 | 1 | 3 | 2 | q=n-f=3 |
| 7 | 2 | 5 | 3 | q=n-f=5 |
| 10 | 3 | 7 | 4 | q=n-f=7 |
| 13 | 4 | 9 | 5 | q=n-f=9 |

**重要边界：**
1. q≤n-f 是上述参数下的可达性算术条件，不是无条件的网络可用性承诺。
2. 网络分区、延迟和节点不可达可能使任何一侧都无法获得 q；正确行为是停止出具 Quorum 证明，而不是降低 q。
3. 2q-n>f 是固定成员集合、固定故障预算和非双签假设下的交集判断；不自动证明某个业务状态机具备 BFT 共识安全性。
4. 若故障域相关、成员集合变化、身份克隆或状态擦除恢复未建模，不能仅凭公钥数量声称 Quorum 独立。
5. 对超过配置上界的恶意节点数，系统应明确进入“保证不成立/隔离”状态，不得输出绿色安全结论。

## 3. 被验证对象与模型边界

### 3.1 Witness 单节点状态

每个 Witness 按 Log Origin 保存：
- 最新已验证 Checkpoint；
- Tree Size 与 Root Hash；
- 上一状态 Digest 和状态序列；
- 已接受的 Trust Root / Registry / Quorum Policy 版本；
- Membership Epoch 与 Key Epoch；
- 已持久化的签名意图/响应索引；
- 隔离、恢复和重新加入事件。

同一 Log Origin 的新 Checkpoint 必须满足：
- Tree Size 不倒退；
- Tree Size 相同则 Root Hash 必须相同；
- Tree Size 增长必须有可验证的一致性证明；
- 签名释放前安全相关状态必须持久化；
- 恢复不得绕过已接受状态或已撤销 Key Epoch。

### 3.2 多 Witness 证据集合

一个候选证据集合至少要绑定：
- Log Origin；
- Checkpoint Size 与 Root Hash；
- Witness Registry Version；
- Quorum Policy Version 和 Digest；
- Trust Root Version；
- Membership Epoch / Key Epoch；
- 唯一 Witness 身份集合；
- 唯一且足够的独立运营/控制故障域集合；
- 各 Witness 的签名与可验证的历史一致性证据。

同一 Witness 的多把密钥、多个服务端点或多个容器实例，不得被重复计为多个独立 Witness。

### 3.3 必须区分的三类结果

| 类别 | 含义 | 系统行为 |
|---|---|---|
| SAFETY PASS | 未发现冲突签名、状态回滚或无效 Quorum | 可进入下一道策略门禁，不等于业务授权 |
| LIVENESS DEGRADED | 可用 Witness 不足、网络分区或依赖不可达 | 保持 HOLD，等待恢复；不得降低门槛 |
| EVIDENCE INDETERMINATE | 状态连续性、密钥有效性、时间或独立性证据不足 | 隔离相关身份/证据，要求独立审查 |

## 4. 形式化性质目录

| ID | 性质 | 可检查的核心断言 |
|---|---|---|
| P-01 | Checkpoint 单调性 | 同一 Witness/Origin 的 Tree Size 不得倒退 |
| P-02 | 同尺寸根唯一 | 相同 Tree Size 不得接受不同 Root Hash |
| P-03 | 一致性证明 | Tree Size 增长必须通过 Merkle Consistency Proof |
| P-04 | 持久化先于签名 | 未持久化安全状态时不得释放 Cosignature |
| P-05 | 恢复防回滚 | 恢复状态不得低于可信高水位或外部已知状态 |
| P-06 | 身份单实例 | 同一 Witness 身份不得在两个未协调实例中同时签名 |
| P-07 | 签名者唯一 | 同一身份最多计一次，不以多密钥/多端点重复计票 |
| P-08 | Quorum 版本一致 | 证据集合必须绑定同一 Registry / Policy / Trust Root 版本 |
| P-09 | 独立域门槛 | Quorum 必须满足策略要求的独立运营/控制故障域数 |
| P-10 | 故障不降级 | 节点不可达、恢复失败不得自动降低 q 或独立域门槛 |
| P-11 | 分区安全优先 | 无法取得有效 Quorum 时不出具证明，不制造双重接受 |
| P-12 | 恢复默认隔离 | 无法证明连续性、身份或密钥状态时保持 QUARANTINED/HOLD |
| P-13 | 撤销单调 | 已撤销 Key Epoch / Policy Version 不得重新激活 |
| P-14 | 证据可重放 | 每个实验结果都能由模型版本、输入、故障计划和随机种子重现 |

形式化工具的有限状态检查只能证明所建模的状态空间与假设范围，不等于证明真实实现、密码学库、HSM/KMS 或组织独立性正确。

## 5. 实验分层

### L0：数学与组合检查
- 枚举 n=4、7、10、13 的成员集合；
- 检查所有 q 大小签名集合的最小交集；
- 检查 f 个 Byzantine 身份与状态擦除恢复身份的预算边界；
- 枚举重复身份、重复密钥、共享故障域及成员变化。

### L1：有限状态模型检查
采用 TLA+ / TLC 或同等级有限状态模型检查工具：
- 对正常签名、并发签名、崩溃、恢复、回滚、撤销和成员迁移建模；
- 对 P-01 至 P-13 检查不变量；
- 分别运行“安全持久化模型”和“状态可回滚反例模型”；
- 保存最短反例轨迹和模型参数；
- 安全性质与活性性质分开检查。

### L2：确定性离散事件模拟
借鉴 FoundationDB 的确定性模拟思路：
- 由模拟器统一控制时钟、网络、消息排序、磁盘、进程和故障注入；
- 固定随机种子后必须可以重放；
- 故障覆盖网络、节点、存储和区域层；
- 每次失败保存事件轨迹、输入快照和复现种子。

### L3：分布式故障注入
借鉴 Jepsen 的 Nemesis（故障扰动）与历史检查方法：
- 网络分区、延迟、丢包、乱序、时钟偏移；
- 进程 Kill / Pause / Restart；
- 存储卷卸载、快照恢复、WAL 截断；
- 节点成员增删和密钥撤销；
- 对实际操作历史运行独立 Checker。

### L4：密码学与恢复互操作
- 验证签名格式、密钥用途、Key Epoch 和撤销状态；
- 验证历史签名区间；
- 验证恢复前后 Checkpoint 连续性；
- 验证多方 Quorum Bundle 的身份、版本和故障域去重；
- 本阶段仅在合成密钥和隔离实验环境中开展。

## 7. 重点攻击序列

### 7.1 单次状态擦除恢复

1. Witness W 对 Checkpoint A 生成有效签名。
2. 持久化状态被回滚到 A 之前。
3. 原身份与原签名密钥仍然可用。
4. 恶意或失陷 Log 提交与 A 冲突的 Checkpoint B。
5. 若 Witness 未核验外部状态或防回滚高水位，可能再次签名。

期望：步骤 2 后 W 不得直接恢复 ACTIVE；无法证明最新状态时隔离原身份。禁止把恢复后的首次启动视为全新空状态。

### 7.2 并发签名与原子性竞态

1. 请求 A 提交 Tree Size N。
2. 请求 B 提交 Tree Size N+K。
3. 两请求并发读取同一旧状态。
4. 若检查与持久化非原子，可能发生状态回退。
5. 两请求均尝试返回签名。

期望：同一 Origin 的检查、状态提交和签名释放必须具备明确的串行化/原子性语义；状态提交未完成的请求不得释放签名。

### 7.3 身份克隆

1. 从同一 Witness 身份复制运行状态和签名密钥引用。
2. 两个隔离实例同时启动。
3. 两实例分别收到不同 Checkpoint。
4. 两边分别尝试生成 Cosignature。

期望：无法证明单实例或共享单调状态约束时，拒绝双实例签名；身份隔离和密钥托管不能只依赖容器唯一 ID。

### 7.4 网络分区与错误降级

1. 网络被分割为不同可达集合。
2. 一侧无法联系足够 Witness，另一侧仍可达部分 Witness。
3. FCP 或 Log 向不同 Peer 返回不同新鲜度视图。
4. Monitor 直接旁路查询 Witness 并核对 Checkpoint。

期望：有效 Quorum 不足时保持 HOLD；禁止临时降低 q；Monitor 发现冲突时固定 Fork Evidence。单纯分区不能被解释为全局共识已达成。

## 8. 指标体系

### 安全指标
- 冲突 Checkpoint 被两个有效 Quorum 同时接受的次数；
- 同一 Witness 身份对不一致历史的重复签名次数；
- 恢复后 Tree Size / Root Hash / Policy Version 回退次数；
- 未持久化先签名次数；
- 重复身份、重复密钥、重复故障域计票次数；
- 无效 Key Epoch / Trust Root / Policy Bundle 接受次数。

安全目标：上述违反安全不变量的事件为 0。出现一次即判定该模型/实现版本 FAIL，不允许用平均值抵消。

### 活性与可用性指标
- 有效 Quorum 形成率；
- Quorum 获取延迟 P50 / P95 / P99；
- 节点不可用、分区和恢复期间 HOLD 持续时间；
- 分区愈合后恢复到 OBSERVE_ONLY / ACTIVE 的时间；
- 有效操作成功率和误 HOLD 率。

活性指标必须附网络假设、节点可达率和故障组合，不能脱离条件单独承诺。

### 恢复指标
- RPO（恢复点目标）实测；
- RTO（恢复时间目标）实测；
- 状态重放完整率；
- 外部 Checkpoint 对账成功率；
- 恢复后首次签名前的独立验证覆盖率；
- 恢复失败隔离正确率。

### 可复现性指标
- 固定种子重放结果一致率；
- 故障轨迹完整率；
- 每个 FAIL 是否有最小反例；
- 每个 PASS 是否记录模型范围、环境和 Checker 版本；
- 独立复核者是否能在隔离环境重现结论。

## 9. 验收门槛

WP-024 不以“跑过多少次”作为唯一通过条件。

**Gate A｜模型正确性**
- Quorum 参数和故障假设显式化；
- P-01 至 P-13 有对应模型；
- 对状态擦除恢复模型能够产生反例或证明其被门禁排除；
- 对安全持久化模型检查恢复与签名顺序；
- 反例与模型边界均可审查。

**Gate B｜故障模拟**
- 60 项场景逐项执行并记录状态；
- 固定种子可重放；
- 网络、进程、存储、时钟和成员变更故障均覆盖；
- 每个失败都有证据链和最小复现路径。

**Gate C｜安全与活性**
- 安全不变量违反次数为 0；
- 不能达到 Quorum 时系统明确 HOLD，不自动降低门槛；
- 网络恢复后能在设定假设下恢复服务；
- RPO/RTO 和误 HOLD 率均有实测数据；
- 超出故障预算时明确撤销安全保证，不输出 PASS。

**Gate D｜独立审查**
- 独立审查者复核模型假设、反例、证据包和结论；
- 对关键安全性质进行独立复现；
- Owner 审批后才能决定是否进入后续 Shadow 实验；
- 生产启用仍需独立的安全、合规和发布审批。

## 10. 当前明确不做的事项

- 不因模型检查通过就宣布生产安全。
- 不因 Quorum 数学交集成立就宣称实现了 BFT 共识。
- 不用单一 HSM/KMS 或云厂商标签替代独立故障域证据。
- 不用备份签名代替新鲜度和防回滚检查。
- 不在恢复失败时自动更换成员并降低 Quorum 门槛。
- 不把实验中的合成密钥当作真实密钥保护证明。
- 不自动修改主线代码，不启用 Runner，不开展未经批准的真实网络攻击测试。

**WP-024 的 60 项正式验收矩阵仍全部 NOT_RUN。** 独立的 L0/L1 预验证已完成：L0 四组 Quorum 参数穷举通过；L1 Python BFS 参考模型对两个危险恢复配置找到 14 步反例，对两个安全恢复配置未发现有界反例。TLA+ 源码与 TLC 配置已创建，但 TLC 尚未运行；因此不得表述为 TLC 验证通过。V1.8 F0 仍未通过；productionAllowed=false；Runner 未启用。


## 11. WP-024-L0/L1 预验证结果（2026-11-15）

- L0：对 n=4/7/10/13 的全部不同 Quorum 集合对进行穷举，集合对分别为 6、210、7,140、255,255；最小交集分别为 2、3、4、5，全部符合 2q-n=f+1。
- L1：Python BFS 在 n=4、Byzantine={W1}、q=3 的有限状态模型中探索 4 种持久化/恢复组合。
