# WP-021｜跨生态目录一致性与撤销传播静态审查

**日期：** 2026-11-15  
**状态：** Candidate / Static Review  
**范围：** Revocation Event、Sync Checkpoint、撤销墓碑、来源水位、快照恢复和 FCP 分区安全

## 1. 已形成的候选约束

1. 每个来源 Domain 的每条 Peer Binding 安全控制 Feed 使用独立 streamId 和连续序列；跨 Domain/Stream 不比较序列号。
2. 事件使用 CloudEvents 风格上下文；持久去重键为 (source,id)。
3. 有效撤销事件立即添加墓碑；事件 Gap 不延迟已知撤销，但会阻断高风险动作。
4. 连续水位只能逐序推进；缺口、摘要链不匹配或来源分叉不能自动跳过。
5. 撤销墓碑集合只增不减；恢复必须签发新对象版本，不能删除旧墓碑。
6. 历史压缩后必须取得来源域签名的完整撤销快照、摘要根与连续性证据；不能仅凭 Merkle Root 推断状态已完整。
7. Merkle 反熵差异定位与 RFC 9162 追加历史一致性证明是两种不同用途。
8. FCP 不负责权威签发；接收域本地 PEP 对 DENY/HOLD 保留最终执行权。
9. Freshness Budget 由目标域 Policy Owner 按风险配置，不在协议中硬编码统一秒数。
10. R4 不进入 Agent 自动执行；FCP 分区不能关闭本地 Kill Switch。
