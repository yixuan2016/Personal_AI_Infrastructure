# WP-020｜跨生态信任协议静态审查与未决事项

**日期：** 2026-11-14  
**状态：** Candidate / Static Review  
**范围：** Peer Trust Binding、Owner Delegation Grant、Capability Owner Attestation 与 WP020 验收矩阵

## 1. 本轮已形成的候选约束

1. Peer Trust Binding 区分 PROPOSED/PENDING/ACTIVE；只有 ACTIVE 才要求本地与对端双边接受收据。
2. 初始 Profile 默认 `transitiveTrust=false`；A 信任 B 不推出 A 信任 C。
3. SPIFFE Bundle 必须与明确 Trust Domain 绑定；Bundle Sequence 回退不能覆盖较新状态。
4. Owner Attestation 允许 OWNER_DIRECT 或 PUBLISHER_DELEGATED 两种签发路径；委托签发必须引用 Owner Delegation Grant。
5. Owner Delegation Grant 明确是“发布/委托权限”，不是任务执行令牌；其 `notTaskExecutionAuthorization=true`。
6. 子 Grant 的 Action、Resource、Purpose、Audience、DataClass、期限、预算和委托深度必须单调衰减。
7. 能力 Attestation 使用候选 JWS/JCS Profile；签名声明必须明确 `typ`、`alg`、`kid`、Key Epoch、Audience、Purpose、有效期和防重放 ID。
8. 目标域本地 Authorization Server/PDP 是任务级最终授权权威；Token Exchange 只承载 Subject/Actor 委托上下文。
9. DPoP 或 mTLS 可用于发送方约束；不能替代资源、动作和 Purpose 授权。
10. 每个来源域维护独立 key/revocation Epoch；高风险撤销状态 UNKNOWN/STALE/UNREACHABLE 时 HOLD。

## 2. 静态检查边界

- 三份新增 JSON Schema 已通过 JSON 语法解析检查。
- WP020 CSV 当前设计 24 项；每行应为 7 列，全部 NOT_RUN。
- 本轮没有运行完整 JSON Schema Draft 2020-12 Validator。
- 本轮没有运行 JWS/JCS 密码学测试、SPIFFE Bundle 互操作、OAuth Token Exchange 互操作、DPoP 重放测试或撤销传播演练。
- JSON Schema 无法证明签名正确、Owner 权限合法、父子 Grant 的集合包含关系、时间先后关系、密钥撤销即时生效或本地 PEP 无法被绕过。
