# Agent Ecology｜相关工作比较矩阵与新颖性审查

**版本：研究审查候选稿 0.1**  
**日期：2026-11-16**  
**对应论文：Governed Stigmergic Coordination for Agent Ecosystems**  
**审查目的：确认首篇论文的研究缺口、差异边界和可主张贡献；防止重复已有工作或过度宣称原创性。**

---

## 1. 审查结论

现有研究已经分别覆盖共享黑板、共享记忆、Substrate-centric 协作、Stigmergy、持久工件、局部反应规则和多 Agent 协作收益边界。因此，Agent Ecology 不能把“Agent 通过共享环境间接协作”本身作为首创贡献。

首篇论文仍有值得研究的交叉问题：

**如何将环境介导的间接协作与类型化状态权威、可验证来源谱系、有界发现、本地授权门禁、持久工件生命周期和跨生态自治边界组合为一个可形式化、可比较、可证伪的多智能体架构，并通过匹配预算的对照实验评价其收益与代价。**

当前结论属于研究缺口假设，不能在完成系统检索和实验前写成“首次提出”或“已证明优于”。

## 2. 相关工作比较矩阵

### 2.1 直接相关研究

| 研究 | 核心机制 | 已有证据 | 与本论文的主要差异 |
|---|---|---|---|
| Blackboard Multi-Agent Systems for Information Discovery in Data Science（2025） | 主体在共享黑板发布需求，其他 Agent 自主响应 | 三类数据发现基准；报告端到端任务成功相对提升 13%—57%，数据发现 F1 最高相对提升 9% | 重点是数据湖发现与黑板通信；本论文研究状态权威、类型化事实/意图、来源谱系、本地授权和跨生态治理 |
| ScaleMAS（2026） | Substrate-centric 发布、搜索、按地址读取；有界 top-k；持久消息 | 深度研究、定理证明、软件工程、文档矛盾审查等任务；最高 128 Agent；包括 Agent 退出/重返测试 | 重点是共享底座上的信息组织与协作扩展；本论文增加 Owner 权威、治理提交、证据来源验证和联邦自治边界 |
| SwarmWorld（2026） | 持久空间、资源加工、工件建造、可执行控制器和环境反馈 | 受控模拟、长期运行、工件在移除 Agent 后的独立扰动评估 | 重点是技术工件的群体演化与功能表现；本论文重点是多主体业务协作中的语义、授权、来源和状态权威 |
| Unprompted Coordination through Shared Memory（2026） | Agent 不知道其他主体存在，仍通过共享 Key-Value Store 影响任务结果 | 4 Agent、9 模型、锁定设计与双实现复现；证明共享状态可形成隐式通信通道 | 重点是隐式共享记忆的因果作用；本论文将其转化为共享范围、命名空间、读写审计、权限和意图区分要求 |
| Waggle（2026） | 匿名局部反应规则、共享局部状态和可学习的群体一致性 | 多种局部协作环境，并测试延迟、丢失和临时退出 | 重点是局部策略学习与群体自组织；本论文强调可审计身份、Owner 责任、本地授权和确定性运行时门禁 |
| Capable Language Models Can Outgrow the Benefits of Collaboration（2026） | 匹配预算下比较单 Agent 与多 Agent 架构 | 260 配置、6 基准、5 架构、3 模型家族；观察到明显任务异质性 | 不是生态架构论文，但直接要求本论文保留强单 Agent 基线、负向任务和匹配预算 |
| MultiAgentBench（ACL 2025） | 以里程碑 KPI 评估 LLM Agent 的协作与竞争，比较多种拓扑 | 提供公开基准、代码和数据 | 重点是任务协作/竞争与拓扑评测；本论文增加长期工件接续、治理攻击和跨域授权测试 |
| Autonomous Agents and Multi-Agent Systems: A Comprehensive Review（2026） | 汇总 Agent 架构模块、应用领域与评价维度 | PRISMA-informed 检索 107 项研究；提出五模块架构和六类评价维度 | 已提供较广的架构与评价综述；本论文不能再声称首次建立通用模块框架，而应提供环境中心治理模型和受控实证 |

## 3. 多维差异审查

| 比较维度 | 常见既有做法 | Agent Ecology 候选设计 | 需要提供的证据 |
|---|---|---|---|
| 协作基底 | 直接消息、黑板、共享记忆或共享数据底座 | 五平面环境，按职责区分 State/Trace/Artifact/Semantic/Governance | 形式化对象定义与消融实验 |
| 状态权威 | 由任务协调器或共享存储承载状态 | 各领域 Owner 保留权威，Runtime 执行受控提交 | 未授权提交负向测试 |
| 信息语义 | 消息、共享记录或任务请求为主 | Intent、Command、Event、State、Artifact、Evidence 分离 | 类型混淆和重放测试 |
| 信息发现 | 广播、订阅、搜索或 top-k 检索 | 先权限过滤，再做有界、来源感知和新鲜度感知排序 | 读取负担、过期信息和越权测试 |
| 来源与血缘 | 消息引用、黑板记录或工件历史 | Owner/来源证明、版本、父引用、验证状态和因果链 | 来源完整率和投毒实验 |
| 主体生命周期 | Agent 退出后的共享数据保留程度不同 | Agent 生命周期与已提交工件生命周期分离，凭证不继承 | Agent dropout/rejoin 实验 |
| 治理 | 依实现而异，通常不作为协作核心评价 | 本地 PDP/PEP、撤销、风险门禁、独立验证、人类审批 | P0 安全不变量测试 |
| 联邦边界 | 多 Agent 通信或多节点部署 | 来源生态与接收生态双边授权，各 Owner 保留本域主权 | 跨域授权缺失和撤销传播测试 |
| 进化 | 学习策略或群体行为形成 | 局部规则 + Shadow + 独立评估 + 人类批准 + 回滚 | 策略漂移、权限不放大测试 |
| 性能评价 | 任务成功、准确率、拓扑或协作 KPI | 同预算质量、成本、时延、重复劳动、韧性和安全分开报告 | 预注册、多任务、统计功效和独立复核 |

## 4. 首篇论文可主张的研究增量

### 4.1 贡献 A：治理型环境协作的形式化模型

将 Agent、Owner、五平面环境、策略、局部反应规则和联邦关系纳入同一系统定义，并给出观察过滤、动作提案和权威提交语义。

需要证明：
- 模型对象之间不存在语义混淆；
- 关键状态转换规则可被独立实现；
- 安全不变量可转化为可检查性质。

### 4.2 贡献 B：将间接协作与状态权威分离

共享环境提供协作可见性，但不成为所有 Agent 可直接修改的全局权威数据库。Agent 只能提交类型化提案，Owner/Runtime 决定是否改变权威状态。

需要验证：
- 共享痕迹不能绕过授权改变状态；
- A2A 消息不能冒充 Owner 批准；
- 过期、撤销和来源不完整的痕迹不会触发高风险副作用。

### 4.3 贡献 C：持久工件与动态主体接续

将 Agent 生命周期与 Artifact 生命周期分离，允许后继主体在授权范围内继承可验证成果，而不是继承原 Agent 的身份、凭证和权限。

需要验证：
- 生产者退出后成果仍可用；
- 版本、父引用和依赖关系可追溯；
- 后继主体不因读取成果自动获得执行权。

### 4.4 贡献 D：多维实证评价

在同一任务、工具、模型和总推理预算下比较单 Agent、A2A、共享黑板、基础 Stigmergy、混合协作和完整治理型环境。

需要验证：
- 哪些任务获得协作收益；
- 哪些任务不应使用多 Agent；
- 治理机制的开销与安全收益；
- 主体退出、痕迹污染和跨域授权失败下的表现。

## 5. 审稿人可能提出的主要质疑

### Q1：五平面只是工程模块划分，为什么构成学术贡献？

回应方向：
- 不以平面数量作为创新；
- 给出类型化对象、权威语义、状态转换和不变量；
- 通过逐项消融证明五平面中关键机制的作用；
- 若无法证明机制间存在必要关系，应将其作为架构设计而非理论定律表述。

### Q2：这是否只是“加了权限控制的 Blackboard”？

回应方向：
- 明确比较共享黑板与五平面环境；
- 说明共享黑板的协作可见性与权威状态提交并非同一语义；
- 提供 Owner 本地权威、Intent/Fact 分离、来源谱系、撤销和跨生态双边授权机制；
- 用投毒、越权、撤销、退出和接续实验验证，而不是只展示架构图。

### Q3：Stigmergy 已经有大量研究，创新在哪里？

回应方向：
- 不声称发明 Stigmergy；
- 研究对象是基于 LLM Agent 的持久环境协作与治理边界；
- 与现有共享黑板、共享记忆、Substrate-centric 和 SwarmWorld 做机制级比较；
- 通过匹配预算和威胁条件明确适用边界。

### Q4：多 Agent 不一定优于单 Agent，是否存在选择偏差？

回应方向：
- 将强单 Agent 作为主基线；
- 预注册低并行性和无协作必要性的负向任务；
- 报告不获益和负收益的场景；
- 不使用“生态一定更聪明”作为论文结论。

### Q5：仅有合成实验，是否足以支撑真实生态主张？

回应方向：
- 首篇论文明确定位为受控架构与机制验证；
- 只对已测试任务和威胁条件作结论；
- 披露仿真到真实系统的外部效度限制；
- 将真实双生态部署作为后续研究，不伪装成已完成验证。

### Q6：治理门禁会不会使系统过慢或过度 HOLD？

回应方向：
- 同时测量安全漏放、误 HOLD、误 DENY 和撤销延迟；
- 按风险等级比较，而不是把所有动作都按最高风险处理；
- 证明高风险安全约束与低风险协作效率可以分层处理。

## 6. 新颖性主张边界

### 6.1 建议使用的表述

- “We formulate a governed, environment-centric coordination model for agent ecosystems.”
- “We distinguish authoritative state transitions from shared traces, intentions, and artifacts.”
- “We evaluate the proposed design against matched-budget single-agent, message-based, blackboard, and stigmergic baselines.”
- “Our results characterize the conditions under which governed stigmergic coordination provides measurable benefits and the conditions under which it does not.”

### 6.2 禁止使用的表述

- “The first stigmergic multi-agent system.”
- “The first shared-memory agent architecture.”
- “The first unified architecture for all multi-agent systems.”
- “Proven to outperform all multi-agent architectures.”
- “Production-safe / production-validated” unless actual independent production evidence exists.

## 7. 首篇论文实验的最小证据要求

| 证据类别 | 最低要求 | 不通过时的处理 |
|---|---|---|
| 基线完整性 | B0—B5 使用匹配任务、工具、模型和总预算 | 不允许声称优于既有方法 |
| 协作效果 | 质量、成本、时延和重复劳动同时报告 | 缩小性能主张 |
| 主体退出 | 生产者退出、替换、重新加入的配对测试 | 不主张持续性优势 |
| 痕迹污染 | 过期、错误、伪造和高热度错误工件测试 | 不主张抗污染能力 |
| 授权安全 | 越权读取、越权写入、未经 Owner 批准的副作用测试 | 任何 P0 安全失败都阻断论文的安全主张 |
| 统计有效性 | 预注册主指标、功效分析、置信区间和效应量 | 不以单次运行或单一模型结果下结论 |
| 独立复核 | 独立 Checker 或第二实现复现关键结果 | 结果标记为初步证据 |
