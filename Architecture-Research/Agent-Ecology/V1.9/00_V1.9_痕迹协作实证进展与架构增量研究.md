# Agent Ecology V1.9｜痕迹协作实证进展与架构增量研究

**版本：候选研究稿 0.1｜日期：2026-11-14**  
**上位基线：V1.3 Stigmergy / V1.4 Environment Runtime / V1.5 Ecosystem Autonomy / V1.6 Ecosystem Intelligence / V1.7 RSI / V1.8 Cross-Ecology Federation**  
**研究性质：架构研究、论文证据审查与合成实验设计；不编写生产实现代码。**

## 1. 本轮研究目的

V1.3 已提出痕迹协作与自组织协作的基本方向；V1.4—V1.8 已进一步形成 Environment Runtime、事件/状态契约、生态自治、RSI 和跨生态联邦治理。本轮不重复定义概念，而是回答五个工程化问题：

1. 共享环境怎样让智能体发现对自己有用的状态、痕迹和工件，而不必读取全部群体上下文？
2. 智能体退出、替换或失联后，协作成果怎样保留并由其他主体接续？
3. 怎样区分环境事实、协作痕迹、Agent 意图和普通消息？
4. 怎样在 Stigmergy 为主、A2A 为辅的条件下控制信息污染、越权读取和群体错误放大？
5. 怎样用可复现对照实验判断痕迹协作是否真的优于单 Agent、直接通信或共享黑板？

## 2. 近期研究证据

### 2.1 共享状态会自然成为通信通道

Abrahamsson 等人的《Unprompted coordination through shared memory in LLM agents: a locked two-implementation replication and extension》，arXiv:2611.12412，2026-11-09。

研究使用四个 Agent、九种模型和一个被描述为个人工作区的键值存储；其中两个 Agent 持有同一计算任务的互补部分。实验没有向 Agent 明示存在其他主体，也没有要求它们协作。研究团队另行构建第二套实现，并对实验设计、数据和分析实施锁定式复现。

研究报告：在有效实验中，跨主体读取和共享存储对联合任务成功具有因果影响；但“读取并使用了他人的结果”不等于“写入者有意向他人发送信号”。论文将证据分为 Access、Influence、Intent：前两项获得支持，主动传递意图尚未被证明。

论文还指出，模型之间的差异主要体现在是否写入中间结果、是否在伙伴写入后再次检查工作区；普通工作流提示会明显改变再次检查行为。复现中还暴露了 API 路由、响应格式、解析器和推理参数差异对结果的影响。

**架构结论：**
- 任何跨 Agent 共享的缓存、文件目录、Scratchpad、Memory Store 和事件投影都必须默认视为通信通道。
- 非共享空间必须按 Agent/租户隔离；有意共享空间必须明确命名空间、读写权限、来源和审计记录。
- 不能把 Agent 的沉默或“不知道有其他 Agent”当作安全隔离措施；真正的隔离必须由资源边界实现。
- 实验必须锁定模型端点、请求参数、解析规则、工具响应格式和提示词版本。
- 评估时分开测量跨主体读取、对后续行为的影响和主动信号意图，不能混为一个“协作率”。

证据限制：该研究是小型受控任务，不能直接推断大型生态中的长期自组织、生产安全或复杂任务效果；论文也记录了实现/端点差异对部分实验单元的影响。复现包：https://doi.org/10.5281/zenodo.23965306

### 2.2 Substrate-centric：把协调结构放在共享底座

Qi 等人的《Scaling Multi-Agent Intelligence with Substrate-Centric Coordination》，arXiv:2610.16120，2026-10-12。

ScaleMAS 将协作组织放在共享数据底座中。Agent 通过三种操作交互：发布消息、按内容搜索、按地址读取。消息可以引用前序消息；每次搜索最多返回 k 条结果，按相关性与被其他消息引用的情况排序；消息在原 Agent 退出后仍然保留。

研究覆盖深度研究、定理证明、软件工程和文档矛盾审查四类任务，并与并行 ReAct、多 Agent Debate、中心协调器 AOrchestra 和共享黑板 DeLM 比较。作者报告在匹配推理计算量下，ScaleMAS 在多项基准上优于对照方法；扩展实验最高达到 128 个 Agent，并测试了 Agent 永久失败和随机退出/重返。

论文的消融结果显示，跨 Agent 读取、引用关系和有界检索对效果有贡献。需要注意，引用次数只是实验中的一种信息排序信号，并不等于事实正确性或来源可信度。

**架构结论：**
- 共享环境需要“发布—发现—读取”三个基础能力，而不是让所有 Agent 订阅全量消息。
- 每个 Agent 的单次读取应有 top-k、字节数、Token、时间和权限边界。
- 工件与消息应形成可追溯引用图；读取者能够查看来源、版本、父引用和后续使用关系。
- Agent 生命周期与成果生命周期分离；Agent 退出不应删除已提交工件。
- 重要内容的排序必须结合来源权威、证据完整性、时效、独立验证和权限；不得只按热度或引用次数排名。

证据限制：论文实验最高到 128 个 Agent；ScaleMAS 主要在推理阶段运行，训练阶段的底座协作仍属后续方向。论文使用 smolagents 和 mini-SWE-agent 作为执行框架，但当前检索未确认 ScaleMAS 独立作者实现仓库的明确公开链接。

原文：https://arxiv.org/abs/2610.16120

### 2.3 局部规则可以生成可重组的群体组织

Zou 等人的《Waggle: Learning One Anonymous Local Law for Self-Organizing LLM Swarms》，arXiv:2609.34136，2026-09-28。

Waggle 将学习对象从显式角色、组织图和路由拓扑，转向可复用的局部规则。相同的匿名局部策略在每次局部观察后共同决定任务行动、语义痕迹更新和局部承诺/重新打开。Swarm-Consistent Distillation（SCD）用于学习跨匿名视图的一致性和局部协调状态演化。

论文报告该方法在多种局部交互环境和群体规模下保持较高质量；在测试的延迟、消息丢失和临时退出场景中，系统仍能一定程度恢复，但延迟与丢包会增加恢复时间和过期痕迹负担。

**架构结论：**
- Agent Ecology 可以研究“局部反应规则”，让 Agent 根据有限局部视图、当前任务状态和邻近痕迹作出下一步行动。
- 规则输出必须是受限的 Task Action、Trace Update 和 Commitment Update，不允许直接写任意全局状态。
- 运行时继续负责 Schema 验证、合法动作、权限、传输上限、过期、冲突和回滚；不能把这些安全能力交给学习模型。
- 匿名局部视图可以减少对固定角色和全局拓扑的依赖，但本项目仍需要在治理层保留可审计主体身份、委托链和责任归属。
- 学习型规则仅可在隔离实验中训练、Shadow 和评估，不能自动修改主线或根策略。

证据限制：Waggle 依赖确定性 Adapter 和固定 Runtime；不覆盖任意调度、永久信息丢失或对抗主体，也不构成完整安全边界。匿名接口不保留跨回合身份信誉。当前未确认论文正文存在明确作者代码仓库链接。

原文：https://arxiv.org/abs/2609.34136

### 2.4 持久工件与共享世界可以成为长期外部记忆

Pal、Wang、Buehler 的《SwarmWorld: Stigmergic Technological Evolution in Societies of Language-Model Agents》，arXiv:2608.26081，2026-08-26。

SwarmWorld 让初始同质的 LLM Agent 在共享空间中探索资源、测试材料、建造工件和编写受限控制程序。研究采用固定动作/材料 Schema，由确定性模拟器决定工件的实际功能；在评估阶段移除 Agent，再用未见扰动测试已形成的工件组合。

论文报告了 800 tick、48 个匹配实验 episode 的主研究，以及 3,200 tick 的独立长期研究；冻结工件在没有 Agent 的情况下接受八组配对扰动测试。研究观察到行为分化、工件继承、持久 Agent—Artifact 关系和跨主体复用。作者报告约 95% 的技术首次采用来自物理观察，而非直接消息传递。

**架构结论：**
- 协作成果不应只存在于对话历史；应沉淀为可版本化、可验证、可复用的 Artifact。
- Artifact 应有作者/来源引用、父版本、创建/修改事件、验证结果、适用环境和依赖关系。
- 工件被后续 Agent 采用时，形成的是“观察/引用/继承/修改”关系，不应直接推断为 Agent 间信任。
- 评价群体能力时，除了 Agent 的回答质量，还要评价移除原生产者后的工件可用性和韧性。
- 模拟器的状态、动作约束和结果评估必须与可视化渲染分离，避免把视觉逼真误当作仿真可信。

复现材料：作者公开代码、Prompt Manifest、版本化协议、原始模型输出、分析脚本和数据。
代码：https://github.com/lamm-mit/SwarmWorld
数据：https://huggingface.co/datasets/lamm-mit/swarmworld-data

证据限制：这是受控的材料/空间仿真，不等于企业业务生态中的知识治理、跨域授权和生产任务效果。

### 2.5 多 Agent 不是默认最优架构

Kim 等人的《Capable language models can outgrow the benefits of collaboration》，Nature Machine Intelligence，2026-07-24，DOI: 10.1038/s42256-026-01268-y。

研究控制任务提示、工具和计算预算，比较 260 种配置、六类基准、五种架构和三个模型家族。结果显示，多 Agent 相对单 Agent 的效果高度依赖任务结构；有些可拆分任务获得明显收益，有些强顺序依赖任务反而下降。研究给出约 45% 的经验性能力饱和参考阈值，并报告其在特定验证配置中的方向预测表现，但作者强调这不是普遍缩放定律。

**架构结论：**
- 每个任务类型都应保留强单 Agent 基线。
- 只有任务存在可验证的并行分解、独立证据搜集、交叉验证或持续工件复用收益时，才增加协作主体。
- 必须按相同总推理预算比较成功率、质量、成本、时延和错误放大。
- 不把论文中的约 45% 经验阈值硬编码为 Agent Ecology 的统一准入规则。

原文：https://doi.org/10.1038/s42256-026-01268-y

### 2.6 环境消息与决策意图应分离

Li、Li 的《DEDMAC: Disentangling Environment and Decision Messages for Multi-Agent Communication》，Information 2026, 17(4), 332，2026-04-01。

该研究来自合作式多智能体强化学习（MARL），不是直接的 LLM Agent Ecology 实证。其方法把环境消息与决策消息分成两条通道：环境信息进入长期记忆，决策意图用于即时协调，并使用互信息约束减少语义混淆。

**架构启发：** Agent Ecology 的事件/痕迹模型要区分“环境发生了什么”和“某个 Agent 打算做什么”。不能把计划、意图、命令和已发生事实写成同一种事件。

原文：https://www.mdpi.com/2078-2489/17/4/332

### 2.7 经典群体强化学习作为非 LLM 对照

Aina、Ha 的《Deep reinforcement learning for multi-agent coordination》，Artificial Life and Robotics，2025-11-26 在线发表，DOI: 10.1007/s10015-025-01089-z。

研究使用虚拟信息素与课程学习进行去中心化协作，报告在其受控采集任务中可扩展到确定性环境的 5 个 Agent 和随机环境的 8 个 Agent。该研究不是 LLM Agent，也不是企业级持久环境，但可作为局部痕迹场、衰减和去中心化策略的对照。

原文：https://doi.org/10.1007/s10015-025-01089-z

## 3. 研究综合：V1.9 应新增的架构能力

### 3.1 不把共享环境简化成一个黑板

建议继续保留 V1.4 的五个逻辑平面，并补充“有界发现与局部反应”能力：

| 平面 | 核心职责 | 关键约束 |
|---|---|---|
| State 状态平面 | 维护经 Owner 授权的真实状态或受控投影 | 权威状态只能由对应 Owner/Runtime 接受的命令改变 |
| Trace 痕迹平面 | 记录状态变化、因果、来源和协作痕迹 | 追加式历史；不能把意图伪装成事实 |
| Artifact 工件平面 | 保存任务产物、知识、方案、代码和版本谱系 | 持久化、可验证、可追溯、可隔离执行 |
| Semantic 语义平面 | Ontology、Schema、映射、索引和检索 | 版本固定、兼容审查、权限过滤 |
| Governance 治理平面 | 身份、授权、用途、风险、撤权、审计 | 读取不等于授权；痕迹不等于命令 |

新增的横切能力：
- Bounded Discovery：有界发现，每次查询只返回授权范围内的有限结果。
- Provenance-aware Ranking：来源感知排序，结合 Owner、来源、验证状态、时效和引用关系。
- Local Reaction：局部反应，Agent 根据局部状态和痕迹生成受限行动。
- Durable Artifact Lineage：持久工件谱系，Agent 退出后成果仍可接续。

### 3.2 三种交互通道分工

1. **Stigmergy（痕迹协作）**：默认的持久协调机制。通过环境状态、任务痕迹、工件和事件影响后续主体。
2. **A2A（Agent-to-Agent）**：需要明确主体间协商、委派、澄清、交接或同步确认时使用；不作为全量广播机制。
3. **MCP（Model Context Protocol）**：Agent-to-Tool 垂直工具接入；工具调用不等于与其他 Agent 协作。

三者可以组合，但不能混淆状态权威、身份验证和授权边界。

### 3.3 新增共享范围等级

- PRIVATE：仅创建主体可见。
- TASK_SHARED：当前任务授权参与者可见。
- DOMAIN_SHARED：同一业务领域内按策略可见。
- FEDERATION_SHARED：跨生态仅共享已批准的最小证据或工件引用。

默认不把个人私有记忆、原始敏感上下文和生产凭证写入共享环境。跨生态共享必须经过来源 Owner 与接收生态双重授权。

### 3.4 局部反应循环

建议将协作循环固定为：

Observe（观察授权局部状态）
→ Discover（有界检索痕迹/工件）
→ Validate（验证来源、版本、权限和新鲜度）
→ Decide（局部策略形成行动/意图）
→ Submit（提交类型化命令或痕迹更新）
→ Govern（Policy/PEP/Owner 校验）
→ Commit（权威状态或工件版本提交）
→ Trace（记录事件、因果、来源与结果）
→ Reobserve（后续主体读取新状态）

被拒绝的 Command 不产生权威状态变化；普通 Trace 不能自动触发生产副作用。

## 4. 必须冻结的架构不变量

1. Environment 是真实状态权威；Agent 本地记忆只是局部视图。
2. Command、Intent、Event、State、Artifact、Evidence、Policy Decision 必须保持语义区分。
3. 共享空间必须显式声明 Owner、可见范围、读写权限、用途和保留期限。
4. 共享状态默认是潜在通信通道；跨主体读取必须可记录。
5. 每次发现/检索必须执行权限过滤和有界返回，不允许默认全量广播。
6. 引用数、热度和重复出现次数不能单独证明事实可信。
7. Trace 和 Artifact 必须保留来源、版本、因果引用和验证状态。
8. Agent 退出不删除已提交成果；新 Agent 不能继承旧 Agent 的凭证或权限。
9. 旧痕迹过期、策略撤销或语义版本不兼容时，相关高风险动作必须 HOLD。
10. A2A 消息仅表达协商/请求，不直接改变对方领域权威状态。
11. 学习型局部规则不能越过 Runtime 的身份、授权、风险和执行校验。
12. 多 Agent 协作必须通过同预算单 Agent 基线证明增量价值。
13. 群体引用或多数意见不能替代独立验证与领域 Owner 裁决。
14. RSI 只能在隔离环境产生候选，经独立评估、Shadow、人类审批和回滚门禁后才可申请采用。

## 5. Personal_AI_Infrastructure 的首轮合成验证方案

### 5.1 对照组

| 组别 | 架构 | 验证目的 |
|---|---|---|
| B0 | 单 Agent | 强基线 |
| B1 | A2A 直接通信 | 测量消息交互收益与成本 |
| B2 | 全局共享黑板 | 测量共享上下文负担 |
| B3 | Stigmergy 有界共享底座 | 测量痕迹、持久工件和局部发现收益 |
| B4 | Stigmergy + 选择性 A2A | 测量混合架构的边际收益 |

所有组使用相同模型版本、任务输入、工具、最大总推理预算、运行环境和评估规则；预先登记随机种子和停止规则。

### 5.2 首批任务

- SYN-EC-01：多源知识检索与证据综合，验证工件复用和来源追踪。
- SYN-EC-02：任务分解与 Agent 失联接续，验证成果持久化和接续。
- SYN-EC-03：共享资源冲突与局部承诺重开，验证状态冲突处理。
- SYN-EC-04：错误/过期/恶意痕迹注入，验证隔离和反证机制。
- SYN-EC-05：跨生态最小证据交换，验证本地授权和接收方独立批准。

### 5.3 评价指标

- Task Success / Artifact Acceptance：任务成功和工件验收。
- Cost per Accepted Result：每个被验收成果的推理成本。
- End-to-end Latency：端到端完成时间。
- Read Burden：每个 Agent 的读取条数、Token 和字节数。
- Evidence Reuse：跨主体证据复用比例。
- Duplicate Work：重复劳动率。
- Agent Churn Recovery：主体退出后的恢复表现。
- Stale Trace Ratio：过期痕迹比例。
- Conflict Resolution：冲突识别和 Owner 裁决结果。
- Authorization Violation：越权读取/写入，目标为 0。
- Provenance Completeness：来源与因果链完整率。
- Coordination Gain：相对单 Agent 基线的质量增量减去成本/时延惩罚。

安全不变量不能被任务成功率、成本或效率平均抵消。任一 P0 失败，实验不得晋级。

### 5.4 实验纪律

- 使用纯合成数据，不导入真实个人/企业数据。
- 固定模型、Prompt、工具 Schema、API 端点、请求参数、解析规则、Ontology/Policy 版本。
- 每个场景使用配对随机种子和相同初始快照。
- 只改变预注册的一个或一组明确干预变量。
- 保存 Run Manifest、输入/输出哈希、事件日志、失败记录和分析脚本。
- 只完成设计或静态检查时，状态必须保持 NOT_RUN 或 STATIC_CHECKED；不得填写虚构运行数据。

## 6. 威胁与治理增量

重点增加以下威胁：

- 隐式共享通道：私有 Scratchpad 或缓存意外暴露。
- 痕迹投毒：恶意 Agent 发布错误结论、伪造工件或错误来源。
- 热度操纵：Sybil/串谋主体互相引用以提高错误工件排名。
- 过期信息：旧状态和旧策略在新任务中被误用。
- 跨域泄露：低权限主体通过检索、索引或引用关系推断敏感信息。
- 身份冒用：伪造作者、来源、审批或工件血缘。
- 反馈放大：局部规则反复强化错误痕迹，形成群体偏差。
- 重放攻击：旧命令、旧事件或旧授权被再次使用。
- A2A 混淆：对话确认被误判为 Owner 授权或业务提交。
- 工件执行风险：共享脚本、插件、代码或控制器未经沙箱验证被运行。

治理要求：共享范围最小化、来源签名/校验、租户与任务命名空间、只读默认、写入门禁、检索审计、TTL/撤销、工件沙箱、独立验证、人类审批和回滚。

## 7. 与 V1.4—V1.8 及 WP-016 的衔接

- V1.4：继续使用 Environment/State/Event/Trace/Artifact/Ontology/Policy/Lease/Fencing。
- V1.5：资源市场、能力信誉和动态授权用于任务匹配，但信誉不能替代证据验证。
- V1.6：共享环境成为世界模型/数字孪生的状态来源；Twin 仍只读。
- V1.7：局部规则和工件改进可以成为 RSI 候选，但不得自动修改主线。
- V1.8：跨生态只共享授权的最小证据、工件引用和语义映射；FCP 只负责发现、协商、证据索引和路由，不持有成员生态生产凭证。
- WP-016.7：副作用执行仍由 Effect Gateway、PDP/PEP 和目标 Owner 管理。
- WP-016.8：环境痕迹必须映射到统一 Event Envelope 和六类核心对象。
- WP-016.9：事件分发、Ontology Registry 和状态投影必须继续保留领域数据所有权。

## 8. 候选决策与待验证事项

本版提出的候选 ADR 见 03_架构决策记录.md。尚未冻结的关键问题：

2. 搜索排序中来源权威、新鲜度、独立验证、引用关系和成本的权重如何确定？
3. 局部视图允许包含哪些身份信息，如何同时保留匿名协作与事后问责？

6. 生态级共享索引如何避免跨租户推断和 Sybil 热度操纵？

## 9. 本轮结论

近期研究为“共享环境 + 持久痕迹/工件 + 有界发现 + 局部反应”的协作方向提供了新的受控实证支持，但尚未证明它在所有任务、所有规模和真实企业环境中都优于其他架构。

Agent Ecology 的下一步不应是盲目增加 Agent 数量，而应建立一个可测量、可追溯、可隔离、可撤销的痕迹协作底座，并通过匹配预算的对照实验验证其真实收益。

**当前状态：候选架构增量；没有生产实现，没有真实领域数据，没有 Runtime 实测，没有生产授权。**
