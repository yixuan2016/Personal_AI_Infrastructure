# WP-023｜可信见证网络治理、密钥生命周期与灾难恢复静态审查

**日期：** 2026-11-15  
**状态：** Candidate / Static Review  
**范围：** 成员生命周期、密钥生命周期、Trust Root 更新、备份恢复、Joint Quorum 和事故治理

## 1. 当前候选约束

1. Witness 身份、运营主体、管理域、密钥托管域、备份故障域和部署域分别登记。
2. Witness 先 OBSERVE_ONLY，再 ACTIVE；观察期不自动激活。
3. SUSPENDED、QUARANTINED、RETIRED 不参与新 Quorum；历史签名与证据不得删除。
4. Trust Root、Witness、Log、Backup、Transport 密钥用途隔离，不复用私钥。
5. 新 Key Epoch 必须有签名过渡事件和策略版本；旧密钥撤销后不得重新激活。
6. 历史签名必须结合可信时间、签名时策略、Key Epoch 和泄露时间窗口判断。
7. Root Rotation 逐版本进行，验证旧根与新根阈值、唯一 Key ID、有效期和回滚保护。
8. 根密钥失陷达到门槛时，不能依赖已失陷根继续授权；必须使用事前登记的带外恢复锚。
9. Witness 对外返回 Cosignature 前必须持久化 Checkpoint 状态。
10. 备份快照签名不代表快照是最新状态；必须与外部 Witness Checkpoint、WAL 水位和策略版本核对。
11. 恢复连续性无法证明时进入 QUARANTINED，不允许空白初始化后重新 ACTIVE。
12. 成员替换和 Quorum 迁移采用 OBSERVE_ONLY 与 Joint Quorum，不允许临时降低安全门槛。
13. RPO/RTO 必须通过实测给出；Anti-equivocation State 必须先持久化再签名。
14. 恢复后必须重新核验 Peer Binding 双方接受的 Trust Root、Registry 和 Policy Digest。
15. 所有恢复、根更新、密钥轮换和成员变更必须留存可离线复核的证据包。
