# WP-025｜多生态动态联盟形成与自治治理架构

**研究版本：Candidate 0.1｜日期：2026-11-16**  
**归属：Agent Ecology V1.9 后续研究工作包；为未来 V2.0 架构候选输入，不代表 V2.0 已冻结。**  
**研究性质：架构研究、机制设计、威胁分析和验收规划；本轮不编写 Runtime 工程代码。**

## 0. 执行摘要

WP-025 研究多个自治 Agent、多个 ADS 和不同业务领域如何围绕任务动态形成协作联盟，并在联盟运行、资源分配、成员更替和联盟解散过程中保持数据所有权、授权边界、执行责任和生态自治。

本轮核心结论：

1. **联盟是临时协作结构，不是新的主权主体。** 联盟只能取得任务契约明确授予的有限协调权限，不继承成员的根身份、根密钥、数据所有权或更高授权。
2. **采用联邦式动态联盟，而不是全局超级编排器或完全无治理的点对点网络。** 任务发起方拥有任务目标与验收权；各成员 Owner 保留本域能力、数据和执行授权权；ADS 协调本生态内部资源和工作流。
3. **先做硬门禁，再做组合优化。** 身份、信任、能力证明、数据用途、撤销新鲜度和本地授权是不可交易的准入条件；收益评分不能抵消未授权或不合规。
4. **每个任务必须与强单 Agent 基线比较。** 只有在相同任务、工具、预算和评估标准下，多 Agent 的质量、韧性或独立验证增益足以覆盖协调成本，才形成联盟。
5. **共享环境是协作状态底座，不是授权权威。** 痕迹可触发发现、唤醒、协商和重规划，但不能自行签发权限或把意图变成业务事实。
6. **执行、验证和价值归因分离。** 关键任务不允许执行联盟自行完成最终独立验收；贡献记录不等于授权、所有权或法律责任转移。
7. **资源治理采用分层、公平、可审计的调度。** 对稀缺算力、工具配额和任务槽位实行预算、配额、优先级和公平性约束；不把所有资源都转化为价格竞拍。
8. **RSI 只能提出候选组织规则。** 新规则进入隔离实验、Shadow、独立评估和人类批准流程；不得自动修改根治理或主线代码。

WP-025 是候选架构设计。本文所列 17 项验收场景、6 项候选 ADR 和 12 项威胁条目均未执行或批准。

## 1. 研究问题与范围

### 1.1 核心问题

当生态中存在多个能力不同、权限不同、资源不同、可信程度不同的 Agent 和 ADS 时：

- 谁可以发起联盟？
- 如何识别任务真正需要哪些能力？
- 哪些成员可以被允许加入？
- 谁负责联盟内部协调，协调者拥有什么权限？
- 如何分配计算、工具、数据访问和任务机会？
- 联盟创造的收益如何归因，成本和失败由谁承担？
- 成员退出、权限撤销、协调者失效或联盟冲突时如何接续？
- 如何防止联盟投票、声誉、经济激励或 RSI 规则突破本地 Owner 的治理边界？

### 1.2 不在本工作包范围内

- 不替代 WP-020 的跨生态信任绑定和授权链。
- 不替代 WP-021 的目录一致性和撤销传播。
- 不替代 WP-022/WP-023 的可信见证、成员治理和灾难恢复。
- 不替代 WP-024 的 Quorum 与恢复形式化验证。
- 不冻结完整经济系统、Token、支付结算或商业分润机制。
- 不假设 Agent 具备现实法律人格；责任主体仍需由相应组织、Owner 和人类治理制度确定。
- 不实现自动联盟 Runtime，不启用 Runner，不接入生产凭证。

## 2. 研究证据与证据边界

### 2.1 2026 年自治 Agent 联盟结构综述

Meng、Li、Hong、Chen，*A Survey on Optimal Coalition Structures Among Autonomous Agents*，IEEE/CAA Journal of Automatica Sinica，Vol.13 No.10，2026 年 10 月，DOI: 10.1109/JAS.2026.125921。

研究将联盟结构生成归纳为两个核心问题：联盟如何形成，以及联盟价值如何在成员之间分配；讨论大联盟、多联盟和受图结构约束的联盟，以及价值分配方法。

**架构启发：** Agent Ecology 应支持多个任务联盟并存，不能默认形成一个全局大联盟；能力组合和收益归因应分开建模。

**证据局限：** 综述并不直接证明本项目的 LLM Agent 联盟机制已经有效；具体算法仍需在本项目任务分布、授权约束和成本模型下验证。

原始来源：https://www.ieee-jas.net/en/article/doi/10.1109/JAS.2026.125921

### 2.2 能力中心型联盟形成模型

Chen 等，*Coalition formation problem: a capability-centric analysis and general model*，Science China Information Sciences，2024，DOI: 10.1007/s11432-023-4169-2。

研究从任务需求、能力聚合、能力度量和环境影响角度讨论联盟形成。

**架构启发：** 联盟不应仅按 Agent 名称、模型品牌或静态角色组合，而应围绕任务所需能力及其可验证证据进行组合。

**证据局限：** 研究对象包含机器人/人机协作的能力中心模型，不能直接视为 LLM Agent 生态的实证验收。

原始来源：https://doi.org/10.1007/s11432-023-4169-2

### 2.3 多 Agent 是否优于单 Agent 的受控评估

Kim 等，*Capable language models can outgrow the benefits of collaboration*，Nature Machine Intelligence，2026。MIT Media Lab 项目页披露了 260 种配置、6 个基准、5 类架构和匹配预算对照。

研究显示，多 Agent 的收益高度依赖任务类型和单 Agent 基线：部分研究任务/金融分析任务受益，短链路规划任务则可能因过度委派而显著退化。约 45% 单 Agent 成功率的经验阈值仅是该研究中的架构选择启发，不是普遍门槛。

**架构启发：** 必须采用任务级 Multi-Agent Admission Gate，先建立强单 Agent 基线，再决定是否联盟化；统一比较质量、成本、延迟、失败和验证收益。

**证据局限：** 基准任务、样本量、模型族和预算边界有限；不能直接外推到所有企业流程或长期生态任务。

原始来源：
- https://www.nature.com/articles/s42256-026-01268-y
- https://www.media.mit.edu/projects/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/overview/

### 2.4 MultiAgentBench 协作与竞争评估

Zhu 等，*MultiAgentBench: Evaluating the Collaboration and Competition of LLM agents*，ACL 2025，DOI: 10.18653/v1/2025.acl-long.421。

该基准纳入任务完成、协作和竞争指标，并比较星型、链式、树型、图型等协作拓扑和群体讨论/认知规划策略。

**架构启发：** 生态评估应同时测量任务质量、协作贡献、竞争行为、里程碑推进和协调开销，而非只看最终成功率。

**证据局限：** 基准表现不能直接证明真实组织治理、数据主权、责任归属或长期联盟稳定性。

原始来源：https://aclanthology.org/2025.acl-long.421/

代码与数据：https://github.com/ulab-uiuc/MARBLE

### 2.5 Stigmergy 局部自组织实验

Aina 与 Ha，*Deep reinforcement learning for multi-agent coordination*，Artificial Life and Robotics，2025-11-26 在线发表，2026 卷期，DOI: 10.1007/s10015-025-01089-z。

研究使用虚拟信息素和课程学习形成局部、去中心化的协作策略；在特定机器人任务仿真中报告了最多 5 个确定性环境 Agent 和 8 个随机环境 Agent 的协作结果。

**架构启发：** 环境痕迹可支持局部反应和动态分工；应让 Agent 基于有来源、有范围、有期限的状态线索调整协作。

**证据局限：** 这是机器人/深度强化学习仿真，不是 LLM Agent 或企业多生态部署证据；规模和任务边界有限。

原始来源：https://link.springer.com/article/10.1007/s10015-025-01089-z

### 2.6 分布式资源分配综述

Doostmohammadian 等，*Survey of distributed algorithms for resource allocation over multi-agent systems*，Annual Reviews in Control，Vol.59，2025，Article 100983，DOI: 10.1016/j.arcontrol.2024.100983。

综述从分布式资源分配和调度框架出发，讨论可行性、收敛性和网络可靠性等算法特征。

**架构启发：** 算力、工具配额、任务槽位和其他稀缺资源的调度应分别定义约束、可行性和收敛/稳定性条件；不能只以即时收益排序。

**证据局限：** 研究覆盖广泛的多智能体资源分配场景，不等于已为本项目选定某种具体调度算法。

原始来源：https://doi.org/10.1016/j.arcontrol.2024.100983

### 2.7 嵌套治理与公共资源制度研究

Ostrom 的公共资源治理研究提出边界明确、规则与本地条件相适应、参与式规则制定、监测、渐进制裁、争议解决、自治权承认和嵌套治理等原则。

**架构启发：** 多生态应采用嵌套治理与清晰资源边界；共享算力、共享工具和共享知识索引必须明确使用资格、成本承担、监测、争议和退出机制。

**证据局限：** 这是现实社会制度与公共资源治理研究。本文只借鉴其制度设计思想，不将 Agent 生态等同于现实共同体，也不以其替代法律、合同或组织责任制度。

原始来源：https://www.nobelprize.org/uploads/2018/06/ostrom_lecture.pdf

## 3. 核心架构决策：联邦式动态联盟

### 3.1 三种候选路线

| 路线 | 机制 | 优点 | 主要风险 |
|---|---|---|---|
| A. 中央总编排器 | 全局调度器选择成员、分配任务和资源 | 控制简单、统一观测 | 权力集中、单点故障、跨域越权、全局上下文泄露 |
| B. 完全去中心化 | Agent 直接协商、自治组成联盟 | 弹性强、局部自治 | 协商风暴、重复任务、串谋、治理与责任难定位 |
| C. 联邦式动态联盟 | 任务发起方提出目标；成员 Owner 本地准入；ADS/联盟协调者组织任务；各域本地门禁执行 | 兼顾自治、可治理、可审计和跨域协作 | 需要契约、状态机、授权和争议机制 |

**推荐候选：C. 联邦式动态联盟。**

这不是让 ADS 变成全局超级 Agent。每个生态仍有独立根治理、身份根、数据权威和本地执行门禁；联邦协调层只处理明确授权的目录、协商、状态与证据交换。

### 3.2 三类权力必须分离

1. **任务权（Mission Authority）：** 谁提出任务、定义成功标准、接受或拒绝结果。
2. **资源权（Resource Authority）：** 谁拥有算力、工具、数据、预算和服务配额，谁可以授予使用权。
3. **执行权（Execution Authority）：** 哪个主体在何种范围、期限、用途和预算内执行具体动作。

联盟协调者只获得任务契约中明确列出的协调权限；不得因担任 Coordinator 自动取得资源所有权或执行权限。

### 3.3 四类联盟

- **任务型联盟：** 围绕一个有明确目标和验收标准的短期任务形成，完成后解散。
- **服务型联盟：** 围绕稳定服务能力形成，采用短期租约/续约和持续健康检查。
- **跨生态联盟：** 由不同 ADS/业务领域成员组成；每个成员域分别批准本域能力、数据和资源使用。
- **验证型联盟：** 负责独立审计、复核或反证；与被验证的执行联盟保持利益隔离。

不建议默认创建全局永久大联盟；成员资格、任务权限和数据访问都必须有期限和退出条件。

## 4. 动态联盟生命周期

建议采用以下状态机：

1. **PROPOSED：** 任务 Owner 提出联盟提案。
2. **DISCOVERING：** 从本地权威目录和联邦摘要目录发现候选能力。
3. **ELIGIBILITY_CHECK：** 目标域检查身份、信任、能力证明、授权、撤销新鲜度、数据用途和资源可用性。
4. **NEGOTIATING：** 候选成员协商角色、接口、预算、期限、交付物和失败处理。
5. **COMMITTED：** 所有必要 Owner 对同一 Coalition Charter Digest 接受；必要授权在各域本地生效。
6. **ACTIVE：** 成员按任务契约执行；共享环境保存状态、工件、事件、证据和审计引用。
7. **SUSPENDED：** 授权撤销、成员状态不明、预算耗尽、冲突、证据过期或治理门禁触发时暂停。
8. **RECONFIGURING：** 成员加入/退出/替换或角色调整，必须提升 Membership Epoch 并重新评估相关授权。
9. **DISSOLVING：** 完成、取消、超时、失败或 Owner 撤销后进入解散。
10. **CLOSED：** 释放资源租约，撤销临时凭证，归档工件谱系、责任记录、成本和验收证据。

任何从 SUSPENDED/RECONFIGURING 返回 ACTIVE 的转换，都必须重新核验受影响的身份、授权、撤销水位、策略版本和任务状态。

## 5. Coalition Charter｜联盟任务契约

每个联盟必须绑定一个不可歧义的任务契约。候选字段如下：

| 字段组 | 最小内容 |
|---|---|
| 身份与范围 | coalitionId、taskId、ownerDomainId、ecosystemId、membershipEpoch |
| 目标与验收 | missionObjective、successCriteria、deliverables、acceptanceOwner |
| 成员与角色 | memberId、ownerId、role、capabilityRefs、delegationRefs |
| 权限与数据 | allowedActions、resourceScope、dataCategories、purpose、audience |
| 资源预算 | computeBudget、toolQuota、costCap、concurrencyLimit |
| 风险与治理 | riskTier、approvalRequirements、independentVerifier、denyConditions |
| 生命周期 | issuedAt、expiresAt、lease、renewalPolicy、exitConditions |
| 状态与证据 | charterDigest、policyDigest、eventCursor、evidenceRefs、auditRefs |
| 责任与争议 | taskOwner、executionOwner、resourceOwner、disputeRoute、incidentOwner |

以上是候选数据字典，不是已冻结 Schema。

### 5.1 契约签署与版本一致性

- 各参与 Owner 必须接受同一 Charter Digest；仅接受聊天消息或 A2A ACK 不算契约生效。
- 每次成员、角色、数据范围、预算、风险级别或验收标准变更都生成新 Charter Version 和 Membership Epoch。
- 旧凭证不能自动覆盖新版本；权限变化必须由对应 Owner 重新授权。
- 联盟契约只约束联盟任务范围，不改变成员原有的数据归属、根身份和业务责任。
- 过期或撤销状态不明时，敏感动作进入 HOLD。

## 6. 联盟形成算法：硬门禁与优化分层

### 6.1 第一层：不可交易的准入硬门禁

以下条件必须全部满足，才可成为候选成员：

1. 身份与工作负载来源可验证。
2. 能力声明由 Owner 或获授权 Publisher 证明。
3. 目标任务的用途、Audience、动作和资源范围合法。
4. 相关 Peer Trust Binding 有效；不依赖传递信任。
5. 撤销 Feed 和 Key/Membership Epoch 满足本地新鲜度策略。
6. 数据 Owner 已批准所需字段/数据类别和用途。
7. 资源 Owner 已确认配额、容量和预算。
8. 安全策略、风险等级和人类审批要求已满足。

**任何一项 DENY 即拒绝；关键状态 ABSTAIN、过期或不可达时按风险 HOLD。**

Trust Score、历史成功率、经济收益或多数投票不能覆盖硬门禁。

### 6.2 第二层：联盟组合优化

仅对已通过硬门禁的成员组合进行评估：

- 任务能力覆盖度与互补性；
- 能力证明质量和独立来源；
- 预计任务收益和完成概率；
- 协作通信、上下文、协调、仲裁和验证成本；
- 延迟、资源占用和预算；
- 故障域多样性与成员替补能力；
- 任务外部性、隐私暴露和共享状态风险；
- 贡献可验证性和验收独立性。

候选目标函数：

\[
U(C)=B(C)-K(C)-R(C)-E(C)
\]

其中 B 为任务收益，K 为协调/计算/通信成本，R 为执行与安全风险，E 为对其他成员或生态造成的外部成本。

该公式只用于已合格组合之间的比较。硬门禁不进入加权求和，不允许用高收益抵消未授权、隐私违规或根策略冲突。

### 6.3 Multi-Agent Admission Gate

在相同任务、工具、数据、模型可用性和总预算条件下，比较：

- 单 Agent 基线；
- 多 Agent 独立并行；
- 集中式协调；
- 图式/局部协商；
- Stigmergy 共享环境协作；
- 混合协调（环境痕迹为主、A2A 为必要补充）。

仅当多 Agent 带来的质量、韧性、覆盖率或独立验证收益超过新增成本和风险时，才允许联盟化。阈值必须由任务类型、风险和样本置信度确定，不直接套用单篇论文的 45% 经验阈值。

## 7. 资源治理与价值归因

### 7.1 资源分类

- **排他性数据资源：** 默认归 Owner 控制，采用用途绑定、最小披露和本地授权；不作为普通可交易资源。
- **稀缺计算资源：** GPU/CPU/内存/存储/网络带宽按配额、优先级、租约和成本上限调度。
- **工具调用配额：** 按风险、业务优先级、速率限制和服务等级分配。
- **任务机会与执行槽位：** 采用明确的优先级、截止时间、公平性和防饥饿策略。
- **共享知识与工件：** 以来源、访问范围、验证状态、版本和保留期治理；访问权不等于所有权。

### 7.2 候选调度策略

- P0 安全/合规与关键业务任务：使用预留容量和显式审批，不参加普通竞价。
- P1 高优先级任务：采用优先级队列、配额上限和可审计抢占规则。
- P2 普通任务：采用加权公平队列、租约、成本预算和反饥饿机制。
- P3 可延迟任务：在低峰时段使用剩余容量，允许延后或取消。

具体配额、权重、抢占条件和公平性阈值尚待资源 Owner 和业务 Owner 共同评审。

不建议把所有资源调度都做成 Agent 之间的自由竞价。价格/竞价机制最多用于低风险、可替代、边界清晰的资源；高风险业务、隐私数据和根权限不应竞价。

### 7.3 价值归因与责任分离

- 贡献以可验证事件、工件、版本、任务里程碑和独立验收为证据。
- 贡献评分不能成为授权凭证或自动提升信任等级。
- 贡献归因不能自动转移数据所有权、知识产权或法律责任。
- 任务失败应区分任务定义错误、数据/能力提供错误、执行错误、协调错误和治理错误。
- 争议由任务 Owner、资源 Owner、执行 Owner 和独立审计方按责任边界处理；高风险争议升级人类治理。

## 8. Stigmergy、A2A 与 ADS 的职责边界

### 8.1 Stigmergy：默认协作底座

共享环境承载：
- 任务需求与能力缺口；
- 成员提案、角色承诺和租约状态；
- 资源可用性、预算和任务进度；
- 工件、验证结果、依赖和失败痕迹；
- 暂停、撤销、争议和解散事件。

痕迹应带来源、版本、命名空间、Purpose、TTL、访问策略和证据状态。痕迹是协作线索，不是授权命令。

### 8.2 A2A：有限的直接协商通道

A2A 用于：
- 能力细节协商；
- 角色/接口确认；
- 任务委托与拒绝；
- 需要同步反馈的协作；
- 对共享状态进行澄清。

A2A 消息不能替代 Charter 接受、Owner 授权、PDP/PEP 判定或正式业务事件。

### 8.3 ADS：生态内部协调与治理

ADS 负责：
- 生态内能力注册、发现和任务路由；
- 生态内资源协调与工作流状态管理；
- 任务联盟生命周期和协作治理；
- 事件、工件、证据与审计索引；
- 风险分级、审批编排和状态回写；
- RSI 候选规则的隔离评估与进化管理。

ADS 不拥有成员生态之外的数据权威，不覆盖业务领域中心数智底座或企业数智底座的 Owner 权限，也不成为全局超级 Agent。

## 9. 权力、数据与责任边界

| 主体 | 可决定 | 不可决定 |
|---|---|---|
| Agent | 局部计划、能力调用请求、执行建议 | 根策略、其他主体权限、跨域数据授权 |
| 联盟 Coordinator | 任务排序、分工建议、状态汇总、协作重试 | 扩大成员授权、签发根权限、改变 Owner 数据策略 |
| 任务 Owner | 任务目标、验收标准、任务接受/终止 | 未经授权处置他域数据或资源 |
| 能力/数据/资源 Owner | 本域能力发布、数据用途、资源配额与撤销 | 替代其他域 Owner 做决定 |
| ADS | 生态内协调、管理、考核和进化编排 | 覆盖成员根治理或全局授权 |
| 联邦协调服务 | 最小化目录摘要、协议转发、证据索引和状态同步 | 持有成员域生产凭证或直接执行成员域副作用 |
| 人类治理 | 根策略、重大审批、争议裁决、否决、接管、问责 | 将不可验证的自动评分当作独立事实 |

同一人/组织可能承担多个 Owner 角色，但必须在授权、审计和争议流程中显式区分角色，不因组织关系而自动合并权限。

## 10. 主要威胁与控制

1. **联盟权限继承：** Coordinator 或联盟把成员权限合并成超范围权限。控制：任务范围委托、父子约束衰减、本地 PDP/PEP。
2. **Sybil 与能力虚报：** 伪造大量 Agent 或夸大能力。控制：身份/Owner 证明、唯一主体去重、能力证据抽检。
3. **联盟垄断与排斥：** 少数成员长期控制任务和资源。控制：多样性约束、可解释的轮换/公平策略、申诉与独立监测。
4. **资源饥饿：** 高频或高声誉成员占满算力/工具。控制：配额、租约、加权公平队列和反饥饿。
5. **贡献归因操纵：** 成员伪造中间步骤、互相刷贡献。控制：事件/工件证据、独立验收、贡献与信任/授权分离。
6. **Coordinator 失陷：** 协调者误用或窃取成员权限。控制：Coordinator 不持有成员生产凭证；短期委托和本地执行门禁。
7. **成员退出后残留权限：** 退出成员继续执行。控制：Membership Epoch、Lease/Fencing、撤销传播和本地 Kill Switch。
8. **跨域外部性：** 工件或共享索引泄露敏感数据。控制：字段级过滤、最小披露、输出检查和接收域本地审批。
9. **重复任务/双重执行：** 多联盟同时接管同一任务。控制：Owner-scoped Lease、幂等 operationId 和 fencing token。
10. **串谋和奖励操纵：** 联盟成员相互背书或操纵价值分配。控制：独立来源、随机抽检、争议机制和延迟结算。
11. **解散后资源悬挂：** 成员退出或任务终止后资源未释放。控制：显式清算、租约到期、状态回写和审计。
12. **信誉自强化：** 热度和历史成功率造成路径依赖。控制：证据质量与声誉分离、时效衰减、独立验证和新成员观察期。

## 11. WP-025 验收矩阵（候选，全部 NOT_RUN）

| 编号 | 场景 | 预期结果 |
|---|---|---|
| ECO-01 | 同预算强单 Agent 与多 Agent 对照 | 记录质量、成本、延迟、风险和协调开销 |
| ECO-02 | 多 Agent 无增益或负增益 | 不形成联盟，保留单 Agent 执行 |
| ECO-03 | 能力互补且协作增益可验证 | 生成有边界的候选联盟 |
| ECO-04 | 高收益但目标域授权 DENY | 硬门禁拒绝，不进入评分补偿 |
| ECO-05 | Coordinator 请求成员根权限 | 拒绝，联盟不继承根权限 |
| ECO-06 | 跨域数据/能力未获接收域批准 | 不得执行，源域批准不能替代目标域授权 |
| ECO-07 | 成员租约过期或 Membership Epoch 变更 | 旧凭证被 fencing，重新认证/授权 |
| ECO-08 | 关键成员退出 | 从持久工件和当前状态安全接续，不继承退出成员凭证 |
| ECO-09 | 两个联盟竞争同一任务 | Owner-scoped Lease 与幂等机制阻止重复副作用 |
| ECO-10 | 高需求成员挤占共享算力 | 配额、公平队列和反饥饿策略生效 |
| ECO-11 | 能力声明夸大或证据过期 | 降级/隔离能力，不以声誉替代证明 |
| ECO-12 | Sybil 成员或多个别名加入联盟 | 按唯一主体/Owner 关系去重并触发审查 |
| ECO-13 | 联盟成员互相刷贡献或操纵分润 | 独立证据审查，争议冻结结算，不提升权限 |
| ECO-14 | 执行联盟自行验收自身关键成果 | 独立验证门禁阻止自我签发可信结论 |
| ECO-15 | 过期/投毒痕迹触发高风险任务 | 只作为待核实线索，不能直接授权或提交业务事实 |
| ECO-16 | 联盟解散或任务取消 | 临时凭证撤销、资源释放、工件和审计归档 |
| ECO-17 | RSI 提议修改联盟规则或准入策略 | 仅进入隔离实验、Shadow、独立评估和人工审批 |

## 12. 评估指标

必须在同任务、同工具和匹配预算下测量：

- **任务价值：** 成功率、质量、覆盖率、里程碑达成、结果可验证性。
- **协作效率：** Coordination Overhead Ratio、Token/算力/工具成本、端到端延迟、重复工作率。
- **生态韧性：** 成员退出后的接续成功率、故障恢复时间、单点依赖、联盟重组时间。
- **治理质量：** 未授权动作数、跨域边界违规数、审批完整率、审计覆盖率、争议处理时长。
- **资源公平：** 配额偏差、任务等待时间、饥饿率、资源利用率和不同 Owner 的资源可获得性。
- **信任质量：** 能力证明有效率、撤销传播延迟、独立验证覆盖率、Sybil/串谋识别率。
- **经济质量：** 单位有效任务成本、可验证贡献比例、资源闲置和外部成本。

硬安全指标（未授权动作、跨域数据泄露、根权限突破）不得用平均分抵消；出现一次有效违规就应单独触发事故与阻断评估。

## 13. 后续研究与验证路线

### WP-025-A｜联盟契约与状态机
冻结 Charter 的字段语义、版本、成员 Epoch、租约和撤销状态；完成状态转换表与负向测试。

### WP-025-B｜能力组合与准入模型
将能力需求、Owner 证明、目标域授权和任务约束分离；建立同预算单 Agent 基线与多 Agent 选择器。

### WP-025-C｜资源调度与公平性
比较固定配额、优先级队列、加权公平队列、租约和受限竞价；验证饥饿、抢占和资源耗尽场景。

### WP-025-D｜价值归因与争议治理
定义事件证据、工件贡献、验收责任和争议冻结；禁止贡献分数自动影响授权。

### WP-025-E｜形式化与仿真验证
为联盟成员加入/退出、权限撤销、任务双重执行、协调者失陷、资源饥饿和联盟串谋建立状态模型；随后进行确定性仿真和独立 Checker。

### WP-025-F｜跨生态 Shadow 试验
仅使用合成数据和非生产凭证，先在两个隔离生态中验证目录发现、联盟契约、成员本地授权、资源租约、审计和解散流程；未通过 F0、Owner 签署和人类治理门禁前，不开展真实生产接入。

## 14. 候选架构决策（待评审）

| ADR | 决策主题 | 候选结论 |
|---|---|---|
| ADR-155 | 联盟组织模式 | 采用联邦式动态联盟；不设全局永久大联盟或全局超级编排器 |
| ADR-156 | 联盟权力边界 | Coalition Charter 只授予任务范围内有限协调权，不继承成员根身份、根密钥、数据所有权和本地授权 |
| ADR-157 | 联盟准入 | 身份、Owner 证明、授权、撤销新鲜度、数据用途和资源资格为硬门禁；收益评分不能覆盖 DENY/HOLD |
| ADR-158 | 多 Agent 采用条件 | 先建立强单 Agent 基线；匹配预算下证明增益大于协调成本后才联盟化 |
| ADR-159 | 执行与验证分离 | 关键成果必须由独立验证主体/Owner 验收；执行联盟不得自行签发独立可信证明 |
| ADR-160 | 资源与贡献治理 | 稀缺资源按 Owner 配额、优先级、公平队列和租约治理；贡献归因基于可验证证据且不自动提升授权/信任 |

## 15. 未决问题

1. 哪些任务类别可以自动形成低风险联盟，哪些必须人工批准？
2. Coalition Charter 是否需要统一跨域 Schema，还是先采用领域扩展加最小公共核心？
3. Coordinator 的选举/指定方式如何防止权力集中与串谋？
4. 多个任务 Owner 对共享成员和资源的冲突优先级如何裁决？
5. 公平性应按 Agent、Owner、生态、任务紧急度还是历史资源占用计算？
6. 联盟价值如何在非线性贡献、负外部性和共同失败下归因？
7. 何种独立性要求足以保证验证联盟与执行联盟不构成利益冲突？
8. 共享环境的痕迹如何避免被联盟操纵成事实、授权或信誉？
9. 跨生态成员退出时，正在进行的任务如何安全停机或交接？
10. RSI 对联盟形成规则的改进如何做离线评估、Shadow 和回滚？

## 16. 本轮结论

Agent Ecology 应从“Agent 之间可以协作”升级为“生态可以在明确权力边界内形成、运行、调整和解散临时联盟”。

**推荐架构是联邦式动态联盟：任务驱动形成、能力互补组合、Owner 本地准入、契约限制权限、Stigmergy 承载协作状态、A2A 补充必要协商、ADS 负责生态内协调、独立验证和人类治理守住边界。**

该模型既允许群体智能涌现，也防止联盟成为新的越权主体。下一步应先验证 Coalition Charter、成员 Epoch、任务租约和多 Agent Admission Gate，再讨论自动化联盟 Runtime。
