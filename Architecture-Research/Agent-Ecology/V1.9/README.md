## 本版关键结论

1. Stigmergy 不等于共享黑板，也不等于把所有 Agent 对话搬进共享记忆。核心是持久环境状态、可追溯痕迹/工件、局部观察和后续行动之间的反馈闭环。
2. 共享状态默认视为通信通道；即使没有协作意图或显式 A2A 消息，也可能发生跨主体信息访问与影响。
3. 环境检索必须有界；每次读取采用 top-k 和权限/来源/新鲜度过滤，不能要求每个 Agent 读取全量群体记录。
4. 持久工件必须脱离原生产者继续存在，并保留来源、版本、引用和验证证据。
5. A2A 用于明确的主体间协商、委派和交互；痕迹协作仍作为默认的持久协调机制。MCP 继续承担 Agent-to-Tool 的垂直工具接入。
6. 学习型局部规则只能在隔离环境中训练和评估；运行时继续执行确定性校验、授权、过期、冲突处理和人类治理门禁。
7. 多 Agent 不是默认最优。每类任务必须与单 Agent 基线在相同总推理预算、工具和评估条件下比较。\n8. 能力发现目录与能力 Owner 本地权威目录分离；联邦摘要可以最终一致，执行前授权必须由目标生态本地 PDP/PEP 决定。\n9. 共享环境的重新观察由 Runtime 通过订阅、唤醒、游标续读和周期对账保障，不依赖模型自发重读。\n10. A2A、MCP、CloudEvents、Ontology、SPIFFE 及本地 PDP/PEP 责任边界清晰；任何协议消息均不自动构成授权。

## 证据边界

本版引用的研究包括预印本、已发表论文、协议草案、正式规范和受控仿真实验。论文报告的实验结果不等于本项目已复现、已部署或已通过验收。原 Stigmergy 合成实验 22 项、F1 能力发现验收 20 项，共 42 项全部 NOT_RUN；8 项原 ADR 加 2 项联邦发现 ADR，共 10 项均为 Candidate。V1.8 F0 12 项 Gate 仍全部 NotRun；没有真实领域数据授权、Runtime 执行或生产写入。
