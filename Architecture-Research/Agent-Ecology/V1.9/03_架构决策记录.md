## 1. 设计理由

- 近期共享记忆研究表明，未被声明为共享的状态也可能发生跨 Agent 读取和影响，因此不能依赖提示词或主体“是否知道共享”作为安全边界。
- ScaleMAS 的结果支持有界检索、持久消息和引用关系作为可扩展底座能力，但引用热度不能替代事实验证。
- Waggle 支持研究局部反应规则与可重组组织，但其固定 Runtime 假设与匿名接口不能直接取代本项目身份、授权和审计模型。
- SwarmWorld 支持持久工件和环境外部记忆的实验价值，但空间仿真不能直接证明企业工作流可用。
- Nature Machine Intelligence 的对照研究提醒：多 Agent 的收益依赖任务分解结构和单 Agent 基线，不应默认增加主体数量。

## 2. 未决决策

1. 不同类型痕迹/工件的默认 TTL、衰减和永久保留类别。
2. 检索排序信号的权重、反操纵机制和人工复核触发条件。
3. 局部协作视图中的身份字段、短期别名与事后问责之间的映射。
4. 哪些状态允许最终一致，哪些状态必须由领域 Owner 强一致提交。
5. A2A 触发条件与超时/拒绝/重新协商状态机。
6. 跨生态共享索引的租户隔离、最小披露和 Sybil/串谋防护。
7. 多 Agent 采用门槛所需的任务级样本量、置信区间和成本模型。

## 3. 决策权限

本文件只记录候选架构决策，不代表用户、ADS、业务领域中心数智底座、企业数智底座或任何领域 Owner 已批准。涉及根身份、根策略、授权上限、真实数据共享、生产副作用和 RSI 主线变更的事项，必须进入既有的人类外环治理与独立审批流程。


## 4. V1.9-B 补充决策依据

- 能力广告是 Owner 的签名声明，不是调用授权；联邦摘要目录只提供候选发现。
- 目录新鲜度、撤销水位、成员状态和能力证明必须在高风险执行前重新核验。
- A2A 的 AUTH_REQUIRED 是任务等待授权状态；不得把它解释为 Permit。
- 共享环境既是协作介质，也是潜在通信/泄露通道；访问必须按域、任务、Purpose 和数据分类隔离。
- FCP 不持有成员域生产凭证，不成为全局超级信任根。

## 5. WP-022 补充决策依据

- Witness Cosignature 表示 Witness 对某个 Log Checkpoint 的历史一致性观察，不是对业务事实的背书。
- Witness 对每个 Log Origin 维护单调状态；签名前必须完成一致性验证和原子持久化。
- Quorum 安全必须同时考虑签名阈值与运营/故障域独立性；公钥数不能替代独立性证明。
- Monitor 必须具备绕过 FCP/Log 的旁路观察能力；Gossip 用于传播和发现冲突，不构成全局共识。
- 分叉证据固定后进入人类治理外环；本地 PDP/PEP 仍拥有最终 DENY/HOLD 权。

| ADR-131 | Witness 成员生命周期 | Witness 先经身份核验和 OBSERVE_ONLY，再进入 ACTIVE；暂停/隔离/退出保留历史记录 | Candidate |
| ADR-132 | Witness 多域独立性证据 | Quorum 独立性同时核验运营域、管理域、密钥托管域、备份域和部署域 | Candidate |
| ADR-133 | 密钥用途隔离 | Trust Root、Witness、Log、Backup、Transport 和 Recovery Key 不跨角色复用 | Candidate |

| ADR-135 | 历史签名风险窗口 | 区分检测时间、最早疑似泄露时间、确认时间和撤销时间；历史验证允许 VALID/INDETERMINATE/REJECT | Candidate |

## 6. WP-023 补充决策依据

- Witness 生命周期必须通过追加式事件记录；状态变更不能删除历史签名和 Checkpoint。
- Trust Root、Witness、Log、Backup、Transport 密钥分层，根密钥离线多方分持，日常 Witness 签名密钥用途隔离。
- 正常根升级采用旧根阈值与新根阈值双重验证、逐版本连续更新和过期/回滚检测；紧急根失陷依赖预登记带外恢复锚。
- 历史签名验证必须区分检测时间与最早疑似泄露时间；证据不足时返回 INDETERMINATE，不作乐观推断。
- Witness 快照签名只证明完整性/来源，不证明新鲜度；恢复必须与独立 Witness Checkpoint 和 WAL 水位对账。
- 成员替换采用 OBSERVE_ONLY 与 Joint Quorum；不可证明连续性时保持隔离。

## 7. WP-024 补充决策依据

- Witness Quorum 仅为跨生态透明证据的多方观察/签署门槛，不等同于完整 BFT 状态机共识。
- 状态擦除恢复身份可能削弱 Quorum 交集中的非双签保证；恢复状态连续性必须进入安全预算。
- Witness 安全状态先持久化再签名；若存储可能回滚，必须验证外部高水位或隔离旧身份。
- 安全模型、确定性模拟和分布式故障注入分别提供不同证据，不能相互替代。
- 安全不变量与活性指标分开验收；不能达到 Quorum 时保持 HOLD，不自动降低门槛。

| ADR-151 | L0 Quorum 组合穷举回归 | 固定成员参数 n=4/7/10/13、q=2f+1 的全部不同 Quorum 集合对纳入可复现回归；结果仅适用于固定成员与唯一身份假设 | Candidate |
| ADR-152 | 持久化先于签名并非充分条件 | 即使签名前已持久化，若恢复可回滚该状态且原身份重新 ACTIVE，仍可能双签 | Candidate |
| ADR-153 | 状态连续性失败时隔离旧身份 | 无法证明防双签状态未回滚时，旧 Witness 身份不得恢复 ACTIVE；须隔离并经新 Epoch 治理 | Candidate |
| ADR-154 | 模型验证引擎与范围必须明示 | Python BFS、TLC、模拟器和故障注入的证据分开登记；不得将一个引擎的结果冒充另一引擎结果 | Candidate |

## 8. WP-024-L0/L1 补充决策依据

- 四组 Quorum 参数的实际最小交集均符合 2q-n=f+1；固定成员与唯一身份条件必须随结论披露。
- 在 f 个 Byzantine 身份之外，再出现一个保留原身份/密钥的状态擦除恢复身份，即可构造最小交集全部可双签的冲突证书示例。
- 持久化先于签名是必要条件，但存储回滚后仍恢复 ACTIVE 会再次破坏防双签约束。
- 安全恢复必须保留单调状态，或在无法证明状态连续性时隔离身份。
- Python BFS 的有界无反例不等于任意规模证明；TLC 尚未运行。
