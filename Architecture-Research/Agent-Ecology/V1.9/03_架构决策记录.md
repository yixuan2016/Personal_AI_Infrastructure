## 1. 设计理由

- 近期共享记忆研究表明，未被声明为共享的状态也可能发生跨 Agent 读取和影响，因此不能依赖提示词或主体“是否知道共享”作为安全边界。
- ScaleMAS 的结果支持有界检索、持久消息和引用关系作为可扩展底座能力，但引用热度不能替代事实验证。
- Waggle 支持研究局部反应规则与可重组组织，但其固定 Runtime 假设与匿名接口不能直接取代本项目身份、授权和审计模型。
- SwarmWorld 支持持久工件和环境外部记忆的实验价值，但空间仿真不能直接证明企业工作流可用。
- Nature Machine Intelligence 的对照研究提醒：多 Agent 的收益依赖任务分解结构和单 Agent 基线，不应默认增加主体数量。

## 2. 未决决策

1. 不同类型痕迹/工件的默认 TTL、衰减和永久保留类别。
2. 检索排序信号的权重、反操纵机制和人工复核触发条件。
3. 局部协作视图中的身份字段、短期别名与事后问责之间的映射。
4. 哪些状态允许最终一致，哪些状态必须由领域 Owner 强一致提交。
5. A2A 触发条件与超时/拒绝/重新协商状态机。
6. 跨生态共享索引的租户隔离、最小披露和 Sybil/串谋防护。
7. 多 Agent 采用门槛所需的任务级样本量、置信区间和成本模型。

## 3. 决策权限

本文件只记录候选架构决策，不代表用户、ADS、业务领域中心数智底座、企业数智底座或任何领域 Owner 已批准。涉及根身份、根策略、授权上限、真实数据共享、生产副作用和 RSI 主线变更的事项，必须进入既有的人类外环治理与独立审批流程。


## 4. V1.9-B 补充决策依据

- 能力广告是 Owner 的签名声明，不是调用授权；联邦摘要目录只提供候选发现。
- 目录新鲜度、撤销水位、成员状态和能力证明必须在高风险执行前重新核验。
- A2A 的 AUTH_REQUIRED 是任务等待授权状态；不得把它解释为 Permit。
- 共享环境既是协作介质，也是潜在通信/泄露通道；访问必须按域、任务、Purpose 和数据分类隔离。
- FCP 不持有成员域生产凭证，不成为全局超级信任根。
