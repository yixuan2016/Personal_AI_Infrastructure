# V1.5 参考部署与责任边界

## 1. 领域自治市场
- 领域 Runtime 发布任务契约，管理本地 Agent Proposal。
- 领域分配器负责专业能力匹配、局部预算和联盟形成。
- 领域 PEP 对每个资源访问和工具调用执行最终授权。
- State Coordinator 通过 CAS、Lease、Fencing 提交唯一执行权。

## 2. ADS 联邦治理
- ADS 管理跨域预算、公共能力目录、共同 Ontology、身份联邦和跨域风险策略。
- ADS 不持有所有领域私有任务数据，也不直接执行所有任务。
- ADS 对跨域资源冲突和公共资源集中度进行协调。
- 高风险授权、根策略发布和RSI上线由人类外环批准。

## 3. 生态市场安全边界
- 内部资源额度仅用于核算，不可兑换现实货币。
- Proposal/Bid 不等于权限或执行权。
- 信誉影响候选排序，不自动授予权限。
- 预算和安全硬约束优先于效用函数。
- 分配结果最终由CAS、Lease和Fencing落地。

## 4. 能力与知识治理
- 能力声明、测试证据、真实任务验收、独立复核和长期稳定性分级管理。
- 知识候选必须来源可追溯、反证可登记、版本可回滚。
- ADS公共知识必须经过领域适配验证后采用。
- 策略知识、根授权和生产发布不得由Agent自我批准。

## 5. 自修复
- 先隔离、后接续。
- 旧执行者的Fencing Token必须失效。
- 新执行者重新获取任务绑定授权。
- 外部副作用结果不确定时先对账，不盲目重试。
- 所有Repair Plan保留触发原因、执行证据和回滚方案。
