# G2-06.9｜十星异构节点与区域部署配置

**状态：** RC0 配置候选，待 OEM 与站点 Owner 核验  
**前提：** 双区域，每区域五颗算力星；十颗星不要求同构

## 1. 设计原则

设备型号、节点角色和站点部署要分开决策。每颗星先定义业务角色和工作负载，再决定 CPU/GPU/存储/网络组合。不能先采购相同机柜，再试图让所有站点承担相同任务。

## 2. 五类参考节点

### A 类：控制与通用计算节点

- CPU 候选：AMD EPYC 9956（高密度/功率效率候选）、EPYC 9996（高功率密度候选）；Intel Xeon 6980P 作为既有 Intel 生态对照。
- GPU：不强制配置；需要推理/图形/预处理时再选 PCIe 加速卡。
- 内存：按虚拟化、数据库、Agent Sandbox、控制服务的工作集确定 DDR5 RDIMM/MRDIMM 容量与频率。
- 存储：企业 NVMe 系统盘与本地缓存；事务日志与状态库需独立持久化策略。
- 网络：管理/控制网络独立；跨区域控制链路与租户数据路径分开。
- 关键验证：NUMA、内存带宽、虚拟化、加密、网络 PPS、控制服务 P99 和功耗。

### B 类：GPU 训练/推理节点

路线一：NVIDIA
- 机柜级：GB300 NVL72，72 GPU + 36 Grace CPU，液冷，形成单机柜 NVLink Scale-up 域。
- 8-GPU 服务器：HGX B300 平台，按 OEM 服务器 SKU 核验 CPU、NIC、NVLink、供电与冷却。
- NIC/网络：ConnectX-8；节点间选择 Quantum-X800 InfiniBand 或 Spectrum-X Ethernet。

路线二：AMD
- 高密度：8× MI355X OAM 平台，2.3TB HBM3E 总容量，液冷和 OAM 基板为关键约束。
- 灵活扩展：MI350P PCIe 卡，适配经过验证的 PCIe 服务器。
- 软件：锁定 ROCm、内核、框架、通信库、驱动和容器版本。
- 关键验证：GPU 互连拓扑、集合通信、显存、ECC、故障隔离、Checkpoint、功耗和冷却。

两条路线应独立形成验证基线，不建议在同一高性能训练 Fabric 中混搭未验证的 CUDA/ROCm 节点并假设通信栈互操作。

### C 类：高性能存储节点

- 热数据：Micron 9650 Gen6 SSD，优先用于经过 PCIe Gen6 认证的主机平台。
- 温数据：Micron 9550、Solidigm D7-PS1010 或 Kioxia CM7-V，按耐久、双端口、容量和性能选型。
- 冷数据：Seagate Mozaic 4+ 44TB 作为候选 HDD 容量层，需确认实际采购 SKU 和机箱兼容性。
- 存储服务：按对象、块、文件、并行文件系统和 NVMe-oF 工作负载分层。
- 关键验证：元数据扩展、重建窗口、故障域、副本一致性、端到端校验、恢复时间、数据驻留和功耗。

### D 类：网络与数据交换节点

- GPU Scale-out：Quantum-X800 InfiniBand 或 Spectrum-6/Spectrum-X Ethernet 选择其一作为主要计算网络。
- NIC：ConnectX-8；Vera Rubin 前瞻路线按 OEM 参考设计评估 ConnectX-9。
- Storage Fabric：单独设计拥塞域、路由、QoS 和多路径。
- WAN：每区域至少验证物理路径多样性、运营商/自治系统、路由收敛和带外运维。
- 关键验证：端到端有效吞吐、P99 RTT、丢包/重传、ECN/PFC、FEC、MTU、光模块和线缆兼容。

### E 类：设施与管理节点

- BMC/Redfish 管理网络、带外交换、PDU、UPS、CDU、温度/流量传感器、漏液检测和消防联锁。
- 设施控制不得依赖租户数据网络或全局 ADS 在线。
- 关键验证：单路/双路供电、冷却冗余、设施告警、联锁、维护窗口和安全停机。

## 3. 双区域十星部署逻辑

每区域五颗星可采用互补分工，而不是固定五种单一类型：

| 区域 | 星位 | 建议主要角色 | 角色互补要求 |
|---|---|---|---|
| Region A | A1 | GPU 密集型 | 提供高性能训练/推理能力 |
| Region A | A2 | CPU/HPC 型 | 数据预处理、科学计算、Agent 执行 |
| Region A | A3 | 存储型 | 区域热/温/冷数据服务 |
| Region A | A4 | 通用/控制型 | 本地 ADS/SCO/LCP、控制与业务服务 |
| Region A | A5 | 网络/边缘/备用型 | 多运营商接入、边缘推理和故障接管 |
| Region B | B1 | GPU 密集型 | 与 Region A 异构或同构均可，但需互操作 |
| Region B | B2 | CPU/HPC 型 | 任务接管和跨区域计算能力 |
| Region B | B3 | 存储型 | 区域数据副本与授权数据服务 |
| Region B | B4 | 通用/控制型 | 区域自治与本地恢复 |
| Region B | B5 | 网络/边缘/备用型 | 多运营商接入、故障隔离与接管 |

此表仅为功能角色建议，不能推导每颗星必须配置一整套独立 GPU/存储机柜。站点实际资源可以共址或共享，但必须保留 Owner、故障域和数据路径边界。

## 4. 单星设备预算模板

每颗星冻结配置前必须填入：

- CPU 型号/数量/插槽/功率/内存通道/DIMM SKU；
- GPU 型号/数量/形态/显存/互连/驱动/固件/功率；
- SSD/HDD 型号/数量/容量/耐久/RAID 或复制策略；
- NIC/DPU 型号/端口速率/光模块/线缆/交换机型号；
- GPU Fabric、Storage Fabric、Control Network 和 WAN 拓扑；
- 机柜高度、输入电压、冗余 PSU、最大功率和冷却方式；
- BMC、Redfish、TPM、Secure Boot、固件签名与远程维护；
- 业务任务画像、性能基线、故障域、恢复目标和验收证据。

## 5. 功率与散热核算原则

不能把 GPU TDP、CPU TDP 和交换机功耗简单相加后当作机柜最终功率。必须区分：

- 芯片/模块 TDP 或 TBP；
- 服务器整机输入功率；
- 机柜 PDU 实测功率；
- 电源转换损耗和冗余；
- 液冷泵、CDU、风扇和网络设备功耗；
- 峰值、稳态、瞬态和故障降级工况。

GB300 NVL72 和 MI355X OAM 等高功率设备必须以 OEM 机柜设计、供电和液冷参数为准。任何站点在未完成设施 Owner 评估前，不得确定 GPU 机柜数量。

## 6. 软件与固件兼容边界

- NVIDIA 路线：CUDA、驱动、固件、NCCL、DOCA/ConnectX、网络交换机 NOS、Mission Control/OEM 管理栈版本锁定。
- AMD 路线：ROCm、驱动、固件、RCCL、GPU Operator、OAM 平台和交换网络版本锁定。
- CPU 路线：BIOS、微码、内存 QVL、NUMA、CXL/PCIe、虚拟化和安全特性验证。
- 存储路线：NVMe 固件、OCP 遥测、PLP、双端口、端到端校验、文件/对象/块服务版本验证。
- 网络路线：NOS、NIC 固件、交换机 ASIC、光模块、线缆、FEC、拥塞控制和拓扑版本锁定。

## 7. 配置冻结门槛

任何设备从“候选型号”升级为“参考 BOM”前，至少完成：
1. 厂商正式 SKU 与区域供货确认；
2. OEM 兼容性清单与固件版本确认；
3. 真实任务基准测试；
4. 功率、液冷、机柜和设施联锁验证；
5. 网络端到端测量与故障切换；
6. 存储持久性、故障重建和数据完整性测试；
7. 双区域互操作和故障恢复验证；
8. Owner 签署与独立见证。

## 8. 当前结论

G2-06.9 已明确一组可追溯的 CPU/GPU/SSD/HDD/NIC/交换机候选型号，并给出十星异构角色分配方式。当前仍是设备候选基线，尚未冻结采购 BOM，也未证明所有型号在同一 OEM 平台中互相兼容。
