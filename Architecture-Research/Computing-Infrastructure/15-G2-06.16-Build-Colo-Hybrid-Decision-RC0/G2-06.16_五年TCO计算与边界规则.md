# G2-06.16｜五年TCO计算与边界规则

## 1. 公平比较方法

三路线都按相同GPU SKU、数量、业务负载、实际有效GPU小时、存储容量、RPO/RTO、安全要求、五年期限和财政口径比较。必要时将一期开工至可用的时间损失转换成“有效GPU小时缺口”和业务机会成本；不可只比较建设CAPEX。

## 2. 三路线现金流

设t=0..5，r为经财务确认的折现率：
- NPV_Total = CF_0 + Σ(t=1..5) CF_t /(1+r)^t − Residual_5/(1+r)^5。
- A自建：CF0包括土地/地基/建筑/许可/变电站/冷源/配电/CDU/IT/光模块/税运安装；CFt包括能源、水、网络、设施与IT维保、人员、保险、周期性更新和碳合规。
- B托管：CF0包括入驻/改造/一次性接入、IT与网络、测试、押金（押金须单列可返还）；CFt包括机柜/预留kW租费、可计量能源或全包电费、液冷服务费、网络、远程手、IT维保、保险及续租价差。
- C专属套间/Powered Shell：CF0包含场地改造/专属下游配电/CDU与二次侧（取决于合同）、IT设备与接口验收；CFt含长期租费、上游电/水/冷源服务费、业主专属设施维保、人员与合同责任，以及退出复原。

## 3. 五种计费模式不可重复加总

- **M1 全包式租赁**：托管租金已含电力/冷却服务，不能再按PUE重复计入全量能源成本；仍应分列超额计费和环境相关费用。
- **M2 预留kW租金+电量单独计费**：容量租金按合同预留kW计算；电量按服务点实际计费与合同电价计算。
- **M3 能耗转嫁/代收（pass-through）**：须确认电表点与PUE、UPS/泵/冷机分摊和管理费，避免双方都计算同一损耗。
- **M4 自建按设施实测**：公用事业费用按电量+需量/容量+其他附加；若设施总表已经计入冷机/UPS，不再重复加上设施设备能耗。
- **M5 PUE估算法（无实测）**：E_Facility = Σ_h P_IT,h×PUE_h×1h；设施相关电费按合同计价，但不得再加计已被PUE覆盖的辅机用电。

## 4. 负荷、液冷和水的口径

- HPE 192kW仅是某款NVL72 rack的母线规划建议，不代表平均用电。
- IT年能耗 = Σ每小时实际IT功率×1h；没有小时曲线时用合理的负荷情景并注明不确定性。
- 设施年能耗=全年设施计量电量；没有时可用IT功耗×PUE估算。
- 水成本按供水量、取水/耗水/排污和水权/再生水合同分别计；若租赁包含水务不重复添加。
- 进口税、增值税/销售税、土地租期、汇率、保险、环保和提前退出费用按合同与辖区核算。

## 5. 计算单位有效产出

- 有效GPU小时 = Σ[实际满足业务SLO的GPU占用小时]，剔除停机、无效作业和空转；不能仅以72GPU×8760小时当作实际产出。
- 单位有效GPU小时TCO = 全五年总拥有成本 / 五年有效GPU小时。
- 单位百万Token成本 = 同口径可归集TCO / 达到约定质量和SLO的有效Token数量 ×10^6。
- 上述指标必须对模型版本、精度、KV Cache、调度利用率、吞吐、完成率及RPO/RTO要求归一化。

## 6. 敏感性/风险情景

至少设计：基准、上电延迟12个月、有效负载下降、涨价/需量费增加、冷却异常、水资源限供、CDU整机故障、双运营商中断、退租/违约、GPU更新与残值变化。

延迟12个月只作假设情景，不暗示真实工程会延期12个月。计算应把利润/产出机会损失与现金流费用区分展示，不能把业务损失与服务信用重复冲销。

## 7. 数据依赖

尚无真实供应商报价、utility tariff、PUE、WUE、每区负荷曲线、资本成本、汇率和残值，**本阶段不输出任何真实总价或“某方案便宜X%”结论**。各项记录责任Owner、来源和确认日期。
