# G2-06.16｜跨区域自治与运营故障域

## 1. 站点资产所有权≠资源授权权威

自建/托管/Powered Shell三路线下，Site LCP仍是本地计算/存储/网络资源的调度与执行协调点。Reservation Authority、Lease Authority、PDP/PEP和设备/业务Owner保留各自授权与租约权威；ADS/GCP负责跨域语义治理、能力注册与审计，不直接拨动机电阀门或远程短接安全硬联锁。

托管运营商对其建筑与设施物理安全、供配电、电水/消防等动作拥有执行责任；IT Owner不得借Agent控制其未授权系统。

## 2. 操作层次

- L0人身、建筑、火灾、漏液与电气安全：现场硬联锁和依法授权的设施专业人员，紧急动作优先，不等待AI批准。
- L1设施运行：UPS、母线、PDU、CDU、泵、一次水源、进排水、冷机，由合同确定运营商/业主专业Owner。
- L2IT资产：GB300/N1380、存储、NIC/交换机、固件、BMC、OOB，由设备Owner与安全审批执行。
- L3任务与业务：调度、数据复制、Checkpoint、恢复、数据分类与AI服务，由业务和算力Owner执行。
- L4跨区域协同：ADS/RCP、任务契约、授权共享、区域状态同步与审计，不覆盖L0/L1/L2安全权威。

## 3. 必须检验的共同故障域

- 两托管机房看似不同运营商，但共用上游电网、同一CDU维保团队/备件、云端BMS、身份服务或WAN批发光缆。
- 单一区域机柜内双GPU Fabric并不等于设施双路供电/独立供液。
- C方案专属CDU仍可能依赖同一上游冷机或电网变压器。
- 两区域采用相同OEM/固件便于运维，但存在供应链召回、共性漏洞和停产风险。
- 跨国部署增加数据驻留、密钥、出口许可及跨境网络风险。
- 托管运营商故障报告/日志供应商断连可能使平台进入Unknown，应本地记录和限制高风险动作。

## 4. WAN分区与事故时序

1. **检测**：区域LCP检测WAN、设施接口异常并记录时间和签名证据。
2. **保护**：设施本地L0硬联锁执行必要物理保护；IT执行Checkpoint/降载/受控停机，不得越权操作机电。
3. **授权**：Lease/FencingToken、Owner epoch/sequence与region epoch分别管理；Unknown不当作成功，撤销缺口时高风险Fail-Closed。
4. **恢复**：联系原Owner对账、核验撤销/电源/水质/链路/存储一致性。
5. **验收**：由运营商与业主各签其责任边界的修复证据；独立见证合格后恢复高风险工作负载。

## 5. 业主与运营商信息接口建议

按“最小可必要”的状态交换：站点供电质量/负荷、CDU温流压和警报、介质状态、管网/冷机维护、门禁异常、光路故障、变更工单、事件时间线及签署回执。高风险远程控制接口不应直接公开给跨区域Agent；如果确需设施自动化，应先有独立风控、授权、限权、本地联锁、审计和回滚测试。

## 6. 双区域组合原则

A+A、C+C、A+C、B+C和B+A均可进入架构评估，但不能因双方形式不同就认为故障独立。按G2-06.13组合100分与No-Go门槛审查，再按RPO/RTO和数据驻留确定复制、热/温备、调度降级策略。
