# G2-06.21｜双区域十星工程容量平衡与候选设备配置优化

- 版本：RC0 / Proposed
- 日期：2026-11-14
- 前置阶段：G2-06.19容量定量模型；G2-06.20业主输入与容量缺口治理
- 性质：架构研究、候选设备比较、容量算术复核与工程验收策划；不是采购批准、施工图、并网许可或投运验收。

## 本阶段目标
把G2-06.19的变量/公式和G2-06.20的Owner/证据/签署机制，推进到具体候选平台、准确整机型号、资源配置、机柜热工、电力与网络约束，并形成可审计的设备决策包。

## 核心结论
1. GPU路线更新：NVIDIA Vera Rubin NVL72纳入主参考候选；AMD Helios MI455X纳入异构替代候选；GB300 NVL72保留为过渡/兼容对照。三者不能混成一套BOM。
2. NVIDIA路线有Lenovo 7DJVCTO4WW机柜级产品指南，公开给出72 Rubin GPU、36 Vera CPU、227kW MaxP/187kW MaxQ机柜TDP、96%液冷/4%风冷及4×110kW Power Shelf。
3. AMD Helios已出现首批客户机柜部署并开始MI455X批量出货，但Helios是开放参考设计，具体OEM订货SKU、整柜功率/热工和站点工程边界仍需供应商回填。
4. Lenovo SC755 V5/N1380官方指南明确支持2N2S与4N1S；每个Tray四颗EPYC 9006 SP7 CPU。8-Tray N1380为32个CPU Socket；两种拓扑改变节点粒度，不改变CPU总Socket数。
5. 存储分层：Micron 9650 Gen6作为高性能/高耐久候选；KIOXIA LC9 245.76TB QLC作为容量/读密集层候选，不能默认承载高写入权威账本。
6. 所有容量、功耗和成本必须按同一计量边界比较；未知值保持TBD，不从芯片峰值推导整站MW、有效Token或TCO排名。

## 重要计算边界
- Vera Rubin NVL72的4×110kW Power Shelf合计440kW是电源输出能力，不是机柜实际功耗；227kW/187kW为Lenovo指南中的MaxP/MaxQ机柜TDP口径。
- 2N2S与4N1S每个SC755 V5 Tray均为4颗CPU；一个N1380包含8个Tray、32颗CPU。不能把节点数变化误认为CPU总量变化。
- LC9容量层每区19.6608PB为原始十进制容量；保护后可用容量必须按副本/纠删码、热备、元数据、快照、保留、重建空间和运行水位扣减。
- 两区域总容量不能自动视为单区域故障时的可接管容量；跨区镜像副本不能重复计为唯一逻辑数据。
- NVIDIA与AMD的FP4/FP8峰值、稀疏/稠密、Scale-up/Scale-out统计边界不一致，不可仅凭厂商峰值做采购排名。
