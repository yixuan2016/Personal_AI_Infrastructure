# V2.9-RC9.2-DM04 跨域交易接口与数据契约冻结候选基线

## 0. 状态与范围
本专题承接 RC1 六域 API、统一请求信封、事件/错误/幂等/重试与协议兼容基线，吸收 RC4 资源市场、SLO、计量结算设计，并把 DM02 的 FRI/ResourceBundle/DecisionTrace、DM03 的 ContractGraph/Amendment/ActivationBarrier/MeteringRecord/AcceptanceRecord/SettlementStatement/DisputeCase 映射到同一契约体系。

**本轮冻结的是候选语义，不是已部署端点。** 先冻结字段、权威、状态、幂等、错误和事件；REST/OpenAPI 是参考绑定。双方 Owner 签署且两套独立实现通过互操作后，才能升级为正式互操作基线。

## 1. 核心决策
1. 保留六个既有接口域：联邦治理、身份与授权、数据空间、算力星、联邦任务、证据与验收。
2. 不新建第二套 Lease Authority、全局授权引擎或全局事务管理器。
3. Offer 是供给声明；Quote 是任务绑定报价；Contract 是签署义务；Reservation/PrepareToken 是临时预留；Lease 是本地资源承诺；Grant 是数据用途授权；ActivationBarrier 是聚合检查；ExecutionReceipt 是执行回执；MeteringRecord 是原始计量；AcceptanceRecord 是独立验收；SettlementStatement 是结算结果。
4. SCO 维护 ContractGraph 关联和 Saga 协调视图，不成为远端 Owner 事实权威。各合同节点由相应签署方独立签署。
5. ActivationBarrier 通过不等于执行启动；本地 PEP、Lease、FencingToken、撤销水位、制品摘要和设施安全联锁必须再次检查。
6. 所有高风险写操作具备幂等键、状态版本、摘要、有效期和证据回执。超时且可能已产生副作用时进入 UNKNOWN，先查询权威状态。
7. 未知权限、未知动作、未知状态、影响授权/受众/目的/地域/资源边界的未知字段拒绝或隔离；非关键扩展可忽略但留痕。
8. 事实、预测、反事实、提案和决策分离；预测/反事实不得成为资源承诺、授权或最终计量。
9. 控制面 Permit 不替代数据平面访问凭证；数据移动、结果披露和资源执行分别由各权威方控制。
10. 版本独立管理：API、Schema、Ontology/Profile、ContractGraph、Policy/Grant、ResourceProfile、SLO、MeteringTerms。

## 2. 六域接口与权威边界
| 接口域 | 主要能力 | 权威主体 | ADS可做 | ADS不可做 |
|---|---|---|---|---|
| 联邦治理 | 成员、信任协议、Profile、退出 | 双方治理方 | 协调、记录批准结果 | 修改对方信任根、单方批准 |
| 身份与授权 | 工作负载身份、委托、本地策略 | 各站点IAM/PDP/PEP | 携带合法委托、查询状态 | 授予远端本地权限 |
| 数据空间 | 目录、数据合同、传输、用途 | 数据Owner/连接器 | 发现与协调 | 绕过数据合同和本地控制 |
| 算力星 | 能力、报价、预留、租约、证明 | 资源所在地Owner | 请求、比较、协调 | 代签Lease或承诺容量 |
| 联邦任务 | TaskContract、Plan、Prepare、Commit、Saga | SCO协调+站点执行方 | 全局协调视图 | 覆盖本地状态/执行事实 |
| 证据与验收 | Evidence、Result、Acceptance、Metering、Settlement | 各证据方/独立验收方/结算方 | 汇总引用、对账 | 自行验收、改写原始计量 |

### 2.1 API增量
既有逻辑操作优先复用。DM04仅增加：
- `ContractGraph.Validate/Publish/Get`
- `Contract.Amendment.Propose/Review/Sign/Activate`
- `Task.ActivationBarrier.Evaluate/Get`
- `Metering.Correction.Submit`
- `Settlement.Adjust`
- `Dispute.Respond/Evidence/Resolve/Appeal`
- `Transaction.Reconcile`

Offer/Quote、Prepare/Commit、Lease、Metering、Acceptance、Settlement既有操作继续使用，仅扩展Schema和版本绑定，不另建同义端点。

## 3. 统一请求/响应契约
RequestEnvelope必需：`request_id`、`correlation_id`、`caller_principal`、`workload_identity`、`audience`、`purpose`、`protocol_profile`、`issued_at`、`expires_at`。有副作用操作必需`idempotency_key`；状态变更必需`expected_state_version`；高风险操作必需`payload_digest`与`signature_ref`。

ResponseEnvelope至少包含`request_id`、`responder_site_id`、`object_ref`、`object_version`、`command_status`、`authoritative_state`、`event_cursor`、`evidence_refs`。`Accepted`只表示受理；`Pending`不表示成功；`Unknown`禁止盲目重放。

幂等作用域建议为`caller_principal + operation + resource/object + task_id`。同Key同载荷返回原结果/权威状态；同Key不同载荷返回`IDEMPOTENCY_CONFLICT`。幂等记录保留期不得短于最大任务生命周期和合同争议窗口，具体数值由双方确定。

时间采用UTC RFC3339；超时用单调时钟；序号只要求在单一权威聚合内单调递增，不假设全联邦全局时钟排序。

## 4. 核心对象字段与权威
- **TaskContract**：任务发起方/签署方权威；任务、版本、参与方、目的、范围、约束、交付物、数据/地域条款、SLO、预算、验收标准、有效期、摘要、签名。
- **FederatedOffer**：资源Owner权威；资源范围、数量/单位、可用窗口、成熟度、证据、TTL、撤销引用、签名。Offer不是容量承诺。
- **FederatedQuote**：报价Owner权威；绑定Offer和TaskContract，明确范围、数量、单位、币种、价格组件、税费、舍入、计量窗口、SLO、排除项、补救、取消费、有效期和签名。口径不可比则标记NonComparable。
- **ContractGraph**：SCO维护关联；每个ContractNode由相应Owner/签署方签名。DAG无环、节点责任完整、依赖闭合、交付物有生产方/接收方/用途/验收条件。版本不可覆盖。
- **Amendment**：绑定基准graph_version，列明变更集和影响分析。目的、数据、地域、模型、资源、价格、SLO、风险或接收方变化时，按影响重新授权/报价/Prepare。
- **ActivationBarrier**：SCO聚合检查；关键项Fail或Unknown不得激活。通过不等于执行启动。
- **LocalResourceLease**：唯一资源承诺由资源所在地Lease Authority签发；含Owner、Site、Task、资源、有效期、Lease Epoch、单调Fencing Token、条款摘要和签名。
- **MeteringRecord**：资源Owner签发；区分Measured、Estimated、Corrected、Disputed、Invalid。更正追加，不覆盖原始记录。
- **AcceptanceRecord**：独立业务验收方签发；绑定标准版本、结果和证据。Conditional必须列明例外、责任方、补救期限和结算影响。
- **SettlementStatement/DisputeCase**：每条结算行引用合同节点、Owner原始计量、适用验收和价格条款；争议只隔离争议行，不覆盖原始证据和历史结算。

## 5. 事件与错误
CloudEvents 1.0.2风格信封：`specversion/id/source/type/subject/time/datacontenttype/dataschema/data`；扩展`siteid/aggregateid/aggregateversion/sequence/correlationid/causationid/schema_version/signature_ref`。采用Outbox/Inbox、至少一次投递、幂等消费、乱序检测、event_cursor补拉；不承诺网络恰好一次投递。事件ID不是授权ID。未知事件不得触发副作用。

错误采用RFC 9457风格Problem Details，扩展`error_code/error_domain/retryable/safe_action/correlation_id/authoritative_site/evidence_ref`。401重新认证；403不得绕过；409/412先读权威状态；422修正契约；429遵循Retry-After；503仅幂等请求可退避；504/UNKNOWN先对账；签名错误隔离。

## 6. 版本兼容
- Major：改变权利/授权语义、必需字段、状态机、副作用或签名覆盖。
- Minor：新增可选字段、非破坏性操作或可选事件。
- Patch：不改变业务语义的澄清/修复。
- API、Schema、Ontology/Profile、Policy/Grant、ContractGraph独立版本；任务创建时固定引用，运行中不静默升级。
- 未知非关键扩展可忽略但留痕；未知关键字段、权限枚举拒绝；未知状态停止迁移；未知事件安全存档、不触发动作。
- RC1把OpenAPI 3.2.1列为优先候选但要求验证工具链；本包以OAS 3.1.1提供参考REST绑定，不能宣称3.2.1已通过验证。DSP只承担数据空间目录/合同/传输互操作，不替代算力租约、Agent委托和业务验收。

## 7. 跨域协议序列
身份互信/Profile → Offer发现 → TaskContract → Quote → ContractGraph校验/签署 → 多Owner Prepare → 本地策略复核 → Owner Commit/Lease → ActivationBarrier → 本地执行前再次授权 → 执行/回执 → 结果披露审查 → Metering → 独立Acceptance → Settlement → Dispute窗口/Close。

若写操作超时且可能已产生副作用：进入UNKNOWN → 查询远端Owner权威状态 → 对账事件水位/对象版本 → 确认成功/失败/部分成功 → Saga补偿或继续 → 记录证据。不得以超时推定失败，也不得以已受理推定成功。

## 8. 单星与双站点部署
单星本地闭环包括LCP、资源目录、调度器、Lease Authority、IAM、PDP/PEP、数据连接器、CPU/GPU运行时、Outbox/Inbox、计量和证据域。ADS/SCO可提供联邦协同，但不成为本地执行单点前提；断连时本地有效租约按本地策略运行，高风险新跨域授权按策略Fail-closed。

双站点A/B各自独立部署LCP、Lease Authority、Local PDP/PEP、调度器、资源目录、数据连接器、事件缓冲、计量和证据域，通过受控WAN共享ADS/SCO协调能力。验证身份互认、Offer/Quote、ContractGraph、Prepare/Commit/Lease、Barrier、本地PEP、执行、计量、验收、结算、撤销、网络分区、UNKNOWN、Saga和版本兼容。至少两套独立实现通过相同契约测试；同一代码库自测不算双实现。
