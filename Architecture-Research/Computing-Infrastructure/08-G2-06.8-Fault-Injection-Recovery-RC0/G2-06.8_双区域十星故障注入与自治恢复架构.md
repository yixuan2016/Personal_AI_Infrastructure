# G2-06.8｜双区域十星故障注入与自治恢复架构

**状态：** RC0 架构候选，待评审  
**验证拓扑：** 两个自治区域，每个区域五颗异构算力星  
**前置阶段：** G2-06.5 RCP、G2-06.6 跨区域协议、G2-06.7 十星容量与网络模型

## 1. 目标与验证问题

G2-06.8 验证系统在网络、控制面、计算、GPU、存储、数据授权、身份、时间和能源设施发生故障时，能否做到：

- 故障局部化，不把单星或单区域故障扩散为全局故障；
- 本地任务在明确授权和有效租约内安全自治；
- 未知状态不被误判为成功或失败，不产生重复资源承诺；
- 撤销、急停和设施联锁不被普通流量阻塞；
- 跨区域交易可对账、补偿、恢复并保留证据；
- 只有满足 Owner 事实、策略和独立验收条件后才恢复新交易。

本阶段不是追求“任何故障下都不中断”。设计目标是安全优先的可控降级、故障遏制、可证明恢复和责任可追溯。

## 2. 十星故障域模型

| 故障域 | 典型对象 | 主要风险 | 首要权威 |
|---|---|---|---|
| 全球治理域 | ADS/GCP、共同语义、信任与策略发布 | 全局目录或治理更新不可达 | ADS/Governance Owner |
| 全局交易域 | SCO、任务图、Saga Ledger | 跨区域交易状态不完整 | SCO Transaction Owner |
| 区域协调域 | RCP、区域目录、区域事件投影 | 区域协调不可用或双主 | RCP/Region Owner |
| 站点自治域 | LCP、站点调度、Lease Authority | 本地控制失效或状态不明 | Site Owner |
| 计算域 | CPU、内存、NUMA、主板、加速卡 | 作业失败、资源隔离失效 | Compute Owner |
| GPU 域 | GPU、显存、驱动、固件、Scale-up Fabric | GPU hang、ECC、互连降级 | GPU Owner |
| 存储域 | NVMe、对象存储、元数据、复制链路 | 数据不可用、写入不一致 | Storage/Data Owner |
| 网络域 | ToR、Spine、NIC、光模块、运营商与路由 | 分区、拥塞、路径漂移 | Network Owner |
| 数据治理域 | DataUseGrant、数据驻留、密钥、结果披露 | 未授权访问或撤销失效 | Data Owner / PDP/PEP |
| 能源设施域 | UPS、PDU、供电、制冷、消防和联锁 | 设备损坏与人身/设施安全风险 | Facility Owner |
| 时间与身份域 | NTP/PTP、证书、令牌、密钥和信任根 | 重放、过期判断错误、签名不可验证 | Identity/Security Owner |
| 事件证据域 | Event Log、快照、审计、计量与结算 | 缺口、乱序、证据丢失或争议 | 各事实 Owner / Audit Owner |

故障域边界必须通过物理拓扑、网络路径、供电、冷却、控制器和运营商依赖图验证，不能仅凭逻辑标签认定独立。

## 3. 故障影响分级

| 级别 | 定义 | 示例 | 默认处理 |
|---|---|---|---|
| F0 / Safety Critical | 可能造成人身、设施、数据主权或重大安全风险 | 消防/过温联锁、密钥泄露、未授权数据出域 | 本地安全动作优先；阻断相关交易；人工升级 |
| F1 / Critical | 影响权威状态、租约、撤销或跨域交易正确性 | Lease Authority 不可达、撤销水位缺口、RCP 双主 | Fail-Closed；冻结新交易；Owner 对账 |
| F2 / Degraded | 局部能力下降但可在边界内运行 | GPU 节点故障、链路拥塞、存储性能降级 | 隔离故障资源；按合同降级或迁移 |
| F3 / Advisory | 非关键性能或可观测性下降 | 非关键遥测延迟、预测指标缺失 | 降频、缓存或延迟处理 |

同一事件的等级由影响范围、可逆性、授权风险和潜在后果决定；不能只根据组件告警级别判断。

## 4. 故障遏制的五条边界

### 4.1 全球 ADS/GCP 故障

- 已签发且仍有效的本地策略可以按其明确授权范围继续使用。
- 区域和站点不得自行扩大策略、信任域、数据用途或离线权限。
- 高风险策略撤销无法确认新鲜度时，相关高风险操作暂停或 Fail-Closed。
- 全局共同语义或信任根变更期间，禁止静默采用未经验证的新版本。

### 4.2 SCO 故障

- 站点已提交任务由本地 LCP 按 Lease、本地策略、数据授权和设施条件自治。
- 新跨区域交易不因 SCO 缓存状态而被视为已 Commit。
- 恢复后从持久 Saga Ledger 与站点 Owner 回执重建投影。
- 未决交易标记 Unknown/RecoveryRequired，先对账再补偿或恢复。

### 4.3 RCP 故障

- RCP 可替换、可重建，不是站点本地执行的必需在线依赖。
- 区域目录失效时，不能把陈旧容量摘要用于新的硬承诺。
- RCP 领导者切换递增 region_epoch，并实施 coordinator fencing。
- region_epoch 不得修改 Site owner_epoch、Lease FencingToken 或已签发租约事实。

### 4.4 Site LCP / Owner 故障

- 站点硬件安全控制器和设施联锁优先于编排层。
- Lease Authority 不可达时，不能由 RCP/ADS 代签或续签。
- Commit 响应未知时查询原 Operation/Owner；不得换幂等键重新创建租约。
- 站点恢复后必须核验硬件状态、Owner epoch、租约、任务状态和事件游标。

### 4.5 数据、网络与设施故障

- 数据访问必须由 Data Owner 授权，并由目标站点 PEP 在访问时复核。
- 网络分区不能推导出数据授权继续有效；撤销水位过期时高风险访问暂停。
- 存储副本、Checkpoint 和模型制品必须按其完整性与版本规则恢复，不能只按“文件存在”判定可用。
- 设施联锁可以本地停止设备，不等待全局控制面审批；事后补充治理审计。

## 5. 自治恢复状态机

建议采用以下跨层状态：

**NORMAL → DEGRADED → ISOLATED → RECOVERING → RECONCILING → VALIDATING → RESUMED**

异常出口：

- **MANUAL_HOLD：** 需要人工批准或责任争议处理。
- **QUARANTINED：** 签名、Owner、数据完整性或资源状态无法证明，隔离对象。
- **ABORTED：** 交易经权威对账后确认终止，并完成必要补偿。

状态含义：

| 状态 | 进入条件 | 允许动作 | 禁止动作 |
|---|---|---|---|
| NORMAL | 关键依赖健康、授权与状态连续 | 正常发现、交易和执行 | 无 |
| DEGRADED | 非关键依赖异常或指标越界 | 已授权任务有限运行、限制新负载 | 扩大离线授权 |
| ISOLATED | 故障域被确认或权威状态未知 | 本地安全控制、隔离资源、停止新跨域 Commit | 未确认状态下激活 |
| RECOVERING | 故障源修复，尚未完成状态核验 | 恢复连接、拉取日志、准备快照 | 直接恢复新交易 |
| RECONCILING | 正在向原 Owner 查询权威事实 | 查询、补传、对账、补偿 | 从缓存推断 Commit/Release |
| VALIDATING | 状态已对齐，执行恢复前检查 | 策略、租约、数据、网络和设施复核 | 跳过独立验证 |
| RESUMED | 所有阶段门通过 | 在批准范围内恢复服务 | 自动扩大资源/权限 |
| MANUAL_HOLD | 需审批、争议或不可逆动作 | 人工审查和限定授权 | 自动绕过审批 |
| QUARANTINED | 完整性或权威无法证明 | 隔离、取证、修复 | 将可疑状态纳入生产 |
| ABORTED | Owner 确认交易终止且补偿闭环 | 关闭交易、保留审计 | 删除交易历史 |

## 6. 恢复必须满足的事实条件

恢复动作至少校验：

1. 故障源已修复，相关健康信号来自正确的 Owner。
2. region_epoch、owner_epoch 和 Lease FencingToken 的关系正确，旧代次被拒绝。
3. 原始 Operation、Prepare、Commit、Activate、Stop、Release 回执可查询。
4. 事件流连续，或已完成签名快照与增量事件补传。
5. Policy、Trust、Credential、Attestation 和 DataUseGrant 均在有效期内，撤销水位无未解释缺口。
6. GPU、存储、网络、能源和设施硬约束重新测量并满足任务合同。
7. Checkpoint、模型制品和数据副本通过完整性、版本和权限校验。
8. 未决 Saga 已推进到明确状态，或进入 MANUAL_HOLD/QUARANTINED。
9. 独立见证记录恢复前后关键状态，必要时由第二套实现复算。
10. 恢复范围、时间窗口、授权主体、回滚条件和责任 Owner 均已记录。

## 7. RTO / RPO 与撤销窗口的确定原则

本阶段不预设统一秒数或分钟数。不同对象的恢复目标应分开定义：

| 对象 | 恢复目标确定方式 | 最低正确性要求 |
|---|---|---|
| P0 撤销与设施联锁 | 由安全风险分析和设施/安全 Owner 确定 | 不得被普通流量阻塞；本地安全动作不依赖远端可达 |
| Lease / Commit 事实 | 由交易合同与站点 Owner 确定 | 已确认的权威事实不能被恢复过程覆盖或重复生成 |
| Saga Ledger | 由交易关键性与持久化机制确定 | 可重建所有未决交易及其因果链 |
| 数据与 Checkpoint | 由任务 RPO、Data Owner 与存储合同确定 | 只能恢复到通过完整性和授权验证的版本 |
| 目录与遥测 | 由发现效率和陈旧风险确定 | 陈旧状态必须标识，不能用于硬承诺 |
| 审计证据 | 由合规与责任要求确定 | 关键审批、授权、执行、撤销和补偿证据不可静默丢失 |

撤销最大陈旧窗口应按风险级别、网络分区最长可接受时间、令牌有效期和目标 PEP 能力确定。超过窗口或水位存在缺口时，高风险操作 Fail-Closed。

## 8. 故障组合与级联控制

必须验证单故障与组合故障。组合测试至少包括：

- WAN 分区 + RCP 主节点切换；
- 站点 Owner 不可达 + Commit 响应丢失；
- GPU 节点故障 + 存储 Checkpoint 退化；
- 撤销事件洪峰 + 普通遥测洪峰；
- 时钟漂移 + 过期令牌重放；
- 多运营商切换 + MTU/路由差异；
- 区域重启 + 事件缺口 + 快照陈旧；
- 能源限电 + 冷却告警 + 任务迁移；
- DataUseGrant 撤销 + 网络分区 + 缓存命中；
- 站点退出 + 未释放 Lease + 结算争议。

每次组合故障必须先证明单故障测试已通过，并设置明确的停止条件。不得一次性注入无法归因的多重故障。

## 9. 关键安全停止条件

出现以下任一情况，立即停止扩大测试规模并进入隔离/人工治理：

- 旧 FencingToken 被接受或出现无法解释的重复 Lease；
- 未授权数据出域、用途扩张或跨地域处理；
- P0 撤销或设施联锁被普通流量阻塞；
- Site Owner 权威事实被区域/全局投影覆盖；
- 事件签名、digest 或序列冲突无法解释；
- Checkpoint/数据副本完整性无法证明；
- 设施功率、温度、消防或人身安全阈值越界；
- 恢复流程在未完成 Owner 对账前重新激活任务；
- 关键证据丢失，导致审批、授权或责任链无法追溯。

## 10. 阶段结论

G2-06.8 的核心不是设计一个“自动重启”按钮，而是建立以 Owner 权威事实为基础的故障遏制与恢复体系。恢复必须经过故障修复、权威对账、撤销核验、资源复测、独立验证和分级放行。

当前结论为 RC0 候选；真实 RTO/RPO、撤销窗口、故障切换时间和十星可用性均待现场测量与 Owner 签署。
