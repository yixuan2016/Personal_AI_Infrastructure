# G2-06.8｜故障注入与恢复演练手册

**状态：** RC0 演练方案候选，待站点安全与运行 Owner 批准  
**用途：** 为双区域十星架构建立可重复、可停止、可追溯的故障注入流程  
**限制：** 本手册是架构级演练设计，不授权在生产环境直接执行任何故障注入

## 1. 演练治理原则

1. 所有演练必须先在隔离环境或明确批准的测试窗口执行。
2. 生产环境注入必须由站点、网络、数据、设施和安全 Owner 联合批准，并具备即时停止与回滚能力。
3. 每次只注入一个主故障变量；组合故障必须在单故障通过后开展。
4. 先定义预期状态、影响范围、停止条件和恢复步骤，再实施注入。
5. 任何 P0/F0 安全联锁、真实客户数据、密钥和未授权数据路径均不得作为未经批准的实验对象。
6. 失败结果必须保留，不得通过删除日志、重置游标或重建环境掩盖。
7. 演练人员、观察人员和独立见证人员应分离；注入者不能单独签署验收。

## 2. 标准演练流程

**阶段 A：准备**
- 选定区域、站点、资源和任务范围。
- 确认测试合同、DataUseGrant、租约、测试数据与网络边界。
- 记录初始 Owner epoch、region_epoch、sequence_no、Lease/FencingToken、事件游标和撤销水位。
- 确认健康基线、告警、监控、带外管理、停止按钮和恢复负责人。
- 记录预期影响、禁止影响和停止条件。

**阶段 B：基线**
- 执行无故障对照任务。
- 记录控制面 API 分位时延、队列、网络 RTT/抖动/丢包/有效吞吐、GPU/存储/设施状态。
- 保存原始 Owner 回执、事件和 Checkpoint 引用。

**阶段 C：注入**
- 按批准的故障场景注入。
- 使用唯一 test_run_id 和 scenario_id 关联所有记录。
- 不改变多个未声明变量；注入失败也要记录。

**阶段 D：观察与遏制**
- 观察故障是否限制在预期故障域。
- 验证本地自治、Fail-Closed、P0/P1 优先级和幂等保护。
- 触发停止条件时立即终止注入，优先保护人员、设施、数据和租约正确性。

**阶段 E：恢复**
- 修复故障源，但不立即恢复新交易。
- 进入 RECOVERING → RECONCILING → VALIDATING。
- 向原 Owner 查询权威事实，补齐事件缺口，核验撤销水位、租约、资源和数据完整性。
- 完成独立复核后才允许恢复。

**阶段 F：复盘**
- 比较预期与实际状态、影响范围、恢复耗时和证据。
- 记录偏差、根因、控制缺口、修复责任和回归测试。
- 未通过的项目保留 Failed/Blocked，不得通过改写验收标准标记通过。

## 3. 重点演练场景

### 场景 01｜双区域 WAN 分区

- **目的：** 验证区域间失联不会扩大站点权限或造成重复跨域交易。
- **注入：** 在隔离测试网络中切断 R1 与 R2 的控制面链路；数据面链路单独控制，不能默认同时断开。
- **预期：** 新跨区域 Commit/Barrier 暂停；已提交站点任务按本地有效 Lease、Policy、Grant 和设施约束运行或按合同暂停；区域目录标记 stale/unknown。
- **恢复：** 重连后先同步撤销水位、Owner epoch、Lease 摘要、事件游标和证据，再恢复新交易。
- **停止条件：** 出现未授权续租、旧 token 接受、未授权数据路径或本地安全联锁异常。

### 场景 02｜RCP 领导者切换与脑裂防护

- **目的：** 验证区域协调器单主与 fencing。
- **注入：** 在测试集群隔离当前 Leader 与部分节点，触发候选 Leader 选举。
- **预期：** region_epoch 按规则递增；旧 Leader 被 fencing；不会产生重复 Prepare/Commit 副作用；Site Lease FencingToken 不被区域切换改写。
- **恢复：** 重建区域投影，向 Owner 对账未决操作。
- **停止条件：** 双 Leader 同时签发有效区域命令或区域层伪造站点 Lease。

### 场景 03｜Site Owner 不可达且 Commit 响应丢失

- **目的：** 验证 Unknown 状态与幂等恢复。
- **注入：** 在目标站点 Lease Authority 完成/未完成 Commit 的不同窗口丢弃响应，并隔离调用方到 Owner 的链路。
- **预期：** 调用方标记 Unknown；保留原 Idempotency-Key；禁止创建第二笔 Lease。
- **恢复：** 链路恢复后查询原 Operation、Owner epoch、sequence 和 Lease 记录；按权威事实推进或补偿。
- **停止条件：** 出现重复 Lease、无法定位原 Operation 或协调层尝试代签。

### 场景 04｜GPU 节点故障与 Checkpoint 恢复

- **目的：** 验证 GPU 故障隔离和任务恢复。
- **注入：** 在专用测试节点通过受控故障模拟触发 GPU Xid/ECC/设备失联或驱动异常；不得在生产共享节点制造硬件风险。
- **预期：** GPU Owner 标记设备不可用；调度器不再分配该设备；任务仅从通过校验且授权有效的 Checkpoint 恢复。
- **恢复：** 设备健康、驱动/固件、显存和互连诊断通过后，由 GPU Owner 解除隔离。
- **停止条件：** 设备异常扩散、数据完整性不明或设施告警触发。

### 场景 05｜存储路径退化与副本不一致

- **目的：** 验证存储故障不会产生静默数据损坏。
- **注入：** 在测试存储环境模拟路径中断、延迟、只读、副本滞后和校验失败。
- **预期：** 受影响数据标记不可用或降级；不以“文件存在”判定 Checkpoint 有效；不将未验证副本提升为权威版本。
- **恢复：** 由 Storage/Data Owner 执行一致性、版本、摘要和授权核验。
- **停止条件：** 写入确认与实际持久化状态冲突、摘要不一致或副本权威不明。

### 场景 06｜DataUseGrant 撤销叠加网络分区

- **目的：** 验证撤销水位与本地 PEP 的安全行为。
- **注入：** 测试环境中撤销指定 DataUseGrant，同时延迟/阻断区域撤销事件传播。
- **预期：** 在授权新鲜度超出批准窗口或出现撤销缺口时，高风险访问 Fail-Closed；不因缓存命中而继续访问。
- **恢复：** 向 Data Owner 查询撤销事实，刷新策略和水位；只有重新授权后才能恢复。
- **停止条件：** 任一未授权读取、训练或结果披露。

### 场景 07｜时钟漂移与过期令牌重放

- **目的：** 验证时间偏差不会绕过有效期和重放控制。
- **注入：** 在隔离环境对测试节点施加受控时钟偏差，并重放已过期测试请求。
- **预期：** 系统检测时钟偏差；高风险命令按 Profile 拒绝或转人工；重放不产生副作用。
- **恢复：** 恢复可信时间源，重新验证证书、令牌、签名和事件时间语义。
- **停止条件：** 过期凭证被接受或时间回拨导致 Owner 顺序倒退。

### 场景 08｜事件缺口、乱序与陈旧快照

- **目的：** 验证 Owner/epoch/sequence 与快照修复。
- **注入：** 丢弃一个测试事件、重复投递、乱序投递，并提供低于撤销水位的快照。
- **预期：** 消费者检测 gap，暂停受影响投影；拒绝陈旧快照；请求原 Owner 补传。
- **恢复：** 校验签名、digest、epoch、sequence 和撤销水位后重放。
- **停止条件：** 系统静默跳过事件或使用低水位快照恢复高风险交易。

### 场景 09｜能源/冷却告警与站点安全停机

- **目的：** 验证设施联锁高于调度和任务连续性。
- **注入：** 仅通过设施仿真或厂商批准的测试接口模拟供电/温度/冷却告警，不得实际触发危险物理条件。
- **预期：** 设施 Owner/联锁按批准策略降载或停止；站点上报事实；全局编排不阻止本地安全动作。
- **恢复：** 设施 Owner 签署安全恢复，资源重新测量并逐步放行。
- **停止条件：** 真实温度、供电、消防或人员安全阈值接近/越界。

### 场景 10｜多运营商切换与路由/MTU 差异

- **目的：** 验证路径冗余是真实故障域独立，并检查控制面与数据面 QoS。
- **注入：** 在批准的测试路径中断开一条承载路径或改变测试 MTU/路由策略。
- **预期：** 路由切换可观测；控制面关键队列保持可用；数据面吞吐下降被准确识别，不误报为 GPU 算力不足。
- **恢复：** 由 Network Owner 确认路由收敛、路径独立性、MTU、丢包和 QoS。
- **停止条件：** P0/P1 控制流被数据面拥塞阻塞，或出现非预期跨域路径。

## 4. 组合故障顺序

仅在相关单故障通过后逐步执行：

1. WAN 分区 + RCP Leader 切换。
2. Commit 响应丢失 + Site Owner 暂时不可达。
3. GPU 故障 + Checkpoint 存储降级。
4. DataUseGrant 撤销 + 撤销事件延迟。
5. 事件缺口 + RCP 重启 + Owner epoch 变化。
6. 多运营商切换 + 控制面 P0 撤销洪峰。
7. 能源降载 + 任务迁移 + 区域目录陈旧。

每个组合场景必须定义注入先后顺序、恢复顺序、状态依赖和停止条件，禁止无序叠加。

## 5. 演练记录最小字段

每次演练至少记录：

- test_run_id、scenario_id、环境、区域和站点范围；
- 参与者、注入者、观察者、独立见证者与批准人；
- 测试合同、软件/配置/本体/Schema 版本；
- 初始 region_epoch、owner_epoch、sequence_no、Lease/FencingToken 和撤销水位；
- 注入时间、故障持续时间、注入方式和实际影响；
- 预期状态、观察状态、停止条件触发情况；
- 恢复步骤、Owner 对账结果、事件缺口与快照引用；
- RTO/RPO 观测值及统计口径；
- 证据引用、摘要、签名和保留位置；
- 通过/失败/阻断结论、偏差、责任人和复测计划。

## 6. 结束条件

演练结束不等于系统恢复。只有故障源修复、Owner 对账、撤销与授权复核、资源/设施检查、证据归档和独立验收完成后，才能将场景标记为 Passed。否则保持 Failed、Blocked、Manual Hold 或 Quarantined。
