# G1 勘误与契约基线校正

**日期：** 2026-11-10  
**状态：** G2 正式采用的修订说明  
**范围：** 仅校正 G1 对 DM04 IFC0.2 与 ADS/SCO OpenAPI 请求信封的解释，不改变已确认的六域权威边界。

## 1. 必须撤回的 G1 表述

G1 报告曾建议在 IFC0.2 中把 `caller_principal`、`workload_identity`、`audience`、`purpose`、`protocol_profile` 等作为顶层必需字段补入请求体。该建议与既有 G0 治理决策不一致，现予撤回。

G0 已明确：IFC0.2 仅提出可选 `profile_extensions` 增量，不改变 IFC0.1 已有必需字段；未获双方 API Owner、Security Owner 与 AEE/ASCP Profile Owner 签署前不得发送。AEE/ASCP V1.1-RC0 同样采用此兼容原则。

## 2. 重新核对 OpenAPI 源文件后的事实

| 核查项 | ADS OpenAPI RC0 | SCO OpenAPI RC0 | 结论 |
|---|---:|---:|---|
| `RequestEnvelope` Schema 必需字段 | 6 | 6 | 两份文件一致 |
| `RequestEnvelope` 被 Path 引用次数 | 0 | 0 | 当前是未绑定组件 |
| `GenericCommand` 被 Path 引用次数 | 24 | 22 | 当前实际请求体主要使用该组件 |
| `GenericCommand` 必需字段 | 5 | 5 | `payload` 未列为必需 |
| `RequestEnvelope` 必需字段 | 6 | 6 | 包含必需 `payload` |
| OpenAPI 文档版本 | 3.2.1 | 3.2.1 | 候选文件，工具链尚未验证 |

`RequestEnvelope` 与 `GenericCommand` 目前不是同一个 Schema：前者要求 `payload`，后者不要求；两者的身份、用途、Audience、Profile 等字段也没有形成完整、可执行的绑定。OpenAPI 3.2.1 与 DM04 参考 REST 绑定中的 OpenAPI 3.1.1 也存在版本选择待决项。

## 3. 修正后的结论

1. DM04 IFC0.1 的逻辑 RequestEnvelope 与 REST 请求体不是同一层。不得仅凭 REST body 没有身份字段，就推断逻辑契约要求将这些字段全部加入 JSON body。
2. `caller_principal`、`workload_identity` 与 `audience` 应由目标服务从经过验证的 OAuth2 / mTLS 身份上下文中形成权威绑定；请求体中的 `caller_workload_id` 只能作为声明性提示，不能作为身份凭证。
3. `purpose` 必须来自明确的操作上下文、TaskContract、DataSpaceContract 或 DataUseGrant，并由本地 PDP/PEP 校验；`reason` 不是 `purpose` 的替代品。
4. `protocol_profile` 必须来自双方明确协商并登记的 Profile；不得从 `api_version` 或 `schema_version` 推断。
5. `expires_at` 可复用现有可选字段，但联邦请求必须按 DM04 规则校验有效期；缺失时不得静默延长。
6. IFC0.2 只增加可选 `profile_extensions`。它不得覆盖主体、工作负载身份、Audience、Purpose、过期时间、幂等键或状态版本。
7. `GenericCommand` 与 `RequestEnvelope` 的引用/绑定问题属于 ADS/SCO REST Binding RC1 的契约整理事项，不应借 IFC0.2 偷偷进行破坏性重构。

## 4. 对 G1 交付物的处理

G1 的六对象语义映射、Ontology 缺口清单、A2A/CloudEvents/FWSX 分层和 66 项验收矩阵继续有效。G1 中有关“IFC0.2 顶层新增身份与安全字段”的建议不再作为基线；以本勘误和 G2-02 ADR 为准。

## 5. 放行规则

在 G0/G1/G2 尚未完成双方签署之前：
- IFC0.1 继续作为兼容候选基线；
- 不发送未经双方批准的 `profile_extensions`；
- 不把未验证的 body 字段、token claim 或 URL 推断当作权威身份/用途；
- 需要 AEE/ASCP 扩展才能安全执行的跨站点动作，若对端未声明支持，则暂停该动作。
