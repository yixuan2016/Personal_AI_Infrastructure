# G2-06.11｜双区域十星网络分层与拓扑设计

**状态：** RC0 候选；网络 Owner/OEM 待审  
**设计对象：** Region A 与 Region B；每区一套 GB300 NVL72 主参考 rack  
**目标：** GPU 训练高带宽、网络故障域隔离、存储吞吐保障、管理面独立和跨区域可控互联。

## 1. 架构结论

网络必须按业务流量与故障域拆分，不以“全网 800G”作为架构目标。

| 网络平面 | 主要连接对象 | 主要流量 | 隔离方式 |
|---|---|---|---|
| GPU Fabric Plane A | NVL72 Compute Tray ↔ A 平面交换机 | GPU Collective / RDMA East-West | 独立物理交换平面 |
| GPU Fabric Plane B | NVL72 Compute Tray ↔ B 平面交换机 | GPU Collective / RDMA East-West | 独立物理交换平面 |
| CPU Converged / North-South | CPU/HPC、GPU DPU、控制服务、用户入口 | 节点通信、服务访问、数据进出 | 独立交换机对；必要时 VRF/VLAN |
| Storage Fabric | R7725xd、NVMe/对象/文件存储、GPU/CPU 客户端 | Checkpoint、训练数据、模型权重、持久化 | 独立物理交换机对或独立高性能端口组 |
| Customer / WAN | 双运营商边界、跨区域网关、用户/企业网络 | API、数据复制、管理控制、业务流量 | 双边界路由/防火墙、加密、路由策略 |
| Control / Support | R9815、部署、监控、目录、审计 | Provisioning、调度、日志、遥测 | 独立控制网络/受控 VRF |
| OOB / Facility | BMC、Redfish、PDU、CDU、传感器、交换机管理口 | 带外管理、设施遥测、紧急控制 | 物理独立管理网；禁止租户直达 |

NVIDIA NVL72 Enterprise RA 采用 GPU East-West、CPU North-South 和 OOB 三类物理 Fabric；其逻辑架构另区分 Storage、Customer 与 Support Server 角色。该参考架构明确 GPU Compute Fabric 不推荐承载 Storage 流量。当前十星方案进一步将 Storage 和 WAN 边界单独列为平面，属于本项目的隔离强化方案。

## 2. GPU Fabric 主参考：双平面 Spectrum-6 Ethernet / RoCE

**候选设备：** NVIDIA Spectrum-6 SN6600，每区域 2 台；Plane-A、Plane-B 各 1 台。  
**规格：** 每台 128×800Gb/s OSFP，交换容量 102.4Tb/s；典型功耗按 FRO 约 3.94kW、TRO 约 3.2kW，具体随光模块形态变化。SN6600-LD 是另一种液冷变体，规格不可与风冷 SN6600 混写。

### 2.1 单 rack 起步拓扑

- 每区一套 NVL72 rack。
- GPU Fabric A 与 GPU Fabric B 各使用独立交换机、独立上电回路、独立线缆路径和独立配置版本。
- HPE QuickSpecs：每个 compute tray 有 2 个 ConnectX-8 IO modules；每个 IO board 有 2 个 OSFP 物理接口。18 个 tray 合计 72 个 rack-side OSFP 物理接口。
- 初始布线假设：每 tray 2 个物理接口进入 Plane-A，另 2 个进入 Plane-B；每平面 36 个 rack-side 接口。必须以 HPE/NVIDIA 端口映射、NIC port mode 与实际线缆 QVL 为准。
- 交换机每平面端口预算至少覆盖 36 个 rack-side 连接，并另行预留上联、扩展、维护和测试端口。实际上联数和速率根据无阻塞目标及多 rack 规模计算。
- 两个平面不做跨平面 MLAG/堆叠/普通 LAG 合并。主机端 NCCL/通信库依据 rail-aware 拓扑处理负载均衡和失效隔离。
- 单平面失效时，作业可退化至另一平面；是否继续、降速、暂停或 checkpoint 由作业策略与实测决定，不承诺无感切换。

### 2.2 RoCE 必须端到端设计

RoCE 不是“以太网端口启用 RDMA”就完成。必须统一：
- NIC 与交换机固件/驱动/ NOS 版本。
- MTU、DSCP/PCP、优先级与队列映射。
- ECN 标记阈值、拥塞反馈、PFC 优先级与缓冲区。
- CNP 处理、流量整形、ETS/QoS、拥塞隔离。
- 端点、交换机、路由路径一致性。
- 多租户隔离、反压风暴检测、拥塞遥测与故障回滚。

NVIDIA Cumulus 文档分别定义 lossless（PFC+ECN）与 lossy（ECN）模式；本项目不得把“必须全网无损”当作默认唯一答案。应以 GPU 集群参考配置和端到端基准测试确定模式，严禁自行拼接不同 ASIC/ NOS 的阈值。

## 3. GPU Fabric 备选：双平面 Quantum-X800 InfiniBand

**候选设备：** NVIDIA Quantum-X800 Q3400-RA，每区域 2 台；每平面一台。  
**规格：** 144×800Gb/s ports，72 个 OSFP cages，115.2Tb/s；4U。典型功耗约 2.9kW（passive cables），active cable 最大约 7kW。

适用条件：
- GPU/HPC 训练为主要负载；
- 团队具备 InfiniBand fabric、UFM、Subnet Manager、线缆和故障排查能力；
- 需要与现有 IB 训练集群、调度与存储环境兼容；
- 运维团队能够承担独立 Fabric 管理栈。

约束：
- Q3400-RA 是交流供电、风冷机型；Q3401-RD 是直流母线供电版本；Q3450-LD 为液冷/CPO 连接器形态，三者不可混淆。
- IB Fabric 与 Ethernet Storage/Customer/WAN 网络仍须通过明确的边界网关或主机协议栈交互。
- 不跨 Region A/B 把两区 IB Fabric 默认合并成一个训练域；跨区作业须独立评估时延、路由、故障恢复和同步成本。

## 4. 双路线决策比较

| 维度 | Spectrum-6 Ethernet/RoCE | Quantum-X800 InfiniBand |
|---|---|---|
| 主要优势 | 与以太网运维、EVPN/VRF、多租户和企业网络集成更自然 | HPC/AI 专用网络栈成熟，训练集群常见 |
| 运维复杂点 | ECN/PFC、拥塞控制、buffer、端到端 QoS | UFM、Subnet Manager、IB 路由、专用运维技能 |
| 适用场景 | 多租户 AI 工厂、混合业务、跨系统服务互联 | 大规模训练/HPC、已有 IB 能力与资产 |
| 隔离方式 | 双物理平面 + QoS/VRF + 独立管理 | 双物理平面 + IB fabric 管理域 |
| 与 Storage | 另设 Storage Fabric；不得默认复用 GPU E-W | 另设 Ethernet/IB Storage 网络；按存储协议验证 |
| 本项目建议 | 主参考路线 | 条件性替代路线 |

**建议决策：** 当前以 Spectrum-6 Ethernet/RoCE 双平面作为主参考设计，Quantum-X800 保留为独立替代方案。只有在训练性能基准、团队能力、现有 IB 资产和 TCO 评估支持时，才切换为 IB。该建议不是对两种技术的普遍排名。

## 5. CPU North-South 与 Storage Fabric

### CPU Converged / North-South
- 连接 CPU/HPC 节点、GPU rack 的 BlueField DPU、控制/支持节点和用户入口。
- NVIDIA NVL72 RA 参考采用节点两条 400Gb/s 链路分别连接两台不同交换机，形成冗余路径；本项目将该做法作为 GPU rack 的 North-South 参考，而非强制所有 CPU 节点均 400G。
- HPE QuickSpecs 列出机柜内置 2 台 SN2201_M Top-of-Rack Switch，属于 1/100GbE 设备；其确切端口角色、VLAN 和外联关系须由 HPE 交付端口图确认。不能把 SN2201 当作 800G GPU Fabric。
- CPU/HPC 节点的 25GbE 管理/业务接口与高性能数据接口分离。

### Storage Fabric
- R7725xd 容量存储节点双归属接入 Storage Switch-A/B。
- 存储前端可按 NFS/对象/S3、并行文件系统、NVMe-oF 或其他协议分别配置端口和 QoS；协议未冻结前不锁定 NIC 型号。
- 热层/事务日志/元数据与 QLC 容量层分开；GPU Checkpoint 大流量不能挤占 OOB、控制或 WAN。
- GPU 训练数据与 Checkpoint 流量优先使用 Storage Fabric，不将 GPU Collective 与存储复制混在同一无隔离队列。

## 6. WAN 与双区域互联

- 每区域至少双边界路由/安全设备，接入两条物理路径尽可能独立的运营商线路。
- 运营商多样性不仅是两个合同，必须验证不同管道、入楼路径、机房 Meet-Me Room、光缆路由和上游自治系统。
- 跨区域默认承载控制面协调、元数据/对象复制、模型/数据分发、审计证据与业务请求。
- GPU AllReduce、NCCL collective、同步训练不默认跨 WAN；必须通过 RTT、抖动、丢包、带宽、恢复语义和训练效率实测后单独批准。
- WAN 失联后，两区域的本地 Owner/Lease/授权/设施控制保持本地权威；跨区状态标记 Unknown/Degraded，禁止把超时解释为成功或自动扩大权限。

## 7. 端口与线缆预算口径

- HPE NVL72 每 rack 72 个 tray-side OSFP 物理接口（基于 18 trays × 2 ConnectX-8 IO modules × 2 OSFP/IO module）。
- 双平面均分假设：每 plane 36 条 rack-side 物理链路；每条链路对端需要一只交换机侧物理接口。
- 若 72 条链路全部使用双端可插拔光模块，理论需 144 只光模块；DAC/AOC/Breakout 形态会改变模块数量与料号。
- 光模块类型（SR8/DR8/FR4/其他）、单模/多模、连接器、波长、FEC、链路距离、功耗和温度范围按实际机房布线与 OEM QVL 选择。
- 不得只根据“800G”字样下单；必须校验 NIC cage、switch cage、模块 vendor code、FEC、lane mapping、线缆极性、端面清洁和链路长度。
- 每条线缆两端都记录设备资产 ID、端口 ID、平面、机柜 U 位、线缆标签、长度、类型和光模块序列号。

## 8. HPE 内置 ToR 的边界说明

HPE GB300 NVL72 QuickSpecs 同时列出 2 台 SN2201_M Top-of-Rack Switch、每个 tray 的 ConnectX-8、BlueField-3 和管理口。SN2201 为 1/100GbE ToR，不能与 SN6600/Q3400 的 800G GPU Fabric 混为一谈。最终须由 HPE 交付完整的：
- NIC 到 ToR/外部交换机的物理连接表；
- 每个 ConnectX-8 IO module 的 port mode；
- BlueField-3 North-South 连接表；
- SN2201 的角色、上联、冗余与管理平面映射。

## 10. 待验证事项

1. HPE 最终端口 breakout、NIC mode、NCCL rail map 和 72 个 OSFP 的准确链路速率。
2. SN6600 NOS/ASIC 版本与 HPE/NVIDIA ConnectX-8 组合 QVL。
3. 每 plane 的上联需求、无阻塞目标、oversubscription ratio 和未来 rack 扩展规模。
4. 800G 光模块与 AOC/DAC 型号、长度、FEC、功耗和光预算。
5. CPU/Storage Fabric 交换机型号、端口数、NIC SKU 和存储协议。
6. 两家运营商物理路径独立性、线路 SLA、RTT/抖动/丢包和切换测试。
7. 双平面单故障、单交换机维护、光链路失效和拥塞场景下的训练性能退化曲线。
