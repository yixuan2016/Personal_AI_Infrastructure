# G2-06.11｜液冷 P&ID 与监测联锁设计

**状态：** RC0 参考设计；正式 P&ID、管径、阀门和控制逻辑由设施工程师与 OEM 共同冻结。  
**范围：** GB300 NVL72 液冷机柜、Lenovo N1380 Neptune CPU/HPC enclosure、区域设施一次水系统。

## 1. 总体原则

采用一次/二次侧隔离的液冷架构：
- 一次侧：站点设施冷却水/温水系统，负责把热量输送至冷机、干冷器或其他散热设施。
- CDU：液-液换热、泵送、过滤、温度/压力/流量控制和遥测。
- 二次侧：按 OEM 指定介质、材料、水质、温度、压力、流量和快速接头连接设备冷板/Manifold。
- 设备侧：GPU/CPU 冷板、管路、快接、回水歧管、漏液托盘和局部隔离。

一次侧与二次侧不得混液。HPE GB300 NVL72 的 XDU1350 回路与 Lenovo N1380 Neptune 的设备水路不默认共用同一二次液体；可否接入同一设施一次侧，需要热工、水质、压力和材料兼容评审。

## 2. HPE GB300 NVL72 + XDU1350

HPE QuickSpecs 给出 XDU1350 为液-液换热 CDU，额定冷量 1.3MW，厂商说明最多支持 8 个 GB300 NVL72 rack。HPE 支持二次侧顶部或地板下供液，并提供不同一次/二次侧方向的 SKU。

本项目每区域一套 NVL72 rack，按一台 XDU1350 作为容量参考，不把该配置自动视为满足高可用：
- XDU1350 内部三泵设计可按厂商运行模式提供泵冗余；Vertiv Guide Specifications 描述 twin-pump run/standby 的 N+1 泵能力。
- 泵 N+1 不等于 CDU 整机 N+1；换热器、控制器、配电、一次水阀门或 CDU 本体故障仍可能造成整机冷却中断。
- 可选冗余模式：一台 CDU + 关键备件/快速更换（成本较低，存在整机单点）；两台独立 100% CDU 1+1（成本高，需设计自动切换与水力平衡）；多 rack 场景按 N+1 模块化 CDU 组设计。
- 本阶段建议按“单 CDU 容量基线 + 独立整机冗余决策”记录，不把 1.3MW 冷量简单换算成八台机柜的现场可用容量。

### 2.1 P&ID 主流程

一次侧：
设施供水总管 → 隔离阀 → 过滤器/压差计 → 流量计 → CDU 一次侧入口 → 板式换热器 → CDU 一次侧出口 → 隔离阀 → 设施回水总管。

二次侧：
CDU 二次侧泵组 → 过滤器 → 供液温度/压力/流量测点 → 供液歧管 → NVL72 Rack Manifold → GPU/CPU 冷板 → 回液歧管 → 回液温度/压力测点 → CDU 二次侧回水。

必备部件：
- 供回水隔离阀、止回阀、排气阀、排水阀、压力释放阀；
- 过滤器及过滤器差压监测；
- 温度、压力、差压和流量传感器；
- 快速接头、盲板/维护接口、滴漏盘和漏液绳；
- 泵组运行反馈、阀位反馈、CDU 控制器和本地急停；
- 自动漏液隔离阀需与漏液检测硬接线/本地控制联动，按 OEM 与设施安全评审确认。

## 3. XDU1350 工程关注点

Vertiv XDU1350 Guide/Planning 文档中可核对：
- Primary (facility) 与 Secondary (IT) 两个独立回路；
- 三泵配置；双泵运行/备用模式为 N+1 泵策略，三泵同时运行可提高最大流量；
- 流量计、差压传感器、泵状态、过滤器差压、供回液温度与压力等遥测点；
- 过滤器精度、冷却液兼容性、管材、阀门、绝热和凝露控制要求须按最终型号与订单核对；
- 设施一次侧最低过滤要求、最大工作压力和具体管路尺寸以对应版本安装手册为准，不将不同版本数据混用；
- 漏液检测建议接入自动关闭现场供回水隔离阀。

不要将 XDU1350 的最大泵流量直接当成 NVL72 rack 的需求流量；必须以 OEM 机柜热负载曲线、冷板压降、Manifold 压降、目标供回液温差和 CDU 工作点确定。

## 4. Lenovo N1380 Neptune 回路

- N1380 使用直接水冷，热量在 CPU/设备热源处被带走。
- Lenovo 数据表给出经处理的清洁水，进水温度从露点以上到最高 45°C 的支持边界；具体条件以 SC755 V5/N1380 产品指南和保修要求为准。
- 服务器 tray 通过盲插快速接头接入 enclosure manifold。
- Enclosure 有独立进水与回水接口，并采用双联锁 FD83 球阀。
- N1380 的 PCS 与服务器液冷回路按 Lenovo 的水质/流量/压降要求设计。
- 不能将 HPE XDU1350 的二次侧水质/压力设定复制给 Lenovo Neptune；两种设备各自形成二次回路和参数基线。

## 5. 监测点与数据契约

| 监测域 | 关键点 | 用途 |
|---|---|---|
| 一次侧 | 供/回水温度、入口/出口压力、流量、过滤差压 | 设施冷源与换热能力 |
| 二次侧 | 供/回水温度、压力、差压、流量、温度设定值 | IT 冷却条件 |
| CDU | 泵运行/故障/转速、阀位、控制器状态、换热负载 | CDU 健康与冗余 |
| 过滤 | 过滤器入口压力、出口压力、差压、告警 | 堵塞和维护 |
| 环境 | 温度、相对湿度、露点、机柜进风温度 | 凝露风险与空气冷却补充 |
| 漏液 | 机柜底盘、Manifold、快接、地板下/上方漏液检测 | 本地隔离与安全响应 |
| 设备 | GPU/CPU 温度、热降频、功耗、冷板告警 | 计算节点健康 |

每条遥测至少包括 asset_id、sensor_id、timestamp、value、unit、quality、calibration_state、source_system 和 event_id。超阈值告警应保留原始测量和采样窗口，禁止只保存最终告警文本。

## 6. 本地联锁与平台协同

### 设施/设备本地硬联锁
- 漏液：本地检测 → 本地声光告警 → 关闭受影响支路供/回液隔离阀（具体动作按 OEM 安全策略）→ 保持其他独立支路运行 → 记录阀位反馈。
- 低流量/泵故障：启动冗余泵或备用 CDU；若恢复失败，发出设备保护告警并按 OEM 降载/关机流程执行。
- 高供液温度/高回液温度：先确认传感器质量和流量，再按本地策略降载/暂停 GPU 工作负载，保护温度由 OEM 设定。
- 压力过高/过低：本地保护与压力释放装置动作，禁止依赖云端审批。
- 断电/控制器失联：阀门进入经风险评审确定的安全位置；不能假设所有阀门都应失电关闭，须按液路失效后果设计。
- 露点/凝露风险：本地调节供液温度和环境条件，不允许平台调度覆盖设备安全限值。

### 平台层协同
- Facility Telemetry 事件进入区域监控与审计系统。
- RCP 可基于已验证的冷却可用容量降低资源承诺或将星位标记 Degraded。
- 调度器对 GPU 作业执行 drain/checkpoint/requeue；ADS/RCP 不直接控制阀门、泵速、断路器或急停。
- 设施恢复后，必须由本地控制器/OEM 诊断、网络/设备健康检查和 Owner 确认后再恢复资源租约与调度。
- WAN 失联时，设施安全控制完全本地自治。

## 7. 冗余与维护策略

1. 设施一次侧供回水总管设置可隔离支路，维护单一 CDU 不导致整个区域所有设备停冷。
2. CDU 泵组 N+1 与 CDU 整机冗余分别评审。
3. 关键阀门、传感器、控制电源和监控网络考虑故障安全状态。
4. 供回水管路设置排气、排水、取样、冲洗和维护接口。
5. 机柜快接维护由受训 OEM 人员执行；维护前执行断电/隔离/泄压/排液/防护。
6. 每次维护记录液体批次、水质检测、过滤器更换、阀门动作、流量/压差基线和回归测试。
7. 漏液检测必须覆盖机柜底部、Manifold、快速接头、CDU 周边和地板下/上方可能积液位置。

## 8. 液冷验收门禁

- 一次/二次侧水路冲洗、压力试验、清洁度和水质报告通过。
- 供回液方向、管径、阀门、过滤器、快接和材料兼容性由 OEM 签署。
- 额定/峰值热负载下流量、压差、供回液温度和 CDU duty 满足 OEM 曲线。
- 单泵失效、泵组切换、传感器失效、CDU 控制器失联和一次侧供水异常完成演练。
- 漏液检测与自动隔离阀动作通过，阀位反馈可追溯。
- 冷却系统与 GPU 作业 drain/checkpoint 流程联调通过。
- 冗余设备维护期间仍满足规定热负载，或有经批准的降载/停机方案。
- 所有阈值、保护动作和复位条件由 OEM 与设施 Owner 签署。
