# G2-04.3｜双站点 Saga 故障恢复与补偿协议

**状态：** 候选架构协议，待站点/资源/安全 Owner 评审。  
**原则：** 不以分布式锁伪装全局原子事务；不推断超时命令失败；以权威对账、幂等命令、单调 FencingToken、Saga 补偿和可审计证据保证最终收敛。

## 1. 故障处理总原则

1. **At-least-once delivery + idempotent command**：跨域消息可能重复；每个命令使用稳定 Idempotency-Key 和 request digest。
2. **Unknown first, reconcile first**：网络超时后业务状态为 Unknown；必须向源 Owner 查询 operation、reservation、lease、taskrun 或 receipt。
3. **Local authority wins**：站点本地 Reservation/Lease/Task Owner 的签名事实优先于 SCO 缓存投影。
4. **Fencing over cancellation**：旧 FencingToken 失效由 Lease Authority 保证；不能只依赖停止消息。
5. **Compensation is not rollback**：跨站点副作用无法完全撤销；补偿记录必须追加，不删除历史事实。
6. **Fail closed for safety gates**：高风险动作遇到身份、撤销、策略、数据授权或 Attestation 状态不明时拒绝/暂停。
7. **Human governance remains outer loop**：超过风险阈值、补偿失败、预算越界、数据泄露疑虑、跨域争议必须升级人工审批。

## 2. Saga 步骤与补偿

| 步骤 | 正向动作 | 权威 Owner | 超时/失败时处理 | 补偿动作 |
|---|---|---|---|---|
| S0 Contract | 校验/签署合同版本 | 合同双方 | 查询签署状态和版本摘要 | 未签署则 Abort；已签署则按合同取消条款 |
| S1 Policy | 获取策略决策 | 目标资源/数据 Owner PDP | 重新查询 Decision 与撤销水位 | 无有效 Permit 不继续 |
| S2 Plan | 选择计划 | Task Owner | 查询 plan digest/version | 标记 Superseded/Rejected |
| S3 Prepare A/B | 本地准备预留 | 各 Site Reservation Authority | GetReservation/Operation 对账 | ReleasePreparedReservation |
| S4 Commit A/B | 本地承诺并签发 Lease | 各 Site Lease Authority | 查询 Lease、CommitReceipt、fencing epoch | Revoke/ReleaseLease；等待签名确认 |
| S5 Barrier | 核对所有站点 Ready | SCO 编排记录；各站点回执权威 | 查询每个站点的最新状态版本 | Barrier 不通过则禁止启动，进入补偿 |
| S6 Activate | 本地 TaskRun 启动 | Site Task Coordinator | 查询 TaskRun/TaskStage/StopReceipt | Stop/Checkpoint；释放资源按合同处理 |
| S7 Execute | 执行工作负载 | Site Task Owner | 对账 attempt、事件水位与租约 | 暂停/重试新 attempt；旧 attempt 留证 |
| S8 Result | 提交结果/产物引用 | Result/Artifact Owner | 查询 result digest/version | Withdraw/Withhold；不删除审计记录 |
| S9 Acceptance | 独立验收 | Independent Acceptance Owner | 查询 AcceptanceRecord | Dispute / Re-assessment；执行方不能自批 |
| S10 Settlement | 计量/结算 | Metering / Settlement Owner | 对账签名计量与版本 | Freeze/Dispute；按争议流程裁决 |

## 3. 关键故障场景

| 场景 | 观测 | 禁止行为 | 恢复策略 | 人工升级条件 |
|---|---|---|---|---|
| A Prepare 成功、B Prepare 超时 | B=Unknown | 不得认为 B 失败后直接换 key 重发 | 查询 B Reservation；如不存在则按原 key 重试；TTL 到期后释放 A | 超过合同等待窗 |
| A Commit 成功、B Commit 失败 | PartialCommit | 不得启动 A 或把全局标为 Committed | 进入 Compensating；A Lease Authority 撤销/释放；B 保留失败证据 | A Lease 无法确认释放 |
| Commit 响应丢失 | Commit Unknown | 不得再次盲目 Commit | GetLease / GetReservation / GetOperation；同 key 查询 | 状态超过最大对账窗 |
| Barrier 期间 Policy 被撤销 | Decision Revoked | 不得使用旧缓存激活 | 重新评估；撤销水位确认；Barrier epoch 递增 | 需例外继续时必须人工审批且不能覆盖Owner拒绝 |
| Site A 网络分区 | A Stale | 不得由 SCO 假设 A 已停机或已释放资源 | 标记 Unknown；保持 Fencing；待恢复后对账 | 失联超过合同 SLA 或影响数据安全 |
| Lease 过期但任务仍报告 Running | Lease Expired / Run Running | 不得信任旧 TaskStage 或续用旧 token | 本地 Fence 旧 token；停机/隔离；创建新 attempt 前重新授权 | 发生实际资源争用或数据写冲突 |
| 重复 CancelRun | Duplicate command | 不得重复释放或删除证据 | 幂等返回原 Stop/Release receipt | 补偿步骤结果冲突 |
| 结果已提交、验收被拒 | Acceptance Rejected | 不得将 Result 状态改为 Accepted | 保留结果版本；按合同补交或争议 | 争议超出合同授权范围 |
| 结算草案金额不一致 | Settlement Mismatch | 不得直接改写签名 MeteringRecord | 冻结草案、逐项对账、DisputeCase | 超阈值或跨Owner争议 |
| 撤销事件有序列缺口 | Revocation Gap | 不得把未知撤销状态视为未撤销 | 拉取全量 checkpoint / delta；隔离高风险动作 | gap 无法在最大陈旧窗内修复 |

## 4. Retry / Backoff / Deadline

- 可重试：网络暂时不可达、429、503、504，但必须保持原 Idempotency-Key 和 request digest。
- 不自动重试：400、401、403、404、409（状态冲突）、412、422、428；修正请求/权限/版本后再提交。
- 对 500/502/504，先查询原 operation 与业务对象；若有副作用可能已发生，状态保持 Unknown。
- 退避策略由服务 SLA 定义；客户端必须遵守 Retry-After，增加 jitter，避免多站点同步重试风暴。
- 每条 Saga 定义 deadline、步骤 TTL、最大重试次数和人工接管阈值；不得无期限占用预留资源。

## 5. Fencing 与租约恢复

1. 每个资源 Owner 维护单调递增 fencing_epoch；每次新 Lease/重建 Lease 都产生更高 epoch。
2. 资源执行面在写入/提交前核验当前 token；低于最新 epoch 的旧请求拒绝。
3. ReleaseReceipt 需要确认 token 已失效且资源已回收；仅收到 HTTP 202 不代表释放完成。
4. Lease Renewal 由本地 Lease Authority 决定；SCO 只能 Request/Forward/Track。
5. Lease 失联或超时不能通过复用旧 token 恢复；必须 Reconcile 后重新申请。

## 6. 证据与审计

每个步骤必须保留：transaction_id、saga_id、step_id、attempt_id、request_id、correlation_id、idempotency_key_digest、contract_digest、authority_ref、object_version、event_cursor、issued_at、expires_at、signature_ref、result_code、compensation_ref。日志不得保留令牌、私钥或原始敏感数据。

## 7. 放行标准

- 每个步骤都有 Owner、超时、重试、补偿、回执和最大陈旧窗口。
- Partial Commit 不启动工作负载；Compensation 未确认时不把交易标记为 Aborted/Released。
- Unknown 能通过权威对账收敛；旧 FencingToken 无法写入。
- 撤销缺口使高风险动作 fail-closed。
- 站点失联、重复命令、响应丢失、回滚和部分成功有故障注入证据。
- 关键补偿失败可升级人工接管并保留责任链。
