# G2-06.6｜跨区域协议与数据契约规范

**状态：** RC0 候选，待评审  
**范围：** 全球/区域/站点之间的控制面协议与最小必要元数据契约  
**不包含：** 工程实现代码、生产密钥、真实租户数据、未授权数据搬迁

## 1. 设计目标与边界

G2-06.6 将区域协调层（RCP）从逻辑组件描述推进为可互操作的协议边界。协议必须允许两个或多个区域协同发现能力、委派子任务、发起站点级资源准备、汇总权威回执、同步事件和执行恢复，同时不把区域协调器变成跨域资源所有者。

### 1.1 四层权威模型

| 层级 | 主要责任 | 可产生的权威事实 | 明确禁止 |
|---|---|---|---|
| 全球联邦层（ADS/GCP） | 共同语义、信任互认、治理模板、跨区域意图与目录摘要 | 全局策略发布记录、信任元数据、治理审计索引 | 直接签发站点 Lease、直接启动站点作业 |
| 区域协调层（RCP） | 区域目录投影、候选发现、区域路由、网络/数据位置分析、Saga 协调 | 区域协调 Operation、聚合视图、区域回执 | 覆盖站点事实、代替 Owner Commit |
| 站点自治层（LCP） | 本地资源目录、Prepare/Commit、Lease、PDP/PEP、执行、计量与恢复 | Reservation、Lease、TaskRun、PolicyDecision、Metering 原始记录 | 接受过期或未授权的全局指令 |
| 专业资源 Owner | 计算、网络、存储、数据、能源设施的专业权威 | 资源状态、报价、授权、设施联锁、数据许可 | 将其他 Owner 的事实视为本方可改写对象 |

RCP 的区域 Operation 只证明协调动作或聚合状态，不等同于站点资源已承诺。区域聚合回执必须列出来源 Owner、站点回执引用、版本、有效期和签名证据引用。

### 1.2 关键对象与权威归属

| 对象 | 权威 Owner | 区域/全局层可做什么 |
|---|---|---|
| RegionCapabilitySummary | 各站点/Owner 提供源事实；RCP 对区域投影负责 | 聚合、筛选、签名区域快照 |
| FederatedSubtaskProposal | Task Owner / SCO | 提案、路由、版本化，不构成承诺 |
| RegionOperation | RCP | 记录区域协调命令及处理状态 |
| PrepareReceipt | 目标站点 Reservation Authority | 转发与汇总，不伪造 |
| ResourceLease / FencingToken | 目标站点 Lease Authority | 保存引用、发起查询或释放请求 |
| PolicyDecision | 目标 Owner PDP | 传递决策引用，不代签 Permit |
| DataUseGrant | Data Owner | 传递授权引用，不扩张用途 |
| RegionStateEvent | 产生该事实的 Owner | 聚合、订阅、索引和对账 |
| AcceptanceRecord | 合同指定的独立验收 Owner | 路由和汇总，不由执行者自验收 |
| SettlementRecord | Settlement Owner；计量事实由 Metering Owner | 汇总与争议协调，不改写原始计量 |

## 2. 协议分层

建议按职责分离协议，不让单一协议承担所有含义：

| 层 | 建议承载 | 主要用途 | 约束 |
|---|---|---|---|
| 语义层 | Ontology V3.x / Profile | 统一对象、关系、状态和术语 | 版本与兼容 Profile 必须显式 |
| 业务契约层 | DM04 / IFC Profile | 任务、授权、资源交易和回执的逻辑请求响应 | 不依赖某个传输协议 |
| HTTP 绑定层 | ADS/SCO REST Binding RC1 及后续版本 | API 路由、Header、状态码、幂等与条件请求 | 沿用 G2-04 的 Idempotency-Key、ETag/If-Match、Request/Correlation ID |
| 事件层 | CloudEvents 1.0 信封 + 领域事件 Schema | 异步状态变化与证据引用 | CloudEvents 只定义事件信封，不替代领域语义 |
| Agent 协商层 | A2A | 能力询问、协商、唤醒和异常升级 | 不作为唯一事实源 |
| 工作流/执行层 | FWSX / 本地工作流契约 | 本地执行步骤与运行状态映射 | 不越过 LCP 与 Owner 的执行权限 |

## 3. 跨区域请求信封

所有会改变状态的命令应携带以下逻辑字段；具体 HTTP Header 与 Body 绑定沿用 G2-04 REST Binding。

| 字段 | 必需 | 语义 |
|---|---|---|
| request_id | 是 | 单次请求标识 |
| correlation_id | 是 | 跨区域端到端关联标识 |
| causation_id | 条件必需 | 触发当前命令的事件/命令 |
| idempotency_key | 有副作用的命令必需 | 防止重放产生重复副作用 |
| payload_digest | 是 | 请求规范化内容摘要 |
| contract_ref / contract_digest | 任务交易必需 | 绑定合同与内容版本 |
| ontology_version | 是 | 语义解释版本 |
| schema_version | 是 | 消息结构版本 |
| source_region / target_region | 跨区域命令必需 | 路由与责任边界 |
| issuer_ref / audience | 是 | 发起主体和目标受众 |
| issued_at / expires_at | 是 | 时效与重放控制 |
| policy_context_refs | 条件必需 | 授权上下文引用 |
| trace_context | 推荐 | 分布式追踪上下文 |
| signature_ref | 受信边界必需 | 签名/验证证据引用 |

请求的有效性必须同时通过身份、受众、签名、有效期、幂等键、契约版本、策略和本地 Owner 校验。仅凭网络可达或 Agent 身份有效不能推导出资源授权。

## 4. 候选 API 操作目录

以下 URI 是逻辑候选，不表示已完成 OpenAPI 冻结。

| 操作 | 方法与路径 | 责任方 | 结果性质 |
|---|---|---|---|
| 读取区域能力摘要 | GET /v1/regions/{region_id}/capability-summary | RCP | 只读投影 |
| 创建跨区域子任务提案 | POST /v1/federated-subtasks/proposals | SCO | 提案，不承诺资源 |
| 校验子任务 | POST /v1/federated-subtasks/{proposal_id}/validate | 目标 RCP | 兼容性/硬约束结果 |
| 发起区域 Prepare | POST /v1/federated-subtasks/{proposal_id}/prepare | 目标 RCP | 委派站点 Prepare |
| 查询 Prepare 状态 | GET /v1/federated-subtasks/{proposal_id}/prepare-status | RCP | 聚合投影 |
| 发起区域 Commit | POST /v1/federated-subtasks/{proposal_id}/commit | SCO → RCP | 请求各站点 Owner 决策 |
| 请求激活 | POST /v1/federated-subtasks/{proposal_id}/activate | SCO → RCP | 仅在 Barrier 通过后 |
| 请求取消/补偿 | POST /v1/federated-subtasks/{proposal_id}/cancel | SCO → RCP | 委派 Stop/Release |
| 查询任务状态 | GET /v1/federated-subtasks/{proposal_id}/status | RCP | 带来源版本的投影 |
| 发起状态对账 | POST /v1/federated-subtasks/{proposal_id}/reconcile | SCO/RCP | 查询原权威 Owner |
| 发布策略包 | POST /v1/regions/{region_id}/policy-bundles | ADS → RCP | 签名策略分发 |
| 传播撤销水位 | POST /v1/regions/{region_id}/revocations | ADS → RCP | 治理优先级事件 |
| 确认事件游标 | POST /v1/regions/{region_id}/events/ack | 消费者 | 消费进度，不改变源事实 |

### 4.1 API 语义约束

- GET 只返回视图，不隐式预留资源。
- POST 命令返回 Operation/Receipt 引用；HTTP 2xx 不等于业务对象最终成功。
- 202 Accepted 仅表示命令被接收；调用方必须查询 Operation 或等待权威事件。
- 对已有对象的并发修改使用 ETag/If-Match；缺失前置条件按 G2-04 约定返回 428，版本冲突返回 412。
- 非幂等副作用 POST 必须带 Idempotency-Key；同 key 不同 payload_digest 返回 409。
- Unknown、超时或响应丢失时必须先 Reconcile，不得换 key 盲目重试。
- RCP 的 Commit 响应必须引用 Site Lease Authority 的原始 CommitReceipt；不能由 RCP 自己构造 Lease 事实。

## 5. 区域能力摘要契约

RegionCapabilitySummary 是带时间边界的发现视图，至少包括：

- region_id、region_epoch、snapshot_id、snapshot_version；
- ontology_version、contract_profiles、trust_domain_refs；
- sites[]：site_id、owner_ref、能力标签、资源摘要、health_state；
- 每个来源摘要的 observed_at、valid_until、source_epoch、sequence_no；
- revocation_watermark、signature_ref、issuer_ref；
- completeness 与 freshness 状态。

区域摘要必须保留来源站点和 Owner。跨区域查询结果要标注陈旧、缺失、部分可见和权限过滤情况。不能将聚合容量简单相加后作为可承诺容量；GPU 型号、显存、互连拓扑、驱动/固件、NUMA、存储路径和网络 QoS 等硬约束必须在目标站点重新校验。

## 6. 数据最小化与数据平面

默认跨区域控制面只交换：

1. 站点/Owner 身份与信任元数据；
2. 最小能力与容量摘要；
3. Offer/Quote 与有效期；
4. 任务子图、契约摘要和约束；
5. Policy/Grant/Attestation/Lease 的引用与状态摘要；
6. 事件、回执、遥测聚合值和证据引用。

默认不交换原始训练数据、客户数据、模型权重、KV Cache、完整检查点或业务负载。确需传输时必须由 Data Owner、接收方和 Network Owner 按 DataUseGrant、地域、purpose、保留期、加密、审计和结果披露规则单独批准。可选策略包括数据留域、代码/容器到数据侧执行、授权派生数据传输或结果摘要披露。

控制面不作为数据面代理。任务输入输出、模型制品、检查点和业务流量采用经批准的直连或专用数据路径，并在网络层与存储层分别验证 QoS、隔离和数据驻留。

## 7. 身份、信任与重放防护

- 区域间使用明确的 TrustAgreement 和双向身份校验；信任不自动传递给下游区域或子站点。
- 令牌 audience 必须绑定具体区域/API；不得接受宽泛 audience 作为跨区域授权。
- 传输保护、消息签名和密钥轮换采用经安全 Owner 批准的密码配置 Profile。
- 请求必须校验 issued_at、expires_at、nonce/operation 标识、签名和幂等键。
- 新区域加入、信任域变更、Owner 替换和密钥轮换均需有版本、审批、撤销和回滚证据。
- 高风险操作在目标 Site PDP/PEP 再判定；区域 Permit 或缓存策略不能替代本地决策。
- 撤销序列出现缺口或水位过期时，高风险动作 Fail-Closed。

## 8. 版本与兼容

每条消息都要携带 schema_version、ontology_version、contract_profile 和 producer_version。版本兼容采用显式矩阵：

- 同一主版本内仅允许经评审的向后兼容增量。
- 删除字段、改变状态语义、放宽权限或改变 Owner 归属属于破坏性变更。
- 未知字段、未知枚举和未知 Profile 的处理必须由 Profile 明确规定；安全相关未知值默认拒绝。
- 区域升级允许短暂版本并存，但不得因兼容层转换而丢失签名、digest、Owner、epoch、sequence 或撤销水位。
- Schema 验证通过不代表两个独立实现的序列化、状态机和错误处理一致。

## 9. 错误模型

| HTTP | 错误码示例 | 含义 | 调用方动作 |
|---|---|---|---|
| 400 | ENVELOPE_INVALID | 请求信封无效 | 修正请求，不重试 |
| 401 | IDENTITY_INVALID | 身份或令牌无效 | 重新认证 |
| 403 | POLICY_DENIED | Owner 明确拒绝 | 不得绕过 |
| 409 | IDEMPOTENCY_CONFLICT | 同 key 不同 digest | 人工/调用方排查 |
| 409 | REGION_EPOCH_CONFLICT | 区域协调代次冲突 | 查询当前代次 |
| 412 | RESOURCE_VERSION_CONFLICT | If-Match 版本过期 | 重新读取 Owner 状态 |
| 422 | ONTOLOGY_INCOMPATIBLE | 本体/Profile 不兼容 | 协商兼容 Profile |
| 428 | PRECONDITION_REQUIRED | 缺少条件请求前置条件 | 补齐 ETag/If-Match |
| 429 | RATE_LIMITED | 限流 | 遵守 Retry-After |
| 503 | OWNER_UNREACHABLE | 原权威 Owner 不可达 | 进入 Unknown/Reconcile |
| 503 | REVOCATION_GAP | 撤销水位缺口 | 阻断高风险动作 |
| 504 | OPERATION_OUTCOME_UNKNOWN | 结果未知 | 查询原 Operation，不换 key 盲重试 |

错误响应还应包含 problem_type、error_code、request_id、correlation_id、retryable、reconcile_required、owner_ref（适用时）和 evidence_ref。

## 10. 本阶段待评审事项

1. ADS/SCO/RCP 的 API Owner 与操作授权矩阵。
2. RegionCapabilitySummary 的最小字段和敏感信息分级。
3. 区域间 TrustAgreement、audience 与签名 Profile。
4. Site Owner Prepare/Commit 回执的原始证据引用规则。
5. Region epoch 与 Site owner epoch 的独立递增和 fencing 规则。
6. 撤销水位最大陈旧窗口及不同风险级别的离线行为。
7. 数据留域、派生数据披露和跨区域数据路径审批。
8. 事件重放、缺口补传、快照对账和消费者游标持久化。
9. 双实现互操作范围、故障注入和独立见证要求。
