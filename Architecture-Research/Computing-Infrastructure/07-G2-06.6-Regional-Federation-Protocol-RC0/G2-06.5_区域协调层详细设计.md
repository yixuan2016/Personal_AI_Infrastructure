# G2-06.5｜区域协调层详细设计

**状态：** RC0 架构候选，待评审  
**定位：** 十星双区域自治联邦的区域协调能力设计  
**性质：** 纯架构研究，不包含工程实现代码，不代表生产部署或验收通过

## 1. 核心决策

RCP（Regional Coordination Plane，区域协调平面）不是新的超级调度器，而是一组区域级协同能力。逻辑上分层，物理上按规模部署：三星彩排可共址，十星采用区域高可用部署，百星演进为多个自治区域联邦。

RCP 可失联、替换和重建，不构成单星继续运行的必要条件。它不拥有站点设备、不签发站点 ResourceLease/FencingToken、不替代本地 PDP/PEP，也不决定数据用途。

## 2. 四层联邦结构

| 层级 | 主要职责 | 权威边界 |
|---|---|---|
| 全球 ADS/GCP | 共同语义、信任互认、全局策略与跨区域意图 | 不直接控制站点设备 |
| 区域 RCP | 区域目录、任务协调、网络与数据位置分析、区域故障管理 | 不覆盖站点 Owner 事实 |
| 站点 ADS/SCO/LCP | 本地自治、资源预留、Lease、执行、计量和恢复 | 站点本地事实权威 |
| 专业资源 Owner | 计算、网络、存储、数据、能源和设施 | 各自保留最终事实和承诺权 |

## 3. RCP 七项能力

1. **区域目录：** 汇总站点能力、健康和容量摘要，保留来源 Owner、版本、观测时间与 TTL。
2. **区域任务协调：** 发现候选站点、分解区域子任务、协调跨星阶段，但不直接执行作业。
3. **区域资源智能：** 组合 CPU/GPU/存储/网络/能源候选，按硬约束过滤后再做多目标排序。
4. **网络与数据位置分析：** 分析 RTT、带宽、QoS、数据驻留和传输成本；不代替 Network/Data Owner。
5. **策略缓存与撤销分发：** 缓存签名策略并传播撤销水位，不扩大授权。
6. **事件与证据协调：** 聚合事件投影、检测缺口、请求 Owner 快照和对账。
7. **区域运营治理：** 区域配额、SLO、公平性、争议和运营指标；不改写原始计量证据。

## 4. 区域划分与目录分片

区域不能只按地理位置划分。至少综合考虑网络 RTT/带宽、数据主权、监管边界、资源运营主体、网络运营商故障域、任务关联度和能源设施边界。

建议目录主分区维度为：

**Region → TrustDomain → Site → Owner**

资源类型、GPU 型号、显存、互连、CPU ISA、存储和网络能力作为二级检索索引。一个地理区域可以包含多个 TrustDomain；一个 TrustDomain 也可能跨越多个网络区域。

目录属于最终一致的发现视图，不是资源权威数据库。每个快照必须包含 source_epoch、sequence_no、observed_at、valid_until、revocation_watermark 和 signature_ref。过期快照不能用于硬承诺；正式 Prepare 前必须回到目标站点 Owner 再确认。

## 5. 区域任务协调流程

意图与任务契约标准化 → 硬约束过滤 → 区域候选发现 → 网络/数据位置分析 → 报价和容量复核 → 站点 Prepare → 站点 Commit → Activation Barrier → 本地执行 → 结果验收 → 计量对账。

区域协调器可以提出候选和组织 Saga，但每个站点必须独立校验并决定是否承诺。部分 Commit 不得启动全局任务；Unknown 必须先查询原 Owner。

## 6. 策略传播与自治

采用“全局发布、区域验证、站点适配、本地执行、证据回传”。普通策略更新按版本分发；高风险撤销走独立优先通道。区域缓存不得扩大授权。撤销水位未知、缺口或超过风险 Profile 的最大陈旧窗口时，高风险动作 Fail-Closed。

网络失联期间，本地任务仅可在本地有效租约、本地策略、数据授权和设施联锁允许的范围内继续。不得无限续租或扩大离线权限。

## 7. 区域故障状态

| 状态 | 行为 |
|---|---|
| NORMAL | 正常区域协同 |
| DEGRADED | 降级运行，限制新增跨域交易 |
| PARTITIONED | 暂停依赖远端未知状态的新跨区域 Commit |
| RECOVERING | 对账、快照同步、撤销状态核验 |

RCP 领导者切换使用独立 region_epoch 与 coordinator_fence。它们不能替代 Site owner_epoch 或 ResourceLease FencingToken。区域恢复后先对账 Owner 状态，再恢复新的跨区域交易。

## 8. 控制面容量与优先级

控制面容量需测量请求到达率、扇出、Owner 响应时延、事件积压、目录刷新频率、Saga 等待、重试放大和撤销洪峰。建议采用分级队列：

- P0：紧急撤销、停止执行、安全联锁、权限阻断。
- P1：Prepare、Commit、Lease、Stop、Release、Reconcile。
- P2：任务路由、目录变更、资源健康更新。
- P3：非关键遥测、统计和预测。

过载时先降频 P3，不得让遥测洪峰阻塞 P0/P1。固定吞吐量和时延目标必须通过目标环境压测确定。

## 9. 十星验收项目

覆盖目录分片和新鲜度、区域路由、Owner Prepare/Commit、双区域网络分区、RCP 主节点切换、撤销传播、事件缺口修复、区域公平性、容量碎片、成员退出、SLO 统计和争议处理。验收必须保留 Owner 原始回执、事件游标、故障注入记录和独立见证证据。

## 10. 放行声明

本设计为 RC0 候选。三星彩排、十星区域互操作、百星容量与故障域验证必须分阶段进行；仿真不能替代真实站点、网络、存储、供电和制冷环境的互操作验证。
